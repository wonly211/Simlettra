# 澄笺 | Simlettra

澄笺是面向个人、家庭和小团队的自有域名邮箱网页应用，专为单个 Cloudflare Worker 部署设计。

## 当前阶段

项目已经完成需求基线、目标架构和六批数据模型设计，并进入纵向切片开发。当前已经完成正式工程骨架、首次初始化、密码登录与会话、密码管理与恢复、用户创建与状态管理、账号邀请码注册、唯一管理员转让、用户注销与期满清理、邮件域名管理、个人地址与别名管理、全局地址策略与别名保留期、组织身份与成员协作、邮件接收与完整性提交、收件箱与安全读信、邮箱整理与垃圾箱、邮件永久删除、邮箱组合搜索、邮件会话归并、草稿与写信编辑、正式发信、回复与转发、外部通知网关、自动转发、免费资源用量与保守停止、逻辑存储配额、用户与组织邮件导出、管理员本地备份与完整恢复、旧系统数据迁移、收信控制与全域认领、网页新邮件自动更新，以及管理员运行健康状态切片：

- 邮箱地址使用 ASCII 前缀、统一小写和 IDNA/Punycode 域名规范化。

- 正式 D1 迁移 `0025` 已幂等补齐早期数据库缺少的内部投递容量拒绝事实、索引和不可修改触发器。
- 用户可以使用主邮箱地址和密码登录，刷新页面后恢复会话，并查看或退出自己的有效会话。
- 会话使用受保护 Cookie、不透明随机令牌、D1 摘要、CSRF 校验、七天空闲与三十天绝对有效期。
- 登录失败按账号和来源分别限速，不存在账号使用虚拟密码记录执行同成本密码验证。
- 用户可以验证当前密码后修改密码，并选择是否退出其他设备。
- 管理员可以为普通用户生成一次性展示、24 小时有效的临时密码；临时密码登录后必须先设置正式密码。
- 管理员忘记密码时可以使用部署配置中的 `init_key` 恢复，恢复后原有管理员会话全部退出。
- 密码变更、会话撤销和成功审计使用同一个 D1 原子批次。
- 管理员可以查看用户，原子创建带主邮箱和临时密码的普通用户，并禁用或重新启用普通用户。
- 管理员可以为指定域名生成、反复查看、复制和撤销一次性账号邀请码；受邀人填写可用邮箱前缀和账号资料完成注册，成功后邀请码立即失效。
- 禁用会立即撤销目标用户全部会话；唯一系统管理员不能通过用户管理接口禁用。
- 管理员可以直接添加邮件域名并暂停或恢复使用；Simlettra 信任管理员，不重复执行 DNS 所有权验证。
- 只有没有关联地址的域名可以永久删除，网页要求明确二次确认，服务端始终重新检查关联关系。
- 初始化管理员和新建普通用户默认拥有 20 个个人别名额度，并默认允许在额度内自行创建。
- 用户可以查看个人主地址和别名，创建别名，修改显示名称与置顶，调整顺序，设置默认发件地址，并二次确认删除自己的别名。
- 管理员可以分别设置每名用户的别名额度和自助创建权限，为用户分配或删除别名；调低额度不会删除已有地址。
- 管理员可以设置邮箱前缀最短长度、禁止文字、保留名称和 0 至 30 天个人别名保留期；收紧规则不影响已有地址。
- 删除个人别名会立即停止使用；地址按删除时的策略立即释放或继续保留，到期后由 D1 权威任务、Queue 和每小时定时补投释放。
- 初始化管理员和新建普通用户默认最多可以创建 5 个组织，管理员可以逐用户调整额度且不会因调低额度改变已有组织。
- 用户可以创建带唯一共享地址的组织，设置邀请偏好，邀请现有用户，处理邀请，查看成员，并按权限退出、继承、删除或恢复组织。
- 组织创建者是唯一组织管理员，始终可以使用组织地址发信；普通成员默认不能，创建者可以开启或关闭该权限。
- Worker 收到邮件后先把原始 MIME 写入当前 R2 或 KV，再由 Queue 使用 `postal-mime` 解析正文与附件；对象全部校验完成前不会显示半封邮件。
- 收信会冻结接收时的实际地址归属，并以一小时有界指纹阻止重复投递；最终 D1 原子批次同时建立个人或组织邮箱条目和完整性事实。
- 登录后默认进入统一收件箱，可以筛选个人和当前组织来信，稳定分页并查看邮件头、实际投递地址、纯文本、HTML 和附件。
- 个人邮件只允许本人读取；组织邮件在每次请求时重新检查当前成员关系。每位组织成员拥有独立已读状态，管理员身份不会自动获得其他用户个人邮件正文。
- HTML 邮件经 `DOMPurify` 净化并在无脚本权限的隔离区域中显示；远程图片默认不加载，可仅对当前邮件放行或信任完整发件地址。
- 附件下载和常见图片预览会重新检查邮件访问权，并使用安全文件名与响应头。
- 邮箱提供收件箱、已发送、星标、归档、垃圾邮件、垃圾箱和全部邮件视图；单封与最多 50 封批量整理使用同一权限边界。
- 组织邮件的已读、星标、归档和垃圾箱状态彼此独立；垃圾箱默认保留 30 天，到期后个人邮件自动进入永久删除，组织成员状态只对该成员永久隐藏。
- 用户可以二次确认永久删除自己的个人邮箱副本；普通组织成员不能永久删除组织原始邮件，只有组织创建者可以让所有成员失去该邮件访问。
- 永久删除先撤销邮箱访问。同一物理邮件仍被其他邮箱引用时保留共享内容；最后一份引用消失后，由 D1 权威任务逐个清理 KV/R2 对象、数据库关系并完成对账，失败可以安全重试。
- 用户可以组合使用正文、主题、发件人、收件人、实际投递地址、日期、附件和个人状态搜索，并按时间、未读、星标或附件优先排序。
- 中文正文使用相邻双字词元；FTS5 只产生候选邮件，返回前仍重新检查个人归属和当前组织成员资格。索引建立或需要处理时，网页会明确说明而不返回伪完整的正文结果。
- 标准 `Message-ID`、`In-Reply-To` 和 `References` 会把回复归入个人或组织邮箱范围内的会话；仅主题相同不会合并，重复外部标识也不会误关联。
- 邮箱列表按当前视图和搜索条件折叠会话并显示邮件数，详情按时间列出当前有权访问的全部物理邮件；自发自收产生的收件箱和已发送条目在详情中不会重复，每封邮件仍独立维护已读、星标、整理、附件和删除边界。
- 用户可以从本人个人地址和获授权的组织地址中选择发件地址，编辑服务端富文本或纯文本草稿，管理收件人和附件，并在电脑与手机浏览器间继续编辑。
- 草稿自动保存使用修订号、防重键和输入摘要；多设备过期编辑会另存为冲突副本，不会静默覆盖较新的内容。附件完整写入并通过大小及 SHA-256 校验后才进入草稿修订。
- 用户可以正式发送当前草稿；服务端先校验精确修订、发件权限、最终 MIME、20 MB 上限和每日及月度额度，再原子建立一封不可变邮件与已发送条目。
- 系统内地址直接投递，不经过外部服务；站外地址只通过 Resend 或 SMTP2GO 异步投递，并按逐收件人展示已提交、已送达、延迟、退信、失败或结果未知。
- 每个域名可以配置默认与备用 Provider。只有服务明确拒绝接受时才自动切换，超时、网络错误和无法判断的结果不会盲目重发。
- 唯一系统管理员可以管理 Provider 明文凭据、域名路线、默认每日 500 名最终收件人的用户额度和默认不限的域名自然月额度；凭据使用独立配置主密钥加密进入 D1。
- 用户可以从有权读取的来信建立回复、回复全部或转发草稿；回复优先使用 `Reply-To`，回复全部自动去除个人地址但会按组织权限保留共享地址。
- 回复和回复全部生成标准 `In-Reply-To`、完整 `References` 与权威会话关系；转发复制普通附件但不加入原会话。不可信 HTML 只提取可见文字并转义为安全引用。
- 用户可以为个人邮箱或当前组织邮箱建立 ntfy、Gotify、WxPusher、Telegram 或 Bark 通知订阅，暂停、恢复或删除订阅，并查看最近通知结果。
- 通知包含发件人、收件人、抄送、实际投递地址、主题和完整安全正文，不发送附件；权限失效、通知失败或结果未知都不会影响原邮件。
- 用户可以通过一次性验证码验证外部邮箱，并把全部个人来信或指定个人地址来信自动转发到已验证目标；组织共享来信不参与自动转发。
- 自动转发冻结规则、实际投递、内容摘要、原始邮件大小和域外路线，使用独立防重操作与环路标记。任务执行前重新检查当前权限；只有 Provider 明确未接受时才切换备用服务，结果未知时停止自动动作。
- 管理员可以查看 D1 与当前 KV 或 R2 的账号总量和当前资源用量、免费上限、剩余额度、来源和更新时间，并设置不超过产品上限的预警与停止比例。
- 收信、草稿附件和已发送副本在增加存储前必须同时通过账号范围与当前资源范围的容量预留；达到停止线后只阻止新增存储，阅读、导出、备份和永久删除仍可继续。
- Cloudflare 官方指标不可用时明确显示 Simlettra 本地估算，并把有效停止比例限制在最高 `80%`；真实 Free 账号接口、权限和指标延迟仍需远程验证。
- 用户与组织逻辑配额独立于 Cloudflare 免费资源上限；管理员可以修改两类默认值和单主体覆盖。调低额度不会删除已有数据，只阻止继续增加容量。
- 管理员可以在线生成 D1 与当前 KV/R2 的可校验原始备份分卷；本地工具默认生成 AES-256-GCM 加密容器，并只向迁移版本一致的空白资源执行分阶段完整恢复。
- 恢复会按正式迁移外键拓扑导入 D1，逐项上传并回读校验对象；清单哈希、表行数、对象哈希、外键、对象引用和搜索重建全部通过后才能标记成功。
- 旧系统迁移工具只读提取旧 D1 与被引用的 KV/R2 对象，生成稳定快照；正式迁移必须引用独立目标产生的匹配演练报告，并可在中断或重复执行时复用来源映射。
- KV 与 R2 本地迁移自检均已通过快照、演练、正式迁移、重放、搜索、会话、七类对账及六类失败场景；真实旧数据副本与 Cloudflare Free 远程迁移仍需演练。
- 唯一系统管理员可以把身份转让给另一名已启用用户；用户申请注销后立即退出普通会话，并可在七天内通过独立受限恢复会话取消注销。
- 用户和组织期满清理由有界后台任务分步处理；组织删除七天内可恢复，升级前缺少正式删除账本的待删除组织会按原截止时间自动补建任务。
- 管理员可以暂停域名、地址或用户收信，建立发件地址、发件域名、主题关键词和正文关键词拒收规则，并为每个域名选择拒收未知地址或保存为未分配来信。
- 获授权用户可以在独立视图搜索、阅读和下载未分配来信；认领会原子建立个人别名并取得当前未分配时期的历史邮件，认领前不产生个人或组织逻辑用量。
- 登录用户的当前邮箱视图会在页面可见且在线时每 60 秒静默刷新；切回页面、网络恢复和登录后立即检查，后台或离线时暂停，连续失败按 2 分钟、5 分钟和 10 分钟逐步退避。
- 自动刷新不会清空当前勾选、提示或正在阅读的邮件，手动刷新始终可用；当前实现重载当前列表，真实 Workers Free 与 D1 读取成本仍需远程验证。
- 唯一系统管理员可以查看收信、发信、存储和定时维护四类健康摘要；普通用户无权读取，健康页不显示邮件正文、附件、地址明文或密钥，也不会主动探测外部服务。
- 收发操作停滞、结果未知、缺少发信路线、资源预警或停止、失败或缺失的 Cron、需人工处理及逾期任务会明确提示“需检查”；尚无事实和未配置状态不会误称正常。
- 系统备份会从 D1 迁移账本读取并冻结实际最新迁移版本，避免新增迁移后备份清单仍标记旧版本。
- 本地升级回退自检会从上一正式迁移重建代表性数据，验证当前迁移前后既有结构、表行数、代表性数据和外键，并从升级前快照建立独立回退目标。
- 正式迁移只向前追加；兼容版本可以只回退 Worker 代码，数据或结构不兼容时使用升级前完整备份恢复到全新空白资源，检查通过后再切换绑定。
- 生产构建会隔离本地 `.dev.vars`，扫描产物中的密钥文件名和已知密钥内容，并清除生成配置中的本机绝对路径。部署前配置自检同时核对 D1、KV/R2、Queue、Cron、网页回退和存储模式；严格部署会拒绝全零资源编号。

## 正式部署

正式发布后的默认安装方式是在 Cloudflare 的“创建 Worker”页面连接[公开部署测试仓库](https://github.com/wonly211/Simlettra)，保持默认构建命令 `pnpm run build` 和默认部署命令 `npx wrangler deploy`。构建变量只需选择 `r2` 或 `kv` 存储模式；构建阶段按 Cloudflare 实际 Worker 项目名称自动创建或复用 `meta` D1、`raw` KV/R2 与 `tasks` Queue，取得真实配置后保护 D1 迁移边界。`INIT_KEY` 与 `CONFIG_KEY` 在 Worker 的“变量和机密”页面保存为唯一管理员可查看的文本变量，不进入 GitHub 或构建变量。

完整步骤见[首次部署与初始化指南](文档/部署/首次部署与初始化指南.md)。本地 Wrangler 部署命令保留给开发、迁移、恢复、真实验收和高级排错。

## 本地环境要求

- Node.js `22.13.0` 或更高版本。
- pnpm `11` 或更高版本。
- 本地高级部署前准备自己的 Cloudflare 账号和邮件域名。R2 模式使用 `wrangler.jsonc`，KV 模式使用 `wrangler.kv.jsonc`；两份模板的全零资源编号不能直接部署。普通正式部署改用上文的 Cloudflare 连接 GitHub 流程。

## 本地启动

```powershell
pnpm install
Copy-Item .dev.vars.example .dev.vars
pnpm dev
```

启动前应把 `.dev.vars` 中的 `INIT_KEY` 替换为至少 16 个字符的随机初始化密钥，并为 `CONFIG_KEY` 生成独立的 32 字节随机 Base64 值。真实 `.dev.vars` 已被 Git 忽略，不得提交。

默认本地地址为 `http://localhost:5173/`。`pnpm dev` 会先应用本地 D1 迁移，再启动 Vue 网页和 Worker 开发环境。

## 统一命令

```powershell
pnpm dev
pnpm db:migrate:local
pnpm db:migrate:remote
pnpm db:migrate:remote:kv
pnpm test:upgrade-rollback
pnpm test:security
pnpm test:accessibility
pnpm test:deployment-config
pnpm test:performance
pnpm check
pnpm build
pnpm package:source
pnpm deploy:github
pnpm deploy
pnpm deploy:kv
```

- `pnpm db:migrate:local`：把尚未应用的正式迁移写入本地 D1。
- `pnpm db:migrate:remote`：通过 D1 文件导入通道逐个把尚未应用的正式迁移写入远程 D1，并沿用 `d1_migrations` 唯一账本；执行前必须完成备份和影响确认。
- `pnpm db:migrate:remote:kv`：使用 `wrangler.kv.jsonc` 和同一远程迁移工具，把正式迁移写入 KV 模式的独立远程 D1。
- `pnpm test:upgrade-rollback`：从上一正式迁移演练当前升级、数据检查和独立回退目标。
- `pnpm test:security`：运行越权、脚本内容边界、恶意附件名、令牌泄露、重复投递与重复发送相关回归，并执行生产密钥扫描。
- `pnpm test:accessibility`：解析 Vue 模板，检查原生交互控件、可访问名称、表单标签、按钮类型和键盘顺序风险。
- `pnpm test:deployment-config`：分别安全构建 R2 与 KV 模板产物，检查绑定、存储模式、Queue、Cron、网页回退和本机路径泄露；该命令允许源配置保留模板占位编号。
- `pnpm test:performance`：以 50 名用户、100,000 封邮件和 10 个读取线程测量当前列表与详情数据查询。
- `pnpm check`：依次检查格式、代码规则、类型、自动化测试、本地备份恢复自检、旧系统迁移自检、升级回退自检、两种早期逻辑配额迁移自检、性能基准、网页控件可访问性、双模式部署配置和安全生产构建。
- `pnpm build`：生成单 Worker 生产构建，并拒绝包含本地密钥文件或已知密钥内容的产物，同时清除生成配置中的本机绝对路径。
- `pnpm package:source`：生成开发版源码 ZIP、外部源码清单和 ZIP SHA-256；产物写入已忽略的 `发布制品/`，不代表已经通过正式发布门槛。
- `pnpm deploy:github`：本地或自定义流水线的一体化 GitHub 部署入口；Cloudflare Git 连接使用默认 `pnpm run build` 和 `npx wrangler deploy`，两条路径均按 Worker 名称准备 `meta`、`raw`、`tasks` 资源，并共用空白 D1 自动迁移和已有 D1 版本保护。
- `pnpm deploy`：完整检查通过后按默认 R2 模式安全构建、严格检查真实资源编号并部署最终产物；`pnpm deploy:r2` 含义相同。
- `pnpm deploy:kv`：完整检查通过后按 KV 模式安全构建、严格检查真实资源编号并部署最终产物。

第一次部署请按照[首次部署与初始化指南](文档/部署/首次部署与初始化指南.md)连接 GitHub；遇到问题使用[基本排错指南](文档/运维/基本排错指南.md)。真实验收和高级命令行操作继续使用[真实 Cloudflare Free 远程验收运行手册](文档/运维/真实Cloudflare-Free远程验收运行手册.md)。当前仍是开发版，不应直接接管生产邮箱。
