# 澄笺正式数据库迁移

本目录是 Wrangler 生产迁移账本的唯一来源。正式迁移按编号排列，只增不改；普通请求不得自动建表、隐式升级或使用第二套迁移账本。

## 当前迁移

### `0001-系统身份与地址基础.sql`

该迁移服务于首次初始化纵向切片，共建立十张基础业务表：

1. `users`：用户账号与生命周期状态。
2. `password_credentials`：版本化慢速密码哈希记录。
3. `mail_domains`：管理员添加的邮件域名，不保存重复的所有权验证状态。
4. `organizations`：组织及唯一创建者基础关系。
5. `email_addresses`：不可修改的邮箱地址身份。
6. `address_claims`：全系统地址占用与保留状态。
7. `address_bindings`：地址与用户或组织的当前及历史归属。
8. `user_address_preferences`：默认发件地址、显示名称、签名和排序偏好。
9. `system_instances`：唯一系统实例与唯一管理员引用。
10. `initialization_rate_limits`：初始化密钥失败次数与阻止时间。

本迁移有意不包含会话、组织成员、邀请和邮件业务表；会话已由 `0002` 加入，组织成员与邀请已由 `0006` 加入，邮件接收核心已由 `0007` 加入，其余邮件业务结构继续随对应纵向切片审查后进入正式迁移。

### `0002-登录会话与限速.sql`

该迁移服务于密码登录与可撤销会话纵向切片，共建立两张表：

1. `sessions`：保存用户会话、令牌摘要、CSRF 摘要、客户端说明、有效期、最近活动和撤销信息，不保存可直接使用的明文令牌。
2. `login_rate_limits`：按规范化账号和请求来源保存失败窗口、连续失败次数与阻止时间。

本迁移有意不加入密码修改历史、管理员重置或 `init_key` 恢复字段；这些结构必须由后续密码管理切片根据真实流程审查。

### `0003-密码操作与安全审计.sql`

该迁移服务于密码管理与恢复纵向切片，共建立一张表：

1. `audit_events`：保存登录、改密、管理员重置、管理员恢复及后续高风险操作的结构化审计事件，不保存密码、密钥、令牌、邮件正文或可逆敏感内容。

该表只允许追加和删除，触发器拒绝普通更新；本切片只迁入审计事件本体、时间及目标索引，审计查看、保留策略和后台清理结构继续留在后续对应切片审查。

### `0004-个人别名策略.sql`

该迁移服务于个人地址与别名管理纵向切片，共建立一张表和一个准入触发器：

1. `user_alias_policies`：为每名用户保存个人别名数量上限和是否允许自行创建，新用户默认额度为 20 且默认允许自助创建。
2. `validate_current_personal_alias_binding`：在数据库边界检查活动用户、策略、当前额度、启用域名和有效地址占用，防止并发请求或绕过应用产生超额别名。

迁移会为已有用户回填默认策略；地址身份、当前占用、历史归属和个人偏好继续复用 `email_addresses`、`address_claims`、`address_bindings` 与 `user_address_preferences`。

### `0005-地址策略与后台释放任务.sql`

该迁移服务于全局地址策略与个人别名保留期纵向切片，共建立七张表和相应约束触发器：

1. `address_policy_settings`：保存全系统邮箱前缀最短长度、个人别名保留天数和策略版本，默认分别为 1、0 和 1。
2. `address_policy_terms`：逐项保存禁止包含的文字和完整保留名称。
3. `deletion_operations`、`deletion_operation_blockers`、`deletion_operation_steps`：保存删除操作、阻塞项和可核对步骤；当前正式用于个人别名释放、个人邮件副本删除和组织原始邮件删除。
4. `background_tasks`、`background_task_attempts`：保存 D1 权威任务、租约、递增领取令牌和每次执行结果。

数据库触发器会拒绝不符合当前地址规则的新地址、非法任务状态流转、任务身份变化以及未完成必要步骤的删除完成状态。策略只约束新地址，不会追溯修改已有地址。

### `0006-组织身份与成员邀请.sql`

该迁移服务于组织身份与成员协作纵向切片，共建立三张表和相应约束触发器：

1. `user_organization_policies`：为每名用户保存组织创建上限，已有用户和新用户默认上限均为 5。
2. `organization_memberships`：保存当前与历史成员关系、加入顺序、退出和创建者继承事实。
3. `organization_invitations`：保存系统内邀请、三类邀请偏好产生的结果和完整状态历史。

数据库触发器会保护组织创建额度、活动用户与组织状态、创建者继承、邀请目标、重复成员关系和共享地址归属。组织创建通过应用服务原子建立组织、创建者成员关系、唯一共享地址、地址占用与归属及审计事件。

### `0007-邮件接收与完整性提交.sql`

该迁移服务于邮件接收与完整性提交纵向切片，共建立十张表：

1. `messages`、`message_header_addresses`：保存物理邮件和解析后的邮件头地址快照。
2. `message_deliveries`、`mailbox_entries`、`mailbox_entry_deliveries`：保存实际投递和个人或组织邮箱中的可见条目。
3. `object_registry`、`message_integrity_states`：登记原始 MIME、正文、附件和内嵌资源，并以对象校验结果控制邮件是否完整可见。
4. `receive_operations`、`receive_operation_routes`、`message_deduplication_keys`：保存可恢复收信操作、接收时冻结的地址归属和最终防重关系。

数据库触发器会保护对象身份和生命周期、必要对象完整性、邮箱可见门槛、冻结路由与最终投递的一致性。原始 MIME 先进入当前 KV 或 R2，Queue 解析和校验全部对象后，最终 D1 原子批次才建立可见邮件。

### `0008-邮箱个人状态与可信发件人.sql`

该迁移服务于收件箱与安全读信纵向切片，共建立两张表：

1. `mailbox_user_states`：稀疏保存每名用户对个人或组织邮箱条目的已读、星标、归档、位置、垃圾箱期限和单封远程图片覆盖状态；收件箱、安全读信、邮箱整理及永久删除切片已经正式使用这些字段。
2. `trusted_sender_addresses`：按用户和完整规范发件地址保存远程图片信任，不把信任扩大到整个域名。

数据库触发器会在插入和更新时重新检查个人邮箱所有权，或当前启用用户、活动组织和未退出成员关系，阻止绕过应用写入越权状态。

### `0009-邮箱搜索索引.sql`

该迁移服务于邮箱组合搜索纵向切片，建立两张普通表和一张 FTS5 虚拟表：

1. `message_search_states`：逐封记录当前对象集版本、索引代次、状态、分块数和失败代码。
2. `message_search_chunks`：为正文分块提供稳定整数编号，并关联物理邮件与索引代次。
3. `message_search_index`：使用 `content=''` 与 `contentless_delete=1` 的内容空 FTS5 索引，只保存正文词元和哈希邮箱范围词元。

触发器保护索引身份、分块与 FTS5 行的删除顺序、完整分块后才能标记就绪，以及新收信可见前必须已登记索引状态和后台任务。迁移只把既有完整邮件标记为待建索引，后续由定时扫描补建任务，不在迁移中读取 KV/R2 正文。

### `0010-邮件关系与会话.sql`

该迁移服务于邮件会话归并纵向切片，共建立三张表：

1. `message_relations`：保存 `In-Reply-To`、有序 `References` 和以后系统内回复产生的权威关系；父邮件未到达时保留原始引用。
2. `mailbox_conversations`：按个人邮箱或单个组织邮箱范围保存可重建的会话摘要，不作为访问授权依据。
3. `mailbox_conversation_entries`：把邮箱条目关联到同范围会话，并保留原始邮件顺序。

触发器保护关系事实、邮箱范围一致性和空会话清理，并要求新收信可见前已经登记会话重建任务。迁移不在执行期间扫描旧邮件；定时维护会为尚未归并的完整邮件补建任务。

### `0011-草稿与写信编辑.sql`

该迁移服务于草稿与写信编辑纵向切片，共建立五张表并扩展统一对象登记：

1. `drafts`：保存草稿所有者、生命周期、发件地址意图、来源邮件和当前修订号。
2. `draft_contents`、`draft_recipients`：保存当前正文对象代次、输入摘要和收件人快照。
3. `draft_attachments`：保存已通过对象大小与 SHA-256 校验的草稿附件关系。
4. `draft_mutation_keys`：保存自动保存的防重键、输入摘要和稳定结果，避免重试重复推进修订或建立多个冲突副本。
5. `object_registry`：新增草稿所有者、草稿正文和草稿附件角色，继续使用不可变对象键、校验与生命周期状态。

D1 在迁移中始终执行外键约束，因此重建对象登记时会先快照并按原约束重建其直接引用的收信操作、路由和防重关系，再完整回填；迁移测试同时检查正式外键目标、触发器恢复和临时快照清除。

### `0012-正式发信与域外路线.sql`

该迁移服务于正式发信纵向切片，共建立十六张表：

1. `outbound_provider_configurations`、`outbound_provider_configuration_versions`：保存 Resend 或 SMTP2GO 的逻辑配置、加密凭据版本和启停状态。
2. `domain_outbound_routes`、`domain_outbound_route_snapshots`：保存每个域名当前默认与备用 Provider 顺序，并为已经接受的发送冻结不可变路线。
3. `sending_quota_policies`、`user_sending_quota_overrides`、`domain_sending_quota_overrides`、`domain_monthly_sending_usage`：保存每日默认 500 名最终收件人、用户覆盖、默认不限的域名月度额度和自然月用量。
4. `send_operations`、`send_idempotency_keys`、`send_recipients`、`send_recipient_status_history`、`send_operation_progress`：保存一次发送、一封物理邮件、稳定请求防重、逐收件人状态及汇总进度。
5. `outbound_provider_attempts`、`outbound_provider_attempt_recipients`、`outbound_provider_events`：保存 Provider 尝试、覆盖的站外收件人和经过鉴权的不可变回调事件。
6. `domain_monthly_usage_reservations`：保存站外投递接受前的月度额度预留，以及明确接受、拒绝或结果未知后的记账转换。

触发器会保护同一草稿只能被精确修订接受一次、发送操作与物理邮件的一对一关系、逐收件人状态流转、默认与备用路线顺序、Provider 事件幂等和月度预留转换。最终 MIME、正文与附件继续使用统一对象登记，全部对象回读校验后才能原子建立可见邮件。

### `0013-外部通知网关.sql`

该迁移服务于外部通知网关纵向切片，共建立五张表：

1. `notification_subscriptions`：保存用户自己的 ntfy、Gotify、WxPusher、Telegram 或 Bark 订阅及启停状态。
2. `notification_subscription_scopes`：保存全部个人邮箱、指定个人地址或当前组织地址范围，并在数据库边界检查当前访问权。
3. `notification_subscription_secrets`：保存使用独立配置主密钥加密后的通道凭据、随机值、算法和密钥版本。
4. `notification_operations`：为同一实际投递和同一订阅保存唯一权威通知操作、冻结正文摘要及可见结果。
5. `notification_attempts`：按顺序保存每次外部提交尝试、状态码、服务编号和安全错误类别。

触发器会保护订阅范围、操作身份、操作与尝试状态流转。正文、附件和明文凭据不进入通知操作、后台任务或普通日志；任务执行时重新检查当前访问权并从完整邮件对象生成通知内容。

### `0014-外部邮箱验证与自动转发.sql`

该迁移服务于外部邮箱验证与个人来信自动转发纵向切片，共建立七张表：

1. `external_email_targets`：保存用户自己的外部邮箱目标和验证状态。
2. `external_email_verifications`：保存带随机盐的验证码摘要、有效期、错误次数和生命周期，不保存明文验证码。
3. `external_email_verification_attempts`：保存验证邮件通过哪条域外路线提交及安全结果。
4. `mail_forwarding_rules`、`mail_forwarding_rule_addresses`：保存规则版本及全部个人地址或指定个人地址范围。
5. `mail_forward_operations`：按实际投递、规则版本和目标保存唯一转发操作、冻结内容摘要、原始邮件大小、路线与可见结果。
6. `mail_forward_attempts`：保存每次 Resend 或 SMTP2GO 提交尝试、切换原因与供应商结果。

触发器会保护目标归属、验证状态、个人地址范围、冻结路线、操作身份和尝试状态流转。验证码明文不进入 D1 或 Queue；转发任务执行前重新检查用户、个人地址、规则和目标仍然有效。环路拒绝、失败或结果未知都不会影响原始来信。

### `0015-免费资源用量与容量预留.sql`

该迁移服务于管理员免费资源用量与保守停止纵向切片，共建立四张表：

1. `cloudflare_resource_configurations`：保存账号、当前 D1、KV 或 R2 资源标识，以及使用配置加密主密钥保护的只读 API Token。
2. `platform_resource_threshold_versions`：保存 D1、KV、R2 不可改写的预警与停止阈值版本。
3. `platform_resource_usage_snapshots`：同时保存账号总用量、当前资源用量、免费上限、来源、统计状态和更新时间。
4. `platform_capacity_reservations`：在收信、草稿附件和已发送副本增加存储前预留 D1 与对象存储容量，并记录提交、释放和待快照对账状态。

数据库触发器会保护配置单例、阈值范围、快照不可改写、预留身份和生命周期。容量准入必须同时通过账号范围与当前资源范围；只使用本地估算时有效停止比例最高为 `80%`，达到停止线只阻止新增存储，不阻止读取、导出、备份和永久删除。

### `0016-用户与组织逻辑存储配额.sql`

该迁移服务于用户与组织逻辑存储配额纵向切片，建立默认策略、主体用量账户、短期容量预留、不可变用量账本和系统内投递容量不足事实。

1. `D1 + KV` 模式下，用户和组织默认各为 `100,000,000` 字节（十进制 100 MB）。
2. `D1 + R2` 模式下，用户和组织默认各为 `1,000,000,000` 字节（十进制 1 GB）。
3. 系统管理员可以修改两类默认值，并为单个用户或组织设置覆盖值；空覆盖值恢复默认策略。
4. 调低额度不会删除已有数据，只阻止继续增加该主体容量；阅读、导出、备份和永久删除继续可用。
5. 收信、草稿、附件、冲突副本、已发送副本和永久删除统一通过逻辑容量预留与账本计费；同一用户的多个地址不重复计算同一物理邮件，组织邮件不按成员人数重复计算。

该迁移不改变 Cloudflare 免费资源上限。D1、KV/R2 的平台容量仍由 `0015` 的资源快照和平台容量预留管理，两种配额分别显示、分别对账。

### `0017-用户与组织邮件导出.sql`

该迁移服务于第二十三批用户与组织邮件导出纵向切片，建立冻结导出运行、导出项目和 ZIP 分卷制品结构，并扩展平台容量预留的操作类型。

1. `export_runs`：保存请求者、个人或组织范围、冻结数量、状态、过期时间和结果摘要。
2. `export_items`：保存冻结范围内每封邮件的稳定顺序、原始 MIME 或结构化重建来源、写入状态和输出摘要。
3. `export_artifacts`：保存每个 ZIP 分卷的对象键、大小、SHA-256、存储模式和激活及删除状态。
4. 导出项目使用现有 `background_tasks` 任务账本；大导出每次最多生成一个分卷，已完成项目作为下一任务的检查点。

导出记录不引用邮件、邮箱条目或组织外键，因此不会阻塞正常邮件永久删除；用户与组织逻辑配额不计入导出制品，但 KV/R2 平台容量仍会计量并执行容量预留。

### `0018-管理员备份与恢复.sql`

该迁移服务于第二十四批管理员本地备份与完整恢复纵向切片，建立在线备份和离线恢复的权威账本：

1. `backup_runs`、`backup_checkpoints`：保存备份版本、存储模式、运行状态，以及每张 D1 表和对象存储扫描的分页检查点。
2. `backup_manifest_entries`、`backup_required_key_versions`：保存不可修改的清单项摘要和目标恢复必须另行提供的配置加密密钥版本。
3. `restore_runs`、`restore_checkpoints`：保存只面向空白目标的恢复运行和清单、D1、对象、迁移、搜索及最终检查阶段证据。
4. `restore_checks`：保存清单哈希、表行数、对象哈希、外键、对象引用和搜索重建六项检查；数据库触发器禁止在六项未全部通过时标记恢复成功。

在线下载是待本地封装的可校验原始分卷。本地工具默认使用加密容器保存备份，并按正式迁移外键拓扑导入空白 D1，逐项上传和回读 KV/R2 对象。搜索索引不进入权威备份，必须在目标系统重建完成后才能收口恢复。

### `0019-旧系统数据迁移.sql`

该迁移建立旧系统迁移运行、阶段检查点、不可变来源映射、失败记录、分类对账、迁移邮件来源和密码处理结果账本。正式迁移必须引用独立目标产生的匹配演练报告；对象写入需要回读校验，D1 可见提交使用确定性编号和可重复来源映射保护重放。

### `0020-用户生命周期与期满清理.sql`

该迁移建立独立注销恢复会话、组织成员关系快照、生命周期清理检查点和父子操作关系，并用数据库触发器保护唯一管理员转让、用户注销以及组织删除和恢复的状态转换。用户和组织的七天恢复期满后由现有后台任务账本分步完成永久清理。

### `0021-收信控制与全域认领.sql`

该迁移服务于第二十七批收信控制与全域认领纵向切片：

1. `inbound_receive_controls`：独立保存域名、邮箱地址或用户的收信暂停状态。
2. `inbound_rejection_rules`：保存发件地址、发件域名、主题关键词和正文关键词四类基础拒收规则。
3. `unallocated_address_periods`、`unallocated_access_grants`：按地址时期隔离未知地址来信，并保存管理员授予的当前查看权限。
4. `unallocated_message_deliveries`、`mailbox_entry_unallocated_deliveries`：保存未分配实际投递，以及认领后与个人邮箱条目的兼容关联。
5. `receive_operation_unallocated_routes`：冻结收信时的未分配路由，并阻止同一操作同时建立已分配与未分配路线。

认领使用一个 D1 原子批次创建个人别名、关闭当前时期、建立历史邮箱条目与实际投递关联、计入逻辑用量、登记搜索和会话任务并写入审计。当前本地验证的单次认领上限为 30 封；该数值在真实 D1 验证完成前只是实现保护线，不是最终产品承诺。

### `0022-运行健康与定时维护心跳.sql`

该迁移服务于第二十九批管理员运行健康状态纵向切片，建立每小时定时维护的权威运行证据：

1. `scheduled_maintenance_runs` 保存不可变运行引用、运行中、成功或失败状态、当前步骤、安全错误代码和开始及完成时间。
2. 状态只能从“运行中”前进到“成功”或“失败”，已经结束的运行不能倒退或重复结束。
3. 健康摘要继续直接聚合现有收信、发信、平台资源和后台任务账本；本迁移不复制邮件正文、附件、地址或密钥。
4. 备份创建时从 `d1_migrations` 读取并冻结实际最新迁移版本，新增正式迁移后不再需要手工更新备份版本常量。

### `0023-账号邀请码注册.sql`

该迁移服务于第三十八批账号邀请码注册纵向切片：

1. `account_registration_invitations` 保存邀请码摘要、AES-GCM 加密副本、绑定域名快照、创建者和撤销事实。
2. `account_registration_invitation_consumptions` 保存一次性使用记录和注册账号快照，唯一约束及触发器阻止并发重复使用。
3. `account_registration_rate_limits` 保存来源 HMAC 摘要、失败窗口与临时阻止时间，不保存来源明文。
4. 删除邮件域名前自动撤销仍未使用的关联邀请码；域名外键随后置空，历史列表继续使用域名快照。
5. 迁移不改写既有表或数据，详细升级、数据检查和回退步骤见[0023 升级说明](../文档/发布/0023升级说明.md)。

### `0024-修复早期逻辑配额表兼容性.sql`

该迁移修复早期开发数据库曾应用的逻辑配额表形状：

1. 同时兼容已有当前结构、只有共享默认策略的早期结构，以及缺少 `logical_storage_usage_entries` 的早期结构。
2. 把共享 KV/R2 默认策略分别拆为用户和组织策略，继续使用已确认的 100 MB 与 1 GB 默认额度。
3. 重建并保留当前配额策略、预留和用量账本，把引用早期共享策略的预留改指向实际主体对应策略。
4. 恢复索引、约束和逻辑配额三张表上的 9 个保护触发器，结束时删除全部 `0024_snapshot` 临时表。
5. 当前正式结构执行时保持业务数据等价；详细影响、检查和回退步骤见[0025 升级说明](../文档/发布/0025升级说明.md)。

### `0025-补齐早期内部投递容量拒绝事实.sql`

该迁移补齐早期开发数据库缺少的站内投递配额拒绝结构：

1. 幂等建立 `internal_delivery_rejections`、操作查询索引和不可修改触发器。
2. 当前数据库已经具备这些对象时不改写表或数据。
3. 与 `0024` 一起构成从 `0023` 到当前版本的完整升级路径。

## 使用命令

```powershell
pnpm db:migrate:local
pnpm db:migrate:remote
```

远程迁移前必须确认目标数据库、备份、版本说明、数据检查和回退步骤。已经应用的迁移文件不得改写；需要调整结构时新增迁移。
