# 0022 升级说明

## 适用版本

- 升级前数据库版本：`0021-收信控制与全域认领.sql`
- 升级后数据库版本：`0022-运行健康与定时维护心跳.sql`
- 发布性质：当前开发版内部升级说明，不代表首发正式发布

## 行为变化

1. 唯一系统管理员的设置页新增收信、发信、存储和定时维护四类运行健康摘要。
2. 普通用户读取健康接口返回 `403`。
3. 每小时定时维护保存运行开始、成功或失败、受限步骤和安全错误代码。
4. 健康页只聚合 D1 权威账本，不显示正文、附件、地址明文或密钥，也不会主动探测外部 Provider。
5. 系统备份在创建时读取并冻结 D1 实际最新迁移版本，不再依赖手工维护的旧版本常量。

## 配置变化

本次升级没有新增 Worker 绑定、部署密钥、环境变量或第三方服务。现有 D1、KV/R2、Queue、`init_key` 和配置加密主密钥保持不变。

## 数据变化

1. 新增 `scheduled_maintenance_runs` 表。
2. 新增按开始时间和状态查询的两个索引。
3. 新增保护运行身份和状态只能前进的两个触发器。
4. 不重建、不改写、不回填现有业务表；KV/R2 对象不变化。

本地升级演练已经验证 112 张既有表的结构与行数不变，代表性管理员、域名、个人别名策略、组织额度策略和逻辑用量数据摘要不变，升级前后外键检查均为零。

## 升级顺序

1. 按[升级与回退手册](../运维/升级与回退手册.md)完成本地演练和升级前完整备份。
2. 执行 `pnpm db:migrate:remote`。
3. 确认最新迁移为 `0022-运行健康与定时维护心跳.sql` 且外键检查为零。
4. 执行 `pnpm deploy`。
5. 登录管理员页面检查四类健康摘要，并等待或手动触发隔离环境中的一次定时维护验证。

## 数据检查

1. `d1_migrations` 最新名称为本说明目标版本。
2. `PRAGMA foreign_key_check` 返回零行。
3. 升级前后用户、域名和邮件数量没有无法解释的差异。
4. `scheduled_maintenance_runs` 存在，首次 Cron 前显示“尚无记录”，首次成功后保存完成时间。
5. 健康接口普通用户为 `403`，唯一系统管理员为 `200`。
6. 新建备份的清单迁移版本为 `0022-运行健康与定时维护心跳.sql`。

## 回退说明

`0022` 是纯新增且上一版本代码可以忽略的结构。数据检查全部通过但新 Worker 行为需要回退时，可以重新部署上一版本 Worker，并保留已经应用的 `0022`；不要删除新表或改写迁移账本。

若外键、数量、对象引用或关键流程检查失败，停止写入并依据[升级与回退手册](../运维/升级与回退手册.md)把升级前完整备份恢复到迁移版本一致的全新空白资源，六项检查通过后切换 Worker 绑定。禁止在原生产库执行临时逆向 SQL。

## 已知限制

1. 运行健康是账本推断，不是 Provider 或通知通道在线探测。
2. 真实 Cloudflare Free Cron、D1、KV/R2、Queue 和绑定切换尚未完成远程演练。
3. 2026-08-14 已补齐管理员页面桌面及 `390 × 844` 手机刷新交互、布局和控制台复核；真实 Cloudflare Cron 与远程资源交叉验证仍待执行。
4. 当前开发版没有产品内自动升级和自动回退按钮。
