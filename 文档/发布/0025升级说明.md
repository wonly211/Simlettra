# 0025 升级说明

## 适用范围

本文用于将最新迁移为 `0023-账号邀请码注册.sql` 的 Simlettra 升级到 `0025-补齐早期内部投递容量拒绝事实.sql`。升级会依次应用 `0024` 和 `0025`，主要修复早期开发数据库的逻辑配额表兼容性；全新数据库和已经具备当前结构的数据库也可以安全执行。

## 行为变化

- 早期数据库可以正常保存草稿并执行站内投递，不再因缺少逻辑用量账本或内部投递拒绝事实而失败。
- 用户与组织继续使用独立默认逻辑存储配额：KV 各 100,000,000 字节，R2 各 1,000,000,000 字节。
- 自发自收邮件仍分别出现在收件箱和已发送中，但同一会话详情只显示一封物理邮件。

## 数据影响

- `0024` 重建 `logical_storage_quota_policies`、`logical_storage_reservations` 和 `logical_storage_usage_entries`，保留当前策略、预留和用量数据。
- 早期共享默认策略会拆成用户和组织两份；引用共享策略的预留会按实际主体改指向对应默认策略。
- `0025` 只在缺失时建立 `internal_delivery_rejections` 及其索引和不可修改触发器。
- 邮件、正文、附件、账号、地址、组织和邀请码数据不被改写。
- 不新增部署配置或密钥。

## 升级前准备

1. 确认当前最新迁移是 `0023-账号邀请码注册.sql`。
2. 停止会产生写入的 Worker 流量和定时任务。
3. 使用管理员备份功能导出 D1 与 KV/R2 完整备份，并确认清单和对象校验通过。
4. 保存升级前 D1 资源快照或副本；不要只依赖应用层回退 SQL。
5. 先在数据副本执行本文步骤并完成数据检查。

## 执行升级

```powershell
pnpm db:migrate:remote
```

KV 部署使用对应配置：

```powershell
pnpm db:migrate:remote:kv
```

不要修改已经应用的迁移文件，也不要在升级过程中同时启动写入流量。

## 数据检查

确认迁移账本、外键和临时表：

```sql
SELECT name FROM d1_migrations ORDER BY id DESC LIMIT 2;
PRAGMA foreign_key_check;
SELECT name FROM sqlite_schema WHERE name LIKE '%0024_snapshot%';
```

预期最新两项依次为 `0024-修复早期逻辑配额表兼容性.sql`、`0025-补齐早期内部投递容量拒绝事实.sql`，外键和临时表查询均无结果。

确认四份默认配额和关键结构：

```sql
SELECT storage_mode, default_owner_type, limit_bytes
FROM logical_storage_quota_policies
WHERE owner_type = 'system_default' AND policy_status = 'active'
ORDER BY storage_mode, default_owner_type;

SELECT COUNT(*) FROM logical_storage_reservations;
SELECT COUNT(*) FROM logical_storage_usage_entries;
SELECT name FROM sqlite_schema
WHERE name IN ('internal_delivery_rejections', 'prevent_internal_delivery_rejection_change');
```

将升级后的预留和用量数量与升级前备份对账；四份默认配额应分别对应 KV 用户、KV 组织、R2 用户和 R2 组织。

## 业务检查

1. 管理员登录并查看运行健康与资源用量页面。
2. 新建草稿并确认显示“已保存到服务器”。
3. 向自己的地址发送一封站内邮件，再回复一次。
4. 确认收件箱会话为两封物理邮件，详情没有因收件箱和已发送副本重复。
5. 检查后台任务、发信操作和审计日志没有异常。

## 回退

`0024` 会重建表，不提供生产环境逆向 SQL。需要回退时：

1. 立即停止 Worker、Queue consumer 和 Cron 写入。
2. 废弃升级后的 D1 目标，不在其上继续写入。
3. 恢复升级前的 D1 快照或在空白资源中使用完整备份恢复。
4. 恢复与该 D1 时点一致的 KV/R2 对象资源。
5. 部署升级前源码并重新执行外键、对象引用和业务检查。

本地 `0023` 到 `0025` 升级与独立回退目标已经通过；真实 Cloudflare Free 远程资源仍必须在数据副本上完成一次演练后才能发布。
