# 澄笺 | Simlettra 第七批个人地址与别名管理

## 文档状态

- 阶段：正式纵向功能切片
- 状态：已完成
- 开始日期：2026-08-12
- 依据：需求 `4.03` 至 `4.12`、`7.13`、`9.09`、`11.08`，需求变更 `0006`、`0007`，ADR `0014`、`0015`、`0035`、`0036`

## 本批目标

完成个人主地址和个人别名的最小管理闭环：用户查看自己的地址，在允许且未超额时创建个人别名，管理员为用户设置额度和自助创建权限并代为分配别名，用户整理地址列表、设置默认发件地址，以及用户或管理员删除个人别名。

## 验收条件

1. 初始化管理员和新建普通用户都原子获得默认 20 个个人别名额度，并默认允许自行创建。
2. 管理员可以查看每名用户的别名已用数量、额度和自助创建权限，并分别修改额度与权限。
3. 管理员调低额度不会删除已有别名；已用数量达到或超过额度后，任何人都不能继续为该用户新增别名。
4. 用户可以查看自己的主地址和全部当前个人别名，不能查看其他用户的个人地址。
5. 用户自助创建前检查账号正常、策略允许、额度未满、域名启用、地址命名规则和全局地址占用。
6. 管理员可以在相同额度和地址规则下为指定活动用户创建并分配个人别名，不受该用户自助创建开关限制。
7. 地址创建以一个 D1 原子批次建立地址身份、当前占用、个人别名归属、用户偏好和成功审计；任一步失败不留下半个地址。
8. 地址列表可以修改自定义显示名称、置顶状态和顺序，并从当前有权使用的个人地址中选择唯一默认发件地址。
9. 主地址不能通过本批接口删除；个人别名删除结束归属、撤销个人偏好并回退失效的默认发件地址。
10. 当前管理员配置的别名保留期尚未进入正式结构，因此本批按已确认默认值 0 天立即释放当前占用；以后增加保留期设置时不得改写历史地址身份。
11. 所有重要修改写入结构化审计，不记录地址以外的个人邮件内容、密码、令牌或密钥。
12. HTTP 权限、CSRF、额度并发保护、地址冲突、暂停域名、偏好唯一性、删除回退和事务失败具有自动化测试。

## 数据结构审查

本批新增正式迁移 `0004-个人别名策略.sql`：

1. 新增 `user_alias_policies`，与用户一对一保存额度和自助创建权限。
2. 为已有用户回填默认额度 20、允许自助创建。
3. 新增当前个人别名归属的数据库准入触发器，保护用户、策略、额度、域名和地址占用一致性。
4. 继续复用 `email_addresses`、`address_claims`、`address_bindings` 和 `user_address_preferences`，不建立第二套地址表。

## 本批不包含

1. 主邮箱地址迁移。
2. 管理员配置地址最短长度、禁止文字、保留名称和 0 至 30 天别名保留期的页面。
3. 组织共享地址、组织成员发信权限和全域收信认领。
4. 发信签名编辑和真正的邮件发送权限判定。
5. 已删除别名保留期到期后的定时释放任务。

## 完成内容

1. 正式迁移 `0004-个人别名策略.sql` 建立独立用户策略，为已有用户回填 20 个默认额度和自助创建权限，并以数据库触发器保护并发额度边界。
2. 初始化管理员和管理员创建普通用户时，策略与用户、密码、主地址及默认地址偏好在同一 D1 原子批次中建立。
3. 用户接口提供个人地址总览、自助创建别名、修改显示名称与置顶、同组排序、设置默认发件地址和二次确认删除。
4. 管理员接口提供全部用户的别名额度、自助创建开关、具体别名列表，以及策略修改、别名分配和二次确认删除。
5. 所有修改继续使用受保护会话、同源与 CSRF 校验；地址身份、占用、归属、偏好和成功审计在同一批次提交，审计失败时完整回滚。
6. Vue 网页为普通用户和管理员分别提供可直接操作的地址管理区域，并在页面中明确新用户默认额度为 20。
