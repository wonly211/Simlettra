# 第三十三批：本地安全验收准备

## 状态

- 状态：已完成
- 完成日期：2026-08-13
- 工程变化：增强两项安全回归，新增安全测试命令与验收记录；无产品代码、依赖或 D1 迁移变化

## 目标

为需求 12.10 指定的越权访问、脚本注入、恶意附件名、令牌泄露和重复投递五类风险建立清楚、可重复的本地证据入口，同时保留真实部署和人工安全总检查的边界。

## 完成内容

1. 登录回归新增明文会话与 CSRF 令牌不得出现在响应正文、请求 URL 或 `Location` 的断言；既有 D1 摘要与会话列表脱敏断言继续保留。
2. 邮箱 HTTP 回归把普通附件名替换为 `../../evil<script>.txt`，验证显示名移除路径、脚本与控制字符，下载响应头不能注入额外字段。
3. `package.json` 新增 `pnpm test:security`，统一执行七个安全相关测试文件和生产安全构建。
4. 新建[本地安全验收记录](../验收/本地安全验收记录.md)，逐项说明证据、结论和未覆盖边界。
5. 没有因为本地结果通过而勾选完整发布安全门槛；验收-19仍为“部分通过”。

## 验证结果

- 登录与恶意附件名定向回归：2 个文件、5 项测试通过。
- 安全测试集合：7 个文件、45 项测试通过。
- 测试 TypeScript、定向 ESLint 和 Prettier 通过。
- 生产安全构建通过，`dist` 不包含 `.dev.vars` 或当前已知密钥内容。
- 全量自动化：55 个测试文件、226 项测试全部通过。

## 已知限制

- 当前工作环境的 pnpm 包装器会在执行项目脚本前尝试访问外部包，因此本批使用与 `pnpm test:security` 完全相同的 Vitest 参数和安全构建工具分开执行；仓库脚本本身已通过 JSON、格式和组成命令验证。
- DOMPurify 的实际浏览器行为沿用第十一批真实样例证据，本批没有新增跨浏览器 DOM 测试。
- 日志总审计、真实外部服务故障注入、扩展恶意样本和独立依赖审查仍是发布前事项。
