# 第三十批升级与回退演练

## 状态

本地升级、数据检查和独立回退目标演练已完成；真实 Cloudflare Free 远程资源、Worker 绑定切换和维护窗口仍待发布前演练。

## 目标

把 `2.07` 和 `12.12` 从文字要求落实为每次发布可重复执行的版本说明、升级检查、回退决策和本地自检，补齐 `验收-27` 中健康状态之外的发布流程。

## 架构依据

- [0012 采用 Drizzle 查询层和 Wrangler 迁移账本](../架构决策记录/0012-采用Drizzle查询层和Wrangler迁移账本.md)。
- [0040 以加密本地容器和空白资源分阶段完成完整恢复](../架构决策记录/0040-以加密本地容器和空白资源分阶段完成完整恢复.md)。
- [0045 区分代码回退与空白资源恢复](../架构决策记录/0045-区分代码回退与空白资源恢复.md)。

## 验收条件

1. 发布说明明确行为、配置、数据、顺序、检查、回退和已知限制。
2. 本地工具从上一迁移版本重放正式迁移，不能依赖当前数据库已经升级后的状态。
3. 升级前后外键为零，既有结构、全部既有表行数和代表性数据保持不变。
4. 新迁移约束能够工作，已经结束的定时维护状态不能倒退。
5. 升级前快照能够建立独立回退目标，并恢复到上一迁移版本和相同代表性数据。
6. 统一 `check` 包含升级回退自检，后续新增迁移忘记更新演练目标时必须失败。
7. 文档明确代码回退与数据恢复的适用条件，不建议在生产执行通用逆向 SQL。

## 实现结果

1. `tools/本地升级回退自检.mjs` 对当前发布跨度设置明确版本，当前固定验证 `0023` 依次升级到 `0024` 和 `0025`；新增迁移后目标与迁移目录不一致时立即失败。
2. 工具从空库重放 `0001` 至 `0021`，注入管理员、系统实例、域名、个人别名策略、组织额度策略和逻辑用量代表性数据。
3. 工具保存升级前隔离快照，应用 `0022` 后比较既有结构摘要、112 张既有表行数和代表性数据摘要，并执行外键和心跳约束检查。
4. 工具从升级前快照创建另一份独立数据库，确认迁移版本恢复为 `0021`、数据摘要一致、外键为零且不存在升级后表。
5. `package.json` 新增 `pnpm test:upgrade-rollback`，并把它加入 `pnpm check`。
6. [升级与回退手册](../运维/升级与回退手册.md)面向非程序员说明准备、备份、迁移、部署、只读检查、代码回退和空白资源恢复。
7. [0022 升级说明](../发布/0022升级说明.md)记录当前版本的具体影响与兼容回退边界。

## 验证结果

- 正式迁移总数：22。
- 升级路径：`0021-收信控制与全域认领.sql` 到 `0022-运行健康与定时维护心跳.sql`。
- 保持不变的既有表：112 张。
- 通过项目：升级前外键、迁移顺序、既有结构、既有表行数、代表性数据、心跳约束和独立回退目标，共 7 类。
- 工具只使用临时本地文件，结束后自动清理，不读取真实用户数据，不连接远程 Cloudflare。
