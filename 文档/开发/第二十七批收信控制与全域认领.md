# 第二十七批收信控制与全域认领

## 状态

本地闭环与网页视觉复核已完成；真实 Cloudflare Free 远程演练仍待补充。

## 目标

完成管理员收信控制、基础拒收规则、全域收信、未分配来信查看和地址认领的完整闭环。暂停或拒收必须发生在持久保存前；未分配来信只在独立视图中向获授权用户开放，认领后才成为个人别名和个人邮箱历史。

## 需求依据

- `5.06`：域名默认拒收未创建地址，管理员可以启用全域收信。
- `5.07`：管理员指定能够查看域名未分配来信的用户。
- `5.08`：获授权用户可以认领未分配地址并取得当前未分配时期的历史来信。
- `5.09`：管理员可以暂停域名、邮箱地址或用户的收信。
- `5.10`：管理员可以按发件地址、发件域名、主题或正文关键词拒收。
- 跨模块基线-01、基线-05：暂停后不保存、不排队；认领创建个人别名并受自建权限、别名配额和命名规则约束。
- ADR `0018`：同一地址的不同时期必须隔离，认领事务要么完整成功，要么完全不改变现状。

## 验收条件

1. 域名、邮箱地址或用户处于暂停收信状态时，邮件在读取或保存原始 MIME 前被拒收；恢复后只接收此后到达的邮件。
2. 禁用、待注销、正在清理或已删除用户继续按照不可收信处理；系统管理员身份不会绕过该规则。
3. 管理员可以建立、暂停、恢复和删除四类拒收规则：完整发件地址、发件域名、主题关键词、正文关键词。
4. 完整发件地址和发件域名规则在读取原始 MIME 前判断；主题和正文关键词在受限解析后、写入 D1、KV 或 R2 前判断。
5. 主题和正文规则只检查解码后的主题、纯文本正文和 HTML 可见文字，不检查附件内容；匹配不区分大小写，关键词按完整 Unicode 文字包含关系判断。
6. 域名默认拒收未创建地址；启用全域收信后，未知地址建立或复用当前开放的未分配地址时期，并保存投递事实，但不建立个人或组织邮箱条目。
7. 未分配来信只出现在独立视图；获授权用户可以查看列表、搜索必要字段、阅读正文和下载附件，但认领前不能执行已读、星标、归档、垃圾箱或永久删除。
8. 管理员可以为每个启用全域收信的域名授权或撤销多个当前已启用用户；撤销后用户立即失去该域名全部未分配来信访问权。
9. 获授权用户认领时必须仍为启用状态，仍具有域名查看权、自建别名权限和足够别名配额，地址也必须符合当前命名规则且未被占用。
10. 认领在一个 D1 原子批次中创建地址身份、当前占用、个人别名归属和偏好，关闭当前未分配时期，并为该时期全部邮件建立个人邮箱条目及投递关联；任一步失败全部回滚。
11. 两名用户并发认领同一时期时只有第一名成功；失败者不获得地址、邮箱条目或部分历史。
12. 未分配邮件在认领前只消耗 Cloudflare 平台免费资源，不计入任何用户或组织逻辑配额；认领时按每封物理邮件一次性计入认领用户，额度不足则整次认领失败。
13. 同一封邮件发往多个未知地址时，共享一份物理内容，但每个未分配地址时期独立查看和认领；认领其中一个地址不改变其他时期。
14. 地址以后释放并再次收到未知来信时建立新时期，新的认领者不能看到过去已经关闭或认领时期的邮件。
15. 管理配置、授权、暂停、恢复、规则变化和认领均写入不包含邮件正文、关键词明文以外敏感内容或对象键的结构化审计。

## 实现边界

### 拒收时点

Cloudflare Email Routing 的 `email` 入口只有一次原始邮件流。实现会在进入现有持久化事务前完成规则判断：

1. 先规范化信封发件人和实际收件地址，并检查域名、地址、用户状态以及发件地址或域名规则。
2. 只有需要检查主题或正文规则时才把原始流读入 `ArrayBuffer`，使用当前锁定的 `postal-mime` 适配器执行同一组 20 MB 与恶意结构限制。
3. 命中规则时立即调用 `setReject`，不建立 D1 操作、不写 KV/R2 对象、不进入 Queue。
4. 未命中时把已经读取的原始字节交给现有接收事务，不能再次读取原始流；原始 MIME 持久化后，仍由现有 Queue 完整性链路再次解析这些字节，生成正文、附件、邮件关系和搜索所需数据。

因此，启用主题或正文关键词规则后，同一封邮件会发生两次 MIME 解析：Email Handler 中的持久化前内容预检，以及 Queue 中的正式完整性解析。这会同时增加接收入口的 CPU 消耗和整条收信链路的总计算成本，必须通过真实 Workers Free Email Routing 与 Queue consumer 环境复核；如果真实 Free 环境无法承受，不得静默改为“先接收后隐藏”，而要重新提交产品方案。

### 未分配逻辑容量

未分配邮件没有用户或组织所有者，因此认领前只受 Cloudflare 平台容量停止线约束。认领时按当前时期内每封不同物理邮件的原始大小计算新增逻辑用量，并在同一 D1 原子批次中写入用户用量账本。额度不足时保持时期开放，用户可以先清理个人邮件或由管理员调整配额后重试。

### 大历史认领

首个实现以 D1 单次批次和约 90 参数分块为边界。认领前先统计当前时期的不同物理邮件数量和所需语句数；当前本地验证上限为 30 封，超过时明确返回 `claim_too_large`，不能只迁移一部分历史。30 封在真实 D1 验证完成前只是实现保护线，不是最终产品限制。

## 实现结果

1. 正式迁移 `0021-收信控制与全域认领.sql` 已建立收信暂停、拒收规则、未分配地址时期、查看授权、未分配投递及认领关联结构。
2. `email` 入口在持久化前执行域名、地址、用户状态和四类拒收规则；未分配邮件保存完整内容但不建立邮箱条目、通知、自动转发或主体逻辑用量。
3. 管理员 HTTP 与网页可以管理域名、地址和用户暂停，全域收信模式、查看授权及拒收规则。
4. 获授权用户可以在独立邮箱视图搜索、阅读和下载未分配来信，并在二次确认后原子认领地址及当前时期历史。
5. 邮箱读取通过统一应用层语义合并已分配与认领后的未分配实际投递，调用者不需要理解两张物理表。

## 验证结果

- 第二十七批定向验证：4 个测试文件、21 项测试全部通过。
- 全量自动化：52 个测试文件、213 项测试全部通过。
- Vue、Worker、配置与测试 TypeScript 检查、ESLint、Prettier、Cloudflare 类型生成和生产安全构建全部通过。
- 2026-08-14 已经通过网页启用全域收信和当前用户授权，经本地 Email Routing 入口投递未知地址邮件，并完成桌面详情、认领确认及 `390 × 844` 手机认领。历史邮件进入新个人别名后，全域收信和授权恢复到测试前状态；页面无溢出或控制台错误。

## 剩余上线门槛

1. 在真实 Workers Free Email Routing 与 Queue consumer 中验证接近 20 MB 邮件，以及启用内容拒收规则时两次 MIME 解析的 CPU、内存、并发和重试代价。
2. 在真实 Cloudflare Free D1、KV 和 R2 环境中验证全域收信、权限撤销、并发认领、事务语句规模和当前 30 封保护线。

## 非目标

1. 不建立完整反垃圾或病毒扫描系统。
2. 不检查附件正文中的关键词。
3. 不允许认领前整理或删除共享的未分配来信。
4. 不把未分配来信混入个人统一收件箱。
5. 不改变已经接受的未认领时期长期保留策略；永久清理仍由后续生命周期工作处理。
