# 第二十九批运行健康状态

## 状态

本地实现、迁移、自动化和质量门槛已完成；桌面及 `390 × 844` 手机视口的刷新交互、布局和控制台复核已于 2026-08-14 补齐。真实 Cloudflare Free 运行演练尚未执行。

## 目标

让唯一系统管理员在不读取邮件正文、不触发外部探测的情况下，集中判断收信、发信、存储和定时维护是否正常，并为每小时 Cron 留下可长期核对的运行证据。

## 需求依据

- `2.08`：管理员可以查看收信、发信、存储和定时任务是否正常，运行日志不显示邮件正文。
- `9.03`、`9.04`：系统管理员负责运行状态，但不能通过产品界面读取普通用户个人邮件正文。
- `12.11`：管理员能够判断系统是否健康，日志可以帮助定位问题但不能泄露邮件内容。
- `验收-27`：健康状态与升级流程需要分别完成；本批只收口健康状态部分。
- [0044 以 D1 账本聚合运行健康并记录定时维护心跳](../架构决策记录/0044-以D1账本聚合运行健康并记录定时维护心跳.md)。

## 验收条件

1. 只有当前唯一系统管理员可以读取健康摘要，普通用户返回 `403`。
2. 页面显示收信、发信、存储和定时维护四类状态、摘要、关键数量和最近时间。
3. 状态名称统一为“正常”“需检查”“尚无记录”和“未配置”，新系统不能被误报为正常。
4. 停滞收发操作、结果未知、缺少发信路线、资源预警或停止、失败或停滞的 Cron、需人工处理及逾期任务能够提示“需检查”。
5. 正常退信等业务结果不直接等同系统故障；打开健康页不会主动调用外部 Provider 或通知通道。
6. 每次定时维护保存开始、成功或失败状态；失败只记录安全步骤和错误代码，不记录正文、附件、地址或密钥。
7. 桌面和 `390 × 844` 手机视口没有横向溢出、遮挡、截断或控制台错误，刷新按钮具有明确状态。
8. 新增迁移进入备份版本事实，备份清单不再硬编码旧迁移版本。

## 实现结果

1. 正式迁移 `0022-运行健康与定时维护心跳.sql` 建立 `scheduled_maintenance_runs`、查询索引和不可逆状态触发器。
2. `src/modules/operations-health/` 聚合现有收信操作、Provider 与域名路线、逐收件人发送状态、平台资源快照、后台任务和定时维护账本。
3. `GET /api/auth/admin/operations-health` 通过现有会话边界和服务端唯一管理员检查返回四类只读摘要。
4. `src/shared/contracts/operations-health.ts` 和 `src/web/services/operations-health-api.ts` 提供前后端契约；Vue 设置页显示响应式四块状态及手动刷新。
5. 每小时定时维护处理器在执行清理、补投、资源刷新等步骤前写入心跳，成功后结束；失败时冻结当前步骤和安全错误摘要。
6. 健康聚合不读取邮件正文、附件内容、地址明文或密钥，也不发起 Provider 在线探测。
7. 备份服务改为创建备份时读取 `d1_migrations` 的实际最新版本并冻结到 `backup_runs`，最终清单沿用该值，避免新增迁移后仍错误标记为 `0018`。

## 判定边界

1. 收信或发信操作超过 15 分钟仍处于处理中，定时维护超过 15 分钟仍在运行，均视为停滞。
2. 最近一次定时维护距当前超过两小时，或者存在需人工处理及逾期后台任务时，显示“需检查”。
3. 尚无收信或 Cron 记录时显示“尚无记录”；没有可用 Provider 或域名路线时显示“未配置”。
4. 存储状态复用当前部署模式下 D1 与 KV/R2 的最新资源快照；缺失、过期和达到阈值分别保留可观察差异。
5. 健康页是账本摘要，不替代真实 Cloudflare、Resend、SMTP2GO 或通知通道的远程联调。

- 全量自动化：55 个测试文件、224 项测试全部通过。
- Prettier、ESLint、Cloudflare 类型生成、Vue、Worker、Node 与测试 TypeScript 检查，以及生产安全构建全部通过。
- 临时本地 `D1 + KV` 与 `D1 + R2` 完整备份恢复自检，以及 KV/R2 旧系统迁移完整自检全部通过。

## 非目标

1. 不新增独立监控 Worker、Durable Objects、WebSocket 或第三方可观测平台。
2. 不在健康页显示邮件正文、附件、完整邮箱地址、Provider 密钥或原始错误堆栈。
3. 不因查看页面而发送测试邮件、测试通知或调用外部服务。
4. 不把健康状态页等同于版本升级、数据检查或回退流程。
