# 第二十二批用户与组织逻辑存储配额

## 状态

已完成本地纵向切片，进入真实 Cloudflare Free 远程复核前的后续开发阶段。

## 目标

让管理员能够为用户和组织分别管理逻辑存储额度，并让收信、草稿、附件、发送和删除沿用同一套可恢复的容量账本。

## 当前规则

| 存储模式 | 用户默认额度 | 组织默认额度 |
| --- | ---: | ---: |
| `D1 + KV` | 100,000,000 字节（100 MB） | 100,000,000 字节（100 MB） |
| `D1 + R2` | 1,000,000,000 字节（1 GB） | 1,000,000,000 字节（1 GB） |

以上是 Simlettra 的用户与组织逻辑配额，使用十进制字节。Cloudflare 账号级免费额度是另一层平台资源上限，由第二十一批资源用量切片单独管理。

系统管理员可以：

- 修改用户默认额度或组织默认额度；
- 为单个用户或组织设置覆盖额度；
- 清除覆盖额度，让主体恢复使用默认值；
- 查看已提交用量、进行中的预留、剩余额度以及调低后是否已经超额。

调低额度不会删除已有数据。已经超额的主体仍可读信、导出、备份和永久删除，但不能继续增加容量；删除释放空间后即可恢复新增操作。

## 计费口径

- 用户的主地址和个人别名合并计算；同一物理邮件投递到用户的多个地址只计一次。
- 组织邮件按组织计算，不按成员人数重复计算。
- 草稿正文、草稿附件和冲突副本计入草稿创建者的用户配额。
- 已发送副本计入发件主体；同一用户同时产生已发送和收件条目时只计一次物理内容。
- 垃圾箱在永久删除前继续占用额度；永久删除完成后才归还。
- 搜索索引、缓存、通知和转发记录不重复计入逻辑邮箱容量。

## 实现边界

- 正式迁移：`migrations/0016-用户与组织逻辑存储配额.sql`。
- 模块：`src/modules/storage-quotas/`。
- 管理员接口：
  - `GET /api/auth/admin/storage-quotas`
  - `PUT /api/auth/admin/storage-quotas/defaults/:ownerType`
  - `PUT /api/auth/admin/storage-quotas/:ownerType/:ownerId`
- 管理员网页位于“用户与组织存储配额”区域。
- 容量预留提交、释放和过期清理均保持幂等；失败不能留下占用或半封可见邮件。
