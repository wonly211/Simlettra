## 本批目标

让一套全新部署可以通过网页完成首次初始化，并用正式 D1 迁移、服务端鉴权和自动化测试建立唯一管理员、首个邮件域名和管理员主邮箱。

## 已实现内容

1. 建立正式迁移 `0001-系统身份与地址基础.sql`，包含系统、用户、密码、域名、地址、组织基础和初始化限速所需的十张表。
2. 提供 `/api/system/status`、`/api/initialization/authorize` 和 `/api/initialization/complete` 三个 HTTP 接口。
3. 使用部署配置中的 `init_key` 完成初始化鉴权；密钥摘要使用恒定时间比较，同一来源 15 分钟内五次失败后阻止 15 分钟。
4. 使用 Workers Web Crypto 的分轮 PBKDF2-HMAC-SHA-256 保存管理员密码：总计 900,000 次迭代，分为 9 轮、每轮 100,000 次，使用 16 字节盐和 32 字节结果。
5. 使用 D1 `batch()` 原子建立用户、密码、域名、主邮箱、地址占用、地址归属、用户地址偏好和系统实例；重复初始化或数据冲突不会留下部分数据。
6. 提供三步 Vue 初始化向导：部署鉴权、管理员与域名、最终确认；完成后显示管理员主邮箱、域名和存储模式。
7. 邮箱地址采用 ASCII 前缀、统一小写和 IDNA/Punycode 域名规范化；不在应用内重复验证域名所有权。
8. `pnpm build` 统一调用 `tools/安全构建.mjs`，避免 Cloudflare Vite 插件把本地 `.dev.vars` 带入生产构建。

## 明确不在本批实现

1. 密码登录、会话 Cookie、退出登录和管理员恢复流程。
2. 初始化完成后的管理后台与普通设置页面。
3. 组织成员、邀请、邮件收发、搜索、通知、备份和旧系统迁移业务。
4. 真实 Cloudflare 远程 D1、KV/R2、Queue 和 Email Routing 验收。

## 剩余风险与下一步

本批只验证本地高保真 D1 和本地 Worker。真实 Workers 已发现单次 PBKDF2 超过 100,000 次会返回 `NotSupportedError`，现已改用分轮派生；远程 D1 迁移、CPU 表现和并发初始化仍需在真实 Cloudflare 环境复核。
