## 本批目标

完成全系统地址命名策略和个人别名保留期闭环：管理员集中设置规则，所有新地址使用同一校验；删除个人别名时立即停止使用，并按 0 至 30 天策略立即释放或保留占用；到期释放通过 D1 权威任务、Queue 唤醒和定时补漏可靠完成。

## 验收条件

1. 新部署和升级后的默认策略都是邮箱前缀最短 1 个字符、无禁止文字、无保留名称、个人别名保留期 0 天。
2. 只有系统管理员可以查看和修改全局地址策略，修改接口使用正常会话、同源和 CSRF 保护。
3. 禁止文字按“前缀包含该文字”判断，保留名称按“完整前缀完全相同”判断；输入统一小写、去除重复项并使用首发允许的 ASCII 字符。
4. 策略更新以版本防止覆盖，并与文字集合和成功审计原子提交；审计不保存密码、令牌、密钥或邮件内容。
5. 初始化主地址、管理员创建用户主地址和个人别名都执行同一策略；数据库触发器拒绝绕过应用的非法新地址。
6. 收紧规则不修改、不停用、不删除任何现有地址。
7. 删除别名时结束归属、撤销个人偏好并回退默认发件地址；保留期为 0 时立即释放，非 0 时把地址占用改为保留并冻结当时的策略版本与释放时间。
8. 保留期内相同地址不能重新建立；到期任务释放占用后可以建立新的地址身份，旧身份和旧归属历史不被改写。
9. `background_tasks` 保存权威状态；Queue 消息只包含任务编号和输入版本；重复消费、未到期消费和消费者中断都不能造成提前释放或重复副作用。
10. 每小时定时任务扫描到期或遗漏任务并重新投递；Queue 暂时不可用不回滚已经安全保留的地址。
11. 管理员网页可以编辑完整策略，并在用户删除个人别名前明确显示“立即释放”或具体保留天数和预计释放时间。
12. 迁移、权限、CSRF、策略并发、三类规则、非追溯性、立即释放、保留释放、重复消息、定时补投和事务失败具有自动化测试。

## 本批不包含

1. 主邮箱地址迁移和旧主地址去向选择。
2. 组织共享地址创建；后续实现必须复用本批策略。
3. 用户注销、组织删除、邮件垃圾箱和通用永久删除操作。
4. 管理员查看全部后台任务、手工重试和运行告警页面。
5. 除 `alias_release` 外的邮件解析、发信、通知、转发、对象清理和对账任务处理器。

## 完成结果

1. 正式迁移 `0005-地址策略与后台释放任务.sql` 建立全局地址策略、删除操作、删除步骤、后台任务和任务尝试结构，并用数据库触发器保护新地址规则和任务状态流转。
2. 管理员 HTTP 接口和 Vue 网页可以查看、编辑完整策略；写入使用会话、同源、CSRF、管理员权限、策略版本和同批成功审计。
3. 初始化、普通用户主地址和个人别名共享地址策略校验；现有地址不被追溯处理。
4. 个人别名删除会立即结束归属。保留期为 0 时立即释放；大于 0 时冻结策略版本与到期时间，并建立 `alias_release` 权威任务。
5. 单 Worker 的 Queue consumer 使用租约和领取令牌处理任务；每小时 Cron 扫描到期或租约遗漏任务，Queue 消息只含任务编号与输入版本。

## 验证证据

1. `pnpm check` 通过格式、ESLint、Cloudflare 类型生成、严格 TypeScript、17 个测试文件中的 80 项测试和安全生产构建。
2. 自动化覆盖默认策略、数据库触发器、管理员权限、CSRF、版本冲突、文字规范化、非追溯性、审计失败回滚、立即释放、两天保留、未到期忽略、定时补投、到期释放和重复消息。
3. 本地正式迁移已应用；浏览器真实验证了规则保存、按一天保留显示删除影响、保留期内拒绝重新创建，以及策略恢复默认。
4. 桌面与 `390 × 844` 手机视口无横向溢出，浏览器控制台无警告或错误；浏览器测试数据清理后外键检查为零。

## 剩余边界

真实 Cloudflare Queue 的并发、重试和 Cron 触发仍需在远程 Workers Free 环境复核。该复核属于上线门槛，不改变当前 D1 权威状态和本地已验证行为。
