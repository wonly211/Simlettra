## 本批目标

让唯一系统管理员查看、添加、暂停、恢复和删除邮件域名，清楚区分“暂时停止使用”和“永久移除”。Simlettra 继续信任管理员，不增加 DNS TXT 或 Cloudflare Zone 所有权验证。

## 验收条件

1. 只有当前唯一系统管理员的正常会话可以查看和修改邮件域名。
2. 管理员输入合法邮件域名后，系统按 IDNA/Punycode 规则规范化，并直接创建为启用状态。
3. 规范化后重复的域名不能再次添加，失败时不留下部分数据或成功审计。
4. 管理员可以暂停域名；暂停状态保留域名、地址和历史数据，不等同于删除。
5. 管理员可以恢复已暂停域名，域名规范名称始终不可修改。
6. 域名状态变化写入结构化审计；状态并发变化时不能产生与实际状态不一致的成功结果。
7. 删除前网页显示具体域名和影响，并要求二次确认。
8. 只要域名仍有任何地址身份，就必须拒绝删除；邮件表进入正式迁移后，删除检查还必须扩展到关联邮件和发信配置。
9. 当前没有地址及其他正式关联结构的空域名可以永久删除，删除与成功审计在一个 D1 原子批次中提交。
10. 域名添加、暂停、恢复和删除都不执行 DNS 查询，也不建立所有权验证记录。
11. HTTP 权限、规范化重复、状态切换、删除阻止、原子回滚，以及桌面和手机网页流程具有自动化或浏览器验证。

## 数据结构审查

本批不新增正式迁移：

1. `mail_domains` 已保存显示名称、规范名称、`active`、`paused`、`deleting` 状态、暂停时间和更新时间。
2. `email_addresses.domain_id` 使用 `ON DELETE RESTRICT`，可作为当前正式结构的最后一道地址关联保护。
3. `audit_events` 已能记录域名添加、状态变化和永久删除。
4. 当前正式工程尚无邮件、Provider 路线和域名配额表，因此本批删除检查只能覆盖已经正式存在的地址关系；以后相关表迁入时必须同步扩大阻止条件。

## 本批不包含

1. Cloudflare Email Routing、Resend 或 SMTP2GO 的配置测试和健康状态。
2. 全域收信模式、未分配来信查看者和地址认领。
3. 域名月度发件配额、当月用量和 Provider 路线。
4. 主邮箱迁移、别名、组织共享地址及单个地址暂停。
5. 带有关联邮件或异步清理任务的完整域名删除工作流。

## 完成内容

1. 新增管理员域名列表、添加、暂停、恢复和永久删除 HTTP 接口；所有修改操作继续使用登录会话、同源和 CSRF 三重校验。
2. 域名添加复用统一的 IDNA/Punycode 规范化规则，管理员提交后直接启用，不进行 DNS 查询或所有权验证。
3. 新增域名管理应用服务，将新增、状态变化或删除与对应成功审计放在同一个 D1 原子批次中。
4. 暂停域名后，用户创建接口不再把该域名列为可分配域名；恢复后重新可用。
5. 永久删除在网页和服务端分别检查关联地址，并要求网页明确勾选二次确认；当前有关联地址的初始化域名不能删除。
6. Vue 管理员页新增行式域名管理区域，显示规范名称、状态、关联地址数量和添加时间，并提供添加、暂停、恢复与受限删除操作。
7. 新增六项 Worker 边界集成测试，覆盖无需 DNS 验证、国际化域名规范化、重复冲突、状态切换、分配限制、删除确认、地址阻止、权限、CSRF 和审计失败回滚。

## 后续约束

1. 邮件、Provider 路线、域名配额或后台任务表进入正式迁移时，必须同步扩大域名删除前的关联检查。
2. 地址与别名管理必须只允许在 `active` 域名下建立新地址，同时保留暂停域名已有地址的身份数据。
3. 域名月度发件配额和免费额度展示在独立切片实现，不写入本批接口。
