## 本批目标

把服务端草稿正式接受为一封不可变邮件。所有可预先判断的问题必须在任何收件人收到邮件前一次性检查完毕；接受成功后，系统内地址立即得到同一封邮件，站外地址进入可追踪的异步投递流程。

## 验收条件

1. 发送时重新核对草稿所有者、精确修订号、发件地址权限、用户状态、域名状态和组织发信权限。
2. 至少有一名有效收件人；同一邮箱在收件人、抄送和密送中重复出现时只投递一次，优先保留收件人，其次抄送，最后密送。
3. 一次操作只建立一份发送操作、一封物理邮件和一个已发送条目；每名收件人仍有独立投递状态。
4. 正文、附件和最终 MIME 作为邮件自己的不可变对象写入 KV/R2，全部回读校验后才在 D1 原子提交为可见。
5. 最终 MIME 总大小不得超过 20,000,000 字节；域外发信时还要采用当前路线中可用 Provider 的更小限制。
6. 系统内地址不经过外部服务，在同一 D1 接受事务中建立投递和邮箱条目；一封邮件同时发往同一用户的多个地址时只显示一个邮箱条目，同时保留全部实际投递地址。
7. 站外收件人在接受时冻结发件域名的默认和备用 Provider 路线；没有可用路线时整次发送失败，系统内收件人也不会提前收到。
8. 客户端提供稳定发送防重键；相同输入的重放返回原发送结果，不生成重复邮件，防重键相同但输入不同则明确拒绝。
9. 用户每日发件限制按过去 24 小时内的唯一最终收件人数计算；系统初始默认值为 500，管理员以后可以调整系统默认或指定用户限额。
10. 域名月度配额按发件地址所属域名和自然月计算；默认不限制，管理员可以为每个域名设置限额。内部投递立即记账，站外投递先预留并在服务明确接受、拒绝或结果未知时转换状态。
11. 域外发信只支持 Resend 和 SMTP2GO；每个域名可以设置一条包含默认与备用服务的生效路线。
12. 外部凭据使用独立的 `CONFIG_KEY` 以 AES-GCM 加密保存到 D1；唯一系统管理员可以查看和更换明文配置，普通用户不能访问。
13. Resend 使用 24 小时幂等键；SMTP2GO 或网络结果未知时不自动重发，也不自动切换备用服务。
14. 网页可以发送当前草稿，并显示接受结果及每名收件人的等待、已提交、已送达、延迟、退信、失败或未知状态。
15. 电脑与手机浏览器均能完成发送并查看结果；迁移、权限、幂等、内部投递、配额、服务切换和未知结果具有自动化测试。

## 实现边界

### 本批包含

- 正式邮件接纳、最终 MIME、不可变正文和附件对象。
- 系统内直接投递、已发送条目和逐收件人状态。
- 用户每日限额、域名月度配额与预留记账。
- Resend、SMTP2GO 配置、域名路线、异步提交、备用切换与回调边界。
- 写信页发送操作和发送结果展示。

### 本批不包含

- 通知网关、外部邮箱转发和退信邮件自动生成。
- 定时发送、撤回、已读回执、模板和营销群发。
- 依赖真实 Provider 账号的远程最终验收；本地使用高保真适配器测试，真实账号仍是上线门槛。

## 风险控制

1. 所有确定性校验先于对象和 D1 可见提交；对象写入失败、回读不一致或 D1 失败都不能产生半封可见邮件。
2. 接受事务失败后，预先写入的不可预测对象仍只有登记意图且没有可见邮件引用，后续对象对账负责清理。
3. Provider 明确未接受时才允许安全切换备用服务；请求已发出但无法判断结果时保持“结果未知”，等待人工核对或可信回调。
4. 邮件正文、附件、服务密钥、会话令牌和完整 Provider 响应不得进入审计或运行日志。
5. Resend 和 SMTP2GO 当前公开限制均大于 Simlettra 的 20 MB 上限，因此本批有效上限仍为 20 MB；供应商规则变化时取更小值。

## 完成结果

1. 正式迁移 `0012-正式发信与域外路线.sql` 建立十六张表，覆盖 Provider 配置与版本、域名默认和备用路线、发送操作、逐收件人状态、尝试与事件、用户每日额度和域名月度额度。
2. 发送服务会在接受前完成草稿修订、发件权限、收件地址、域名路线、20 MB 大小和额度检查；同一草稿的并发发送只能有一次成功。
3. 系统内邮件通过同一 D1 接受批次建立物理邮件、已发送条目和收件条目；已发送列表显示实际发件地址，不再显示“投递地址未知”。
4. Resend 与 SMTP2GO 使用冻结路线异步提交。只有服务明确拒绝接受时才切换备用服务，网络错误、超时和无法判断的响应均保留“结果未知”。
5. Resend 回调使用 Svix 签名、时间窗口和事件编号防重；SMTP2GO 回调使用 HTTPS Basic Auth。回调只保存负载摘要和必要状态，不保存完整响应。
6. 外部服务 API Key 和回调凭据使用独立配置主密钥加密进入 D1；唯一系统管理员可以在网页查看、修改和测试配置，普通用户没有入口和服务端权限。
7. 网页已经提供草稿发送、稳定请求防重键、逐收件人状态轮询，以及 Provider、域名路线和发件额度管理。

## 供应商限制核验

核验日期为 2026-08-12：

- [Resend 发送邮件接口](https://resend.com/docs/api-reference/emails/send-email)及[附件说明](https://resend.com/docs/dashboard/emails/attachments)公开限制为 Base64 编码后 40 MB。
- [SMTP2GO 发送接口](https://developers.smtp2go.com/docs/send-an-email)及[通用 API 限制](https://developers.smtp2go.com/reference/general-api-resources)公开限制为 50 MB。
- 两者均大于 Simlettra 的 20,000,000 字节限制，因此当前单封邮件总大小仍以 Simlettra 的 20 MB 为准；以后供应商限制变小时自动采用更小值。
- [Resend Webhook 验证](https://resend.com/docs/webhooks/verify-webhooks-requests)和[SMTP2GO Webhook 设置](https://developers.smtp2go.com/docs/setup-a-webhook)作为当前回调边界的官方依据。
