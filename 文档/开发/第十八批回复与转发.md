## 本批目标

用户从当前有权读取的邮件直接建立回复、回复全部或转发草稿。草稿生成后继续使用现有的跨设备编辑、自动保存、附件和正式发送流程，不建立第二套发送通道。

## 验收条件

1. 创建相关草稿时使用邮箱条目编号重新检查个人邮箱所有权或当前组织成员资格，网页不需要知道物理邮件内部编号。
2. 回复优先使用原邮件的 `Reply-To`，没有时使用 `From`；主题只补一个标准 `Re:` 前缀。
3. 回复全部在回复目标之外加入原 `To` 与 `Cc`，统一规范化和去重，不加入原 `Bcc`。
4. 回复全部去除当前用户全部个人地址和实际选中的发件地址；组织共享地址只有在实际选为发件地址时才去除。普通成员使用个人地址回复组织邮件时，原收件人中的组织地址因此会继续保留。
5. 回复默认优先使用原邮件实际投递且当前仍有权使用的地址；不能使用组织地址时回落到用户默认个人发件地址。
6. 转发不预填收件人，主题只补一个标准 `Fwd:` 前缀，并复制原邮件的普通附件到新草稿；内嵌资源不作为独立附件复制。
7. 三种草稿都在正文中加入经过转义的来源摘要和引用内容，不把原始不可信 HTML、远程图片、脚本、样式或表单直接放进编辑器。
8. 回复和回复全部正式发送后建立明确父邮件关系，并生成标准 `In-Reply-To` 与 `References`；转发只保留来源说明，不生成关系头，也不加入原会话。
9. 来源邮件无权访问、已经永久隐藏、完整性损坏或正文及附件对象缺失时明确失败，不留下半份可见草稿。
10. 桌面和手机网页都提供回复、回复全部和转发入口，并能继续编辑、保存和发送生成的草稿。

## 实现边界

### 本批包含

- 邮箱模块向草稿模块提供经过授权的来源快照。
- 回复、回复全部与转发的默认发件地址、收件人、主题、引用正文和转发附件。
- 正式 MIME 关系头、D1 权威关系和会话归并边界。
- 邮件详情页入口及自动化测试。

### 本批不包含

- 自动转发到外部邮箱；该能力属于通知与外部转发模块。
- 用户自定义引用格式、附件选择策略或回复模板。
- 在回复中自动下载原邮件远程图片或复制内嵌资源。

## 风险控制

1. 来源访问权由服务端按邮箱条目重新检查，不能依赖网页传来的物理邮件编号、地址或正文。
2. 引用正文只使用纯文本；HTML-only 邮件通过平台 HTML 解析器提取可见文字后再进行 HTML 转义。
3. 转发附件从已经登记并完整校验的邮件对象复制为草稿自己的新对象，不跨邮件共享对象身份。
4. 创建任一步骤失败时不建立草稿记录；已经写入但尚未激活的对象由现有对象对账流程清理。
5. 用户仍可编辑自动生成的收件人，但不会因此抹掉回复来源；转发始终不自动加入原会话。

## 完成结果

1. 网页创建相关草稿只提交邮箱条目编号和操作类型；服务端重新检查个人邮箱所有权、当前组织成员关系、邮件完整性及垃圾箱期限，再读取来源快照。
2. 回复优先使用 `Reply-To`，回复全部加入原 `To` 与 `Cc` 并去除用户个人地址；普通成员不能使用组织地址时，默认个人发件地址与原组织收件地址会同时保留。
3. 回复、回复全部与转发均生成富文本草稿，引用部分只从纯文本或经过两轮 `HTMLRewriter` 处理的可见文本生成，并进行 HTML 转义，不复制脚本、样式、表单或远程图片。
4. 转发复制普通附件为草稿自己的不可变对象，不复制内嵌资源，不预填收件人，也不建立会话关系。
5. 回复和回复全部正式发送时同时保存 `internal_reply`、`in_reply_to` 与有序 `reference` 关系，并生成标准 `In-Reply-To` 和完整 `References` 邮件头。
6. 邮件详情页提供图标化的回复、回复全部和转发入口；生成的草稿继续使用现有自动保存、附件、正式发送和跨设备编辑流程。
