## 本批目标

建立可跨设备继续编辑的服务端草稿：用户能够选择有权使用的发件地址，填写收件人、抄送、密送、主题和富文本或纯文本正文，上传附件，并在多设备并发编辑时避免旧内容静默覆盖新内容。

## 验收条件

1. 草稿始终属于实际编辑者本人；选择组织地址不会让其他组织成员看到草稿。
2. 用户可以新建、列出、打开、丢弃和恢复自己的草稿，不能读取或修改他人的草稿。
3. 发件地址候选包含用户当前可用的个人地址，以及当前明确有权使用的组织地址；权限失效时保留草稿内容但标出该地址不可用于发送。
4. 草稿保存收件人、抄送、密送、主题、富文本或纯文本正文和附件，并能在另一浏览器会话继续编辑。
5. 正文和附件保存到当前 KV/R2；D1 统一登记大小、SHA-256、对象代次和当前状态，不把大正文写入 D1。
6. 自动保存携带稳定变更编号、预期修订号和输入摘要；相同请求重放返回同一结果。
7. 两台设备基于同一修订保存不同内容时，第一份成为新修订，后一份成为可见的冲突副本，不覆盖第一份。
8. 附件只有在对象完整写入并通过大小与哈希校验后才能加入当前修订；文件名始终按不可信输入处理。
9. 编辑期间定期自动保存并显示“未保存、保存中、已保存、保存失败或已生成冲突副本”。
10. 电脑与手机浏览器均可完成写信、切换正文格式、管理收件人和附件、丢弃与恢复草稿。
11. 迁移约束、对象完整性、幂等重放、修订冲突、越权访问和 HTTP 契约具有自动化测试。

## 实现边界

### 本批包含

- 草稿权威状态、当前内容、收件人、附件和变更防重正式迁移。
- 草稿正文与附件的 KV/R2 对象写入、校验、读取和生命周期登记。
- 发件地址候选、草稿列表、详情、自动保存、附件上传与删除、垃圾箱和恢复接口。
- 简体中文电脑与手机写信界面。

### 本批不包含

- 正式发送、站内投递、域外 Provider、投递状态和退信处理。
- 定时发送、撤回、模板、营销群发和协作编辑草稿。
- 完整逐次编辑历史；只保留当前草稿与必要的冲突副本。

## 风险控制

1. 单封邮件正文和附件合计最多 20,000,000 字节；以后正式发送时仍按最终 MIME 与 Provider 的更小上限再次检查。
2. 对象先使用不可预测的新键写入并回读校验，再由 D1 原子批次切换当前修订；D1 失败留下的对象由后续对账识别，不能成为可见草稿内容。
3. 富文本按不可信 HTML 保存，编辑和显示时均执行白名单清理，不能执行脚本或加载未授权远程内容。
4. 每次读取、保存、上传和删除都在服务端检查草稿所有者，不依赖前端隐藏。

1. 正式迁移 `0011-草稿与写信编辑.sql` 已建立五张草稿业务表，并扩展统一对象登记以支持草稿正文和附件；正式工程现有 47 张业务表。
2. 迁移已经分别在全新高保真 D1 和带既有邮件、收信路由及防重关系的本地 D1 上执行；历史对象及三层收信关系数量保持不变，`PRAGMA foreign_key_check` 无违规。
3. 服务端测试覆盖草稿所有权、CSRF、发件地址授权、自动保存重放、过期修订冲突副本、附件完整写入、附件上传重放、下载、移除、丢弃和恢复。
4. 前端对保存期间的继续编辑使用本地编辑编号保护，较慢的旧响应不会覆盖用户随后输入的新内容；离开草稿前会完成未保存内容，退出登录会立即清除草稿内存状态。
5. `pnpm check` 已通过：30 个测试文件、135 项测试全部成功，格式、ESLint、Cloudflare 类型生成、严格 TypeScript 检查和单 Worker 安全生产构建均通过。
6. 本地应用内浏览器已完成桌面和 `390 × 844` 手机视口验收：新建富文本草稿、收件人与抄送、自动保存、附件上传、刷新后恢复、丢弃与恢复均正常；手机视口无横向溢出，浏览器控制台无警告或错误。
