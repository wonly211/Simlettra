## 本批目标

完成一个可直接使用的邮箱搜索闭环：用户可以在自己的个人邮箱和当前加入的组织邮箱中，组合使用正文关键词、主题、发件人、收件人、实际投递地址、日期、附件和个人状态筛选邮件，并按时间、未读、星标或附件优先排序。

正文搜索继续遵守已经接受的中文双字词元方案。搜索索引是可以从 KV 或 R2 正文对象重建的派生数据，不参与判断邮件是否存在，也不能代替个人邮箱所有权或当前组织成员资格检查。

## 验收条件

1. 正文中的两个及以上连续汉字可以命中，单个汉字正文搜索会得到清楚的输入提示。
2. 拉丁文字、数字和中英文混合正文使用确定性的规范化与词元规则。
3. 主题、发件人、收件人、实际投递地址、日期、附件、已读、星标和归档条件可以组合使用。
4. 结果可以按最新、最早、未读、星标或有附件优先排序，并继续使用稳定游标分页。
5. 个人邮件只能由其所有者搜索；组织邮件只对当前成员可见，退出组织后不能通过旧索引发现邮件。
6. 新邮件可见事务同时登记搜索状态和索引任务；搜索失败不阻塞读信，但正文搜索会明确显示索引正在建立或需要处理。
7. 索引任务可以从当前活动正文对象重建搜索分块，并能在重复执行或中断重试后得到一致结果。
8. 物理邮件永久删除时同步删除 FTS5 数据、搜索分块和搜索状态，删除步骤不再标记为跳过。
9. 网页在电脑与手机宽度下提供正文搜索、组合条件、排序、清除条件和索引状态提示。
10. 迁移、词元、组合筛选、越权、重建、删除和 HTTP 契约具有自动化测试，并通过 `pnpm check`。

## 实现边界

### 本批包含

- 内容空且支持普通删除的 D1 FTS5 索引。
- 每封物理邮件的派生索引状态和正文分块元数据。
- 中文相邻双字词元、拉丁文字和数字词元。
- 邮箱范围词元，以及结果返回前的正式服务端授权。
- 新邮件索引任务、遗漏任务补建和可重复重建。
- 邮箱列表中的组合搜索、排序和网页操作。
- 永久删除链路中的搜索数据清理。

### 本批不包含

- 单个汉字的正文全文搜索。
- 模糊拼写纠正、同义词、相关度排序或外部搜索服务。
- 会话归并。
- 备份恢复界面；本批只提供恢复流程以后可以调用的可重建索引能力。
- 真实 Cloudflare D1 的远程容量和性能复核；该项仍是发布前门槛。

## 技术核验

2026-08-12 复核结果：Cloudflare D1 官方文档继续列明支持 FTS5；SQLite 官方文档说明从 SQLite `3.43.0` 起，`content=''` 与 `contentless_delete=1` 组合可以只保存索引并支持普通 `DELETE`。本批仍需用当前项目的真实 Workers Vitest pool 验证该选项，不能只依据文档宣布可用。

- Cloudflare D1 SQL 与 FTS5：<https://developers.cloudflare.com/d1/sql-api/sql-statements/>
- SQLite FTS5 内容空删除表：<https://www.sqlite.org/fts5.html#contentless_delete_tables>

## 风险控制

1. FTS5 命中只产生候选物理邮件，最终查询必须重新关联当前邮箱条目、用户归属和组织成员关系。
2. 正文原文继续只保存在 KV 或 R2；D1 普通表不复制正文或完整词元文本。
3. 索引状态不是邮件存在性的权威依据，索引故障不能删除、隐藏或损坏已可读邮件。
4. 索引任务只读取当前活动且通过大小与 SHA-256 校验的正文对象。
5. 正文索引不完整时不返回部分正文命中；普通列表和不依赖正文的组合筛选仍可使用。
6. 查询表达式只由服务端生成并通过参数绑定交给 FTS5，用户输入不能拼接为 SQL。

## 剩余风险

1. 真实 Cloudflare D1 上的 FTS5 容量、构建时间和 100,000 封邮件规模仍需远程复核。
2. 本地 KV/R2 完整恢复已经调用搜索重建并通过收口；真实 Cloudflare Free 空白资源恢复仍需复核容量和耗时。
3. 以后新增邮箱条目引用已存在物理邮件时，必须重新安排该邮件索引，使哈希邮箱范围词元包含新范围。最终权限检查已经阻止旧范围造成越权泄漏。
