## 本批目标

让 Cloudflare Email Routing 交给 Worker 的邮件先可靠保存原始 MIME，再由 Queue 解析并保存正文和附件。只有原始内容、必要衍生对象、投递关系和邮箱条目全部完整时，邮件才进入个人或组织邮箱；中断和重复投递不能产生重复邮件或半封可见邮件。

## 验收条件

1. `email` 入口只接受已初始化系统中当前启用域名、活动地址占用和当前归属对应的个人或组织地址；暂停域名、禁用用户、删除中的组织、已退休或已释放地址立即拒收。
2. 原始邮件总大小最多为 `20,000,000` 字节，Cloudflare 实际限制更小时采用更小值；超限邮件在建立对象和数据库记录前拒收。
3. 接收入口先建立稳定收信操作、冻结实际投递路由和原始对象写入意图，再把原始 MIME 写入当前 KV 或 R2；对象键不包含邮箱地址、主题或附件名。
4. 没有来源事件编号时，使用原始字节摘要、信封发件人和一小时窗口生成物理邮件有界防重键；实际投递地址使用同一操作下的独立冻结路由防重。窗口内同一原始邮件的多地址事件推进同一操作，窗口外相同内容可以成为新邮件。
5. Queue 消息只包含 D1 后台任务编号和输入版本；Queue 重复、漏唤醒或 Worker 中断后仍以 D1 状态继续处理。
6. Queue consumer 使用锁定的 `postal-mime 2.7.6` 解析 `ArrayBuffer`，限制邮件头大小、嵌套深度、附件数量和衍生对象总大小；解析失败保留原始 MIME，普通邮箱不显示半封邮件。
7. 原始 MIME、纯文本正文、HTML 正文、附件和内嵌资源逐对象登记，保存大小与 SHA-256；R2 写后校验即可继续，KV 必须经过后续任务再次读取校验。
8. 最终 D1 原子批次同时建立物理邮件、邮件头快照、实际投递、个人或组织邮箱条目、对象活动代数、完整性状态和最终防重关系，并把收信操作与冻结路由改为完成。
9. 个人邮件只建立一个所属用户邮箱条目；组织邮件只建立一个组织邮箱条目，不按成员复制正文或邮箱条目。
10. 任一对象写入、解析或最终事务失败时，邮件保持不可见；可恢复失败由同一任务重试，确定性失败进入需要处理状态，错误记录和日志不包含正文或附件内容。
11. 正式迁移、对象契约、路由授权、大小限制、防重、个人与组织投递、Queue 重放、解析失败和最终事务回滚具有自动化测试。

## 本批不包含

1. 全域收信、未分配地址认领、按发件人或正文关键词拒收，以及单独暂停某个邮箱地址的管理界面。
2. 收件箱列表、邮件详情、已读、星标、归档、垃圾邮件、垃圾箱、搜索和会话归并界面。
3. 远程图片放行、附件下载或预览，以及 HTML 邮件安全渲染。
4. 发信、回复、转发、外部通知和外部邮箱转发。
5. 七天组织删除期结束后的邮件永久清理、对象库存全量对账和备份恢复。
6. 在真实 Workers Free 环境对接近 20 MB 邮件的 CPU、内存、Queue 并发和 KV 多地区一致性复核；该项仍是首发上线门槛。

## 实现结果

1. 正式迁移 `0007-邮件接收与完整性提交.sql` 建立物理邮件、邮件头地址、实际投递、邮箱条目、对象登记、完整性、收信操作、冻结路由和防重关系，共十张业务表。
2. Worker `email` 入口会先检查系统、存储方式、域名、地址占用和当前归属，再保存原始 MIME；暂停域名、禁用用户、无效地址和超过 `20,000,000` 字节的邮件不会进入对象存储。
3. 原始 MIME 保存成功后才建立 D1 权威解析任务并投递 Queue；Queue 消息只携带任务编号和输入版本，发送失败可由定时任务重新发现。
4. `postal-mime 2.7.6` 负责解析原始字节，正文、附件和内嵌资源分别登记大小与 SHA-256。R2 写入后立即校验，KV 通过后续任务再次读取校验。
5. 邮件只有在全部必要对象校验完成后，才通过一个 D1 原子批次建立可见邮箱条目。事务失败不会留下半封可见邮件，重试继续处理同一收信操作。
6. 没有来源事件编号时按一小时窗口生成有界指纹；窗口内重复投递复用同一收信操作。组织来信只建立一个组织邮箱条目，不按成员复制内容。

1. `pnpm check` 全部通过，包括格式、ESLint、Cloudflare 类型生成、严格 TypeScript、21 个测试文件中的 100 项测试和安全生产构建。
2. 高保真 Workers 测试覆盖 R2 与 KV 两种对象存储、个人与组织投递、重复投递、防护性拒收、KV 二次校验、最终事务故障回滚和重试。
3. `pnpm db:migrate:local` 已成功应用 `0007`；本地 D1 共有 34 张业务表，`PRAGMA foreign_key_check` 无违规。
4. 本批没有新增可见网页，因此不重复进行浏览器截图验收；收件箱列表和邮件详情属于下一纵向切片。
