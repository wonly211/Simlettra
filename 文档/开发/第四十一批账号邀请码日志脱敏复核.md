# 第四十一批账号邀请码日志脱敏复核

## 文档状态

- 状态：本地完成
- 完成日期：2026-08-14
- 对应需求：`3.02`、`9.09`、`9.13`
- 对应验收：验收-03、验收-19

## 目标

把账号邀请码“不进入网址、错误响应、审计详情和应用日志”的安全边界转成可重复执行的发布前证据，不改变已经确认的邀请码产品行为。

## 实现与检查

1. 账号邀请码继续只通过固定路径的 `POST` JSON 请求正文提交，不建立包含邀请码的注册链接。
2. 邀请码模块和 HTTP 边界没有 `console` 或应用日志调用；未处理异常由 Hono 统一转换为固定的 `internal_error`，不回显异常对象或请求正文。
3. `account-registration-http.test.ts` 使用一枚真实邀请码触发 D1 审计失败，分别检查带连字符和去除连字符的形式都不会出现在失败响应、控制台各级输出或审计字段中。
4. 账号邀请码 HTTP 回归加入 `test:security`，安全聚合门槛由 7 个文件、45 项测试扩展为 8 个文件、49 项测试。

## 验证结果

- 邀请码 HTTP 定向回归：1 个文件、4 项测试通过。
- 发布前安全聚合：8 个文件、49 项测试通过。
- 测试文件通过 Prettier、ESLint 和测试 TypeScript 检查。
- 生产安全构建通过，产物不包含 `.dev.vars` 或当前本地配置中的已知密钥内容。
- 全量复核的一次并行运行中，Cloudflare Vitest pool 因瞬时 `bad port` 未能启动 `mail-search-migration.test.ts`；其余 55 个文件、229 项测试通过，漏跑文件随后单独以 1 个文件、2 项测试通过。本次没有测试断言失败，但不把组合执行记作一次完整命令全绿。

## 仍需远程验证

本地检查能够证明当前应用代码不会主动记录或回显邀请码，但不能替代真实 Cloudflare Worker、Queue、Cron、Provider 和第三方控制台的日志总审计。真实部署日志仍属于发布-22 阻断项。
