# 第四十九批 Git 仓库初始化与忽略审计

## 状态

新项目 Git 仓库和忽略边界已经建立；首次提交、标签与远程推送均未执行。

## 目标

为新项目建立独立、干净的版本控制边界，确保将来形成正式版本时不会把本地密钥、运行数据、依赖、构建制品或临时文件误纳入提交。同时保持用户对首次提交、远程仓库和发布动作的决定权。

## 实现结果

1. 在 `E:\SynologyDrive\github\Simlettra` 初始化全新的 `main` Git 仓库，没有继承旧项目历史。
2. 仓库级设置 `core.quotepath=false`，Git 状态可以直接显示简体中文路径；没有改动用户的全局 Git 配置。
3. 根级 `.gitignore` 继续排除 `.dev.vars*` 并保留 `.dev.vars.example`，同时补充 pnpm 缓存、项目临时目录、开发服务器日志、TypeScript 增量文件、生成的 Cloudflare 类型和源码快照制品。
4. 验证原型中的依赖、Wrangler 数据、`.data-*`、`.debug-*`、`.generated` 和日志保持忽略；原型自身忽略的可再生成结果也不会进入源码快照。
5. Git 可纳管文件与源码快照文件集合进行双向对照，修正了 6 个只进入快照、但已被原型 `.gitignore` 排除的生成结果文件。

## 验证结果

- 当前分支为 `main`，状态为“尚无提交”；
- 忽略规则审计没有发现 `.dev.vars`、依赖、构建目录、日志、临时数据库、开发快照或生成类型被纳入可提交集合；
- Git 可纳管文件和开发源码快照的相对路径集合完全一致；
- 没有执行 `git add`、`git commit`、`git tag`、`git remote add` 或 `git push`；
- 沙箱账号触发 Git 所有者保护时只对检查命令使用临时 `safe.directory`，没有写入全局例外。

## 当前边界

1. 空白仓库本身不是不可变版本；没有首次提交就无法用提交编号定位当前源码。
2. 当前没有上一正式版本，不能完成正式回退来源验证。
3. [发布-17](../发布/首发发布门槛.md)继续保持开放，直到用户明确批准建立正式提交或采用其他不可变版本标识。
