# 第四十二批网页控件可访问性自检

## 文档状态

- 状态：本地结构检查完成
- 完成日期：2026-08-14
- 对应需求：`12.07`
- 对应验收：验收-25

## 目标

把“主要流程支持键盘且控件名称清楚”中能够由项目结构稳定判断的部分转成可重复自检，同时把必须由真实浏览器和真人操作验证的部分继续保留为发布门槛。

## 实现

新增 `tools/网页控件可访问性自检.mjs`，直接使用项目已有的 `vue/compiler-sfc` 解析 `SimlettraApp.vue`，不使用正则代替模板结构，也不新增依赖。自检覆盖：

1. 按钮和链接具有静态文字、插值或 `aria-label`、`aria-labelledby` 等可推导名称。
2. 输入框、选择框和文本区域由包裹标签、`for` 关系或 ARIA 属性命名。
3. 点击操作使用按钮、链接或其他原生交互元素，不给普通容器直接绑定点击事件。
4. 所有按钮明确设置 `type`，避免表单中的隐式提交。
5. 不使用会重排自然键盘顺序的正数 `tabindex`。
6. 静态 `aria-labelledby` 指向实际存在的元素，新窗口链接同时设置 `rel`。

该工具以 `pnpm test:accessibility` 独立执行，并已进入统一 `pnpm check`。

## 验证结果

- Vue 模板共检查 1,723 个元素、338 个原生交互控件，未发现违规项。
- 当前已登录收件箱的运行时可访问结构有 39 个可见原生控件，没有空名称控件。
- 源码没有非原生点击目标、正数 `tabindex` 或缺少 `type` 的按钮。
- 显式移除默认轮廓的搜索、草稿和通用表单输入均设置了可见的焦点边框或阴影；其他按钮没有全局移除浏览器焦点轮廓。
- 自检工具通过 Node 语法检查和 Prettier。

## 证据边界

当前应用内浏览器能够读取运行时可访问结构，但其控制层不能可靠触发 Tab 默认焦点移动或原生按钮的 Enter 默认动作。因此，本批只确认模板结构和当前可见控件名称，不声称真实键盘流程已经通过。

发布前仍须在目标 Chrome、Edge、Firefox 和 Safari 中由真实键盘完成登录、区域切换、搜索、读信、写信、回复、设置、确认与取消流程，并检查焦点顺序、焦点可见性和状态反馈。
