# 第四十八批可校验源码快照

## 状态

本地工具、开发版制品、密钥扫描和完整性自检已经完成；正式发布来源仍待建立。

## 目标

在当前工作目录没有 Git 元数据的情况下，先建立一种不会泄露本地密钥、能够明确文件范围并可验证是否被修改的开发源码快照。它用于保留当前开发状态和验证发布打包路径，不替代正式提交、标签、真实环境验收或正式发布。

## 实现结果

1. `tools/生成源码快照.mjs` 只收录显式允许的根级文件和目录，包括正式源码、迁移、测试、配置模板、简体中文文档、验证原型源码和项目级 Skill。
2. 递归收集会跳过隐藏目录，并明确排除依赖、构建产物、覆盖率、日志、临时数据库、TypeScript 增量文件和生成的大邮件样本。
3. `.dev.vars` 永不进入快照；工具还会读取其中只存在于本机的值，逐文件检查是否泄漏。示例配置和测试配置中已经公开的固定夹具不误判为本地秘密。
4. 每个文件记录相对路径、字节数和 SHA-256；源码集合另有稳定摘要，清单同时放在 ZIP 内并作为外部文件写出。
5. ZIP 使用固定时间和稳定路径顺序，同一输入在内存中生成两次并要求字节完全一致；随后立即解压，逐项核对路径、字节数、文件摘要和清单内容。
6. 外部 `.sha256` 保存整个 ZIP 的校验值，默认制品目录为已被 `.gitignore` 排除的 `发布制品/`。

## 验证结果

- 新工具通过 Prettier 和 Node 语法检查；
- 首轮发现验证原型中的 Miniflare 数据、调试数据库和接近 20 MB 的生成邮件被误纳入，工具随后统一排除递归隐藏目录；
- 最终开发快照通过两次生成一致性、内存解压逐项校验、本地密钥值扫描和 PowerShell 外部 SHA-256 复核；
- 制品包括源码 ZIP、外部源码清单和 ZIP SHA-256，版本为 `0.1.0-dev.0`；
- 没有创建 Git 仓库、提交、标签，也没有发布或上传任何制品。

## 当前边界

1. 开发快照只证明当前允许文件集合的完整性，不说明代码已经通过真实 Cloudflare Free、Provider、浏览器矩阵、安全总检查或真人验收。
2. 当前没有上一正式版本可供重新取得，因此[发布-17](../发布/首发发布门槛.md)仍未关闭。
3. 正式发布时必须在最终源码状态重新生成快照和摘要；本批开发制品不能直接改名为正式版。
