## 为什么推荐这一组方案

1. 11 组本地自动验证全部通过，已经覆盖查询一致性、权限范围、键集分页、FTS5、批处理、失败迁移和恢复。
2. Drizzle 保留了接近 SQL 的透明度，同时给普通表提供 TypeScript 类型检查；本地代表性 Worker gzip 只有 38.52 KiB。
3. Prisma 可以运行，但相同代表性 Worker gzip 为 1,242.30 KiB，且 D1 adapter 自身仍明确标记为 Preview。
4. Wrangler 迁移账本是 Cloudflare 平台的原生机制，生成迁移和手写迁移都能进入同一顺序，失败时不会留下半个迁移。
5. D1 物理导出当前无法处理 FTS5；搜索索引本来就是可重建数据，因此备份权威表比临时删除生产搜索表更可靠。
6. Time Travel 与本地备份解决的是不同问题：一个适合短期快速回到过去，一个适合长期独立保存和跨库恢复。

## 需要知道的限制

1. 采用 Drizzle 后仍然需要维护少量原生 SQL，不会追求“所有数据库操作都由 ORM 包办”。
2. Drizzle 生成的迁移必须审查，不能直接自动推到生产。
3. 逻辑备份工具需要由项目自行实现，100,000 封邮件的流式备份和断点续传还要单独验证。
4. 恢复完成后全文搜索需要重建，重建期间页面必须明确显示状态。
5. 真实 D1 Time Travel、远程迁移和多地区 Sessions 尚未验证，仍是发布前门槛。
