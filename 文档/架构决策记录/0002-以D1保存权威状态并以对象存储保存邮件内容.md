# 0002 以 D1 保存权威状态并以对象存储保存邮件内容

## 状态

已接受

- 接受日期：2026-08-10

## 背景

邮件需要组合搜索、权限检查、组织共享、个人状态、幂等任务、备份和恢复。正文、原始邮件和附件可能接近 20 MB，超过 D1 单行和单值限制。系统同时需要支持 KV 与 R2。

## 决定

1. D1 是系统唯一的权威状态来源，保存用户、权限、地址、组织、邮件元数据、投递、邮箱状态、任务、审计和可重建搜索索引。
2. KV 或 R2 只保存不可变对象：原始 MIME、正文和附件。
3. 业务代码通过统一对象存储接口访问 KV/R2，不直接判断绑定类型。
4. 对象写入完成不代表邮件可见；只有 D1 状态完成并确认必要对象存在后，邮件才进入可见状态。
5. 搜索索引属于派生数据，备份恢复后允许重建。

## 备选方案

1. 全部保存到 D1：查询简单，但无法可靠承载大正文和附件。
2. 元数据也保存到 KV/R2：对象容量足够，但权限查询、唯一约束、组合搜索和事务难以维护。
3. KV 与 R2 分别实现业务逻辑：能针对平台优化，但会形成两套行为和迁移风险。

## 后果

### 正面

1. 权限、唯一性和状态变化集中在 D1。
2. 大对象不占用 D1 单行空间。
3. 两种部署模式保持相同行为。
4. 原始 MIME 能支持导出、迁移对账和重新解析。

### 负面

1. D1 与对象存储之间没有跨资源事务，必须使用状态机和补偿任务。
2. 完整备份需要同时处理两类资源。
3. KV 最终一致，需要用不可变键和 D1 可见状态规避短暂读取差异。

## 验证方式

1. 对每个收信、发信、删除和恢复阶段注入失败，确认不会出现半封可见邮件。
2. 同一操作重复执行不会生成额外邮件或对象引用。
3. D1+KV 与 D1+R2 通过相同的存储契约测试。
4. 完整恢复后可以重新生成搜索索引并通过数量和哈希对账。
