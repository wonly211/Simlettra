# 0004 以 R2 作为默认对象存储

## 状态

已接受

- 接受日期：2026-08-10

## 背景

需求要求同时支持 `D1 + KV` 和 `D1 + R2`。两种方式都能保存邮件对象，但当前免费额度、写入次数、一致性和总容量差异明显。新用户需要一个默认推荐，避免在不了解限制时作出不合适选择。

## 决定

1. 新部署向导默认推荐 `D1 + R2`。
2. `D1 + KV` 作为个人、低写入或无法启用 R2 时的兼容模式。
3. 两种模式提供相同产品功能和对象存储契约，不形成高级版与简化版。
4. 管理界面显示当前模式的使用量、主要限制和接近额度时的提醒。

## 备选方案

1. 默认 KV：资源概念较少，但每日写入、总容量和最终一致性更不适合邮件。
2. 不提供默认推荐：表面中立，但会把技术判断转嫁给非程序员部署者。
3. 只支持 R2：实现最简单，但违反已经接受的两种部署方式需求。

## 后果

### 正面

1. 大多数用户获得更适合邮件附件和长期存储的默认选择。
2. 强一致性减少新对象短暂不可见的情况。
3. KV 兼容模式仍保留，不改变需求范围。

### 负面

1. R2 可能需要用户先在 Cloudflare 账号中开通相关服务。
2. 文档和测试仍需完整覆盖两种模式。
3. 不能因默认 R2 而忽视 KV 的额度和一致性测试。

## 验证方式

1. 初始化向导清楚说明推荐原因，不使用误导性的套餐语言。
2. 两种模式通过相同功能和恢复测试。
3. KV 模式达到限制时给出可理解提示，不静默丢失邮件。
