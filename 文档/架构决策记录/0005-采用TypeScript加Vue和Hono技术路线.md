# 0005 采用 TypeScript、Vue 和 Hono 技术路线

## 状态

已接受

- 接受日期：2026-08-10

## 背景

新项目是完全重构，可以延续旧系统的技术家族，也可以更换前端或全栈框架。更换框架只有在能明显改善可靠性、维护性或用户体验时才有价值，不能为了“看起来更新”增加学习和迁移成本。

## 决定

1. 全项目使用 TypeScript 编写生产代码和测试。
2. 网页使用 Vue 3 单页应用重写，使用 Vite 和 Cloudflare 官方 Vite 插件进行开发与构建。
3. Hono 只负责 Worker 的 HTTP 接口和 HTTP 中间件，并按业务模块组合路由；不承载业务核心。
4. `email`、`queue` 和 `scheduled` 使用 Cloudflare Worker 原生入口，并调用与 HTTP 层相同的应用服务。
5. D1 使用版本化 SQL 迁移。是否使用 Drizzle 等数据库工具，等待数据模型和查询原型验证后另行决定。
6. 使用一个根级包管理和统一命令，最终生成一个 Worker 部署产物。

## 备选方案

1. React：生态成熟，但对当前产品没有足以抵消迁移成本的明显收益。
2. Nuxt 或 SvelteKit：全栈整合方便，但邮件、队列和定时入口更受框架生命周期约束。
3. 继续 JavaScript：初期代码少，但地址、权限、状态和网关契约更容易在运行时才发现错误。
4. 不使用 Hono：依赖更少，但需要自行维护路由、中间件和错误处理基础能力。

## 后果

### 正面

1. 旧系统的 Vue 经验和部分品牌资源可以选择性复用。
2. TypeScript 能统一网页、Worker、网关和测试契约。
3. Hono 为 HTTP 层提供轻量路由能力，又不会约束邮件、队列和定时任务入口。

### 负面

1. 旧 JavaScript 代码不能直接复制，需要明确类型后重写。
2. 必须控制组件库和工具依赖，避免重新形成庞大前端包。
3. 数据库工具尚未确定，需要在数据模型和查询原型后再作选择。

## 验证方式

1. 验证性骨架能够通过 Cloudflare 官方 Vite 插件在本地同时运行网页、接口、收信、队列和定时入口。
2. 类型检查覆盖业务模块、网关接口和数据库映射。
3. 生产构建只输出一个 Worker 部署单元。
4. 关键网页流程在电脑和手机尺寸通过浏览器测试。
