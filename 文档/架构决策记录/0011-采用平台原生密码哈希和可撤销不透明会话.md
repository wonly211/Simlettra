# 0011 采用平台原生密码哈希和可撤销不透明会话

## 背景

需求 `3.03` 至 `3.07` 要求使用主邮箱地址和密码登录、支持改密与会话管理，并提供普通用户和管理员恢复流程；需求 `9.10`、`9.11` 和 `9.13` 要求使用成熟慢速密码哈希、可撤销且有有效期的会话令牌，以及登录限速和异常告警。

Cloudflare Workers 原生 Web Crypto 支持 PBKDF2，但不原生提供 Argon2id。符合 OWASP 最低参数的 Argon2id 可以通过第三方 Wasm 或纯 TypeScript 实现运行，不过两个候选分别存在维护停滞、相对性能劣势和具体实现未纳入既有审计的问题。认证记录会长期存在，依赖一旦选定，迁移成本高于普通业务库。

2026-08-10 的本地验证完成 9 组自动场景。PBKDF2 900,000 次的本地第 95 百分位约 284 毫秒；Wasm Argon2id 约 25 毫秒；纯 TypeScript Argon2id 约 128 毫秒。全部会话安全场景通过。详细证据见[密码与会话验证结果](../验证/密码与会话验证结果.md)。

## 决定

采用以下方案：

1. 首发密码算法使用 Workers Web Crypto PBKDF2-HMAC-SHA-256，默认 900,000 次迭代、16 字节随机盐和 32 字节派生结果；不得低于 600,000 次。
2. 密码记录保存格式版本、算法、迭代次数、盐和结果。验证旧参数成功后，可以在同一登录流程中重新哈希并升级记录。
3. 首发不使用 pepper，也不复用 `init_key` 充当 pepper。以后增加 pepper 必须建立新决策并同时解决密钥备份、轮换和丢失恢复。
4. 密码最短 15 个字符、最长 128 个 Unicode 字符；允许空格，不要求字符种类组合，不执行无理由的定期强制改密。
5. 创建和修改密码时使用本地版本化拦截表检查常见、已泄露及与当前账号明显相关的密码；默认不把密码或密码哈希片段发送给外部服务。
6. 登录不存在的账号时使用固定虚拟密码记录执行同成本哈希；账号不存在、密码错误、禁用和待注销均返回相同的对外错误描述。
7. 会话令牌使用 Web Crypto 生成 32 个随机字节。浏览器持有原始不透明令牌，D1 只保存其 SHA-256 摘要和会话元数据。
8. 浏览器会话使用名为 `__Host-simlettra_session` 的 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/` Cookie；不把会话令牌放入 URL、日志或 `localStorage`。
9. 修改状态的请求同时验证同源和与会话绑定的独立 CSRF 令牌。跨源、缺少令牌和令牌错误均拒绝。
10. 会话采用 7 天空闲有效期和 30 天绝对有效期；首发不提供“保持登录”选项。最近活动时间最多每小时写回一次，减少 D1 写入。
11. 用户可以列出并撤销自己的单个会话。用户改密时可选择保留当前会话并撤销其他会话；禁用、待注销和管理员重置始终撤销全部会话。
12. 管理员重置普通用户密码时产生 24 小时有效的临时密码；用户首次登录只能先设置自己的新密码。管理员使用 `init_key` 恢复时直接设置新密码并撤销全部管理员会话，`init_key` 不换取普通长期会话。
13. 登录失败同时按账号和来源限速。同一账号 15 分钟内 5 次失败后，从 30 秒开始指数延迟，最长 15 分钟；同一来源 15 分钟内最多 20 次失败。成功登录清理对应失败状态。
14. 发布前必须在真实 Cloudflare Worker 复核 PBKDF2 的 CPU、墙钟、冷启动和并发结果。若 900,000 次不能稳定运行，必须通过新证据和新决策调整，不能在部署时静默降低安全参数。

## 备选方案

1. 采用 `argon2-wasm-edge`：本地最快且具备内存困难属性，但 npm 包自 2024-04-02 后未更新，核心认证长期依赖风险过高，当前不采用。
2. 采用 `@noble/hashes` Argon2id：项目维护活跃，但项目自身说明纯 JavaScript Argon2 约慢五倍，且既有独立审计不包含 Argon2，当前不采用。
3. 采用 scrypt：OWASP 推荐参数约需 128 MiB，几乎占满 Worker 内存上限，不采用。
4. PBKDF2 使用 600,000 次：满足明确基线且本地更快，但 900,000 次仍在约 0.3 秒范围内，可以增加离线破解成本，保留为远程环境不通过时需要重新决策的下限候选。
5. PBKDF2 使用 1,200,000 次：本地仍低于 0.4 秒，但高成本更容易放大恶意登录造成的 CPU 消耗，当前不采用。
6. 使用长期可读会话令牌直接作为 D1 主键：查询简单，但数据库泄露即可直接接管会话，不采用。
7. 只依靠 `SameSite` 防止跨站请求：不能覆盖全部浏览器和同站子域边界，不采用。
8. 首发增加“保持登录”开关和多套会话期限：增加产品和测试分支，当前没有必要，不采用。
9. 使用 pepper：可以降低数据库单独泄露的风险，但部署密钥丢失会让所有密码记录无法验证，且增加自行部署的备份恢复负担，首发不采用。

## 后果

### 正面

1. 核心密码验证只依赖 Cloudflare 平台能力，不依赖维护状态不确定的密码学运行时包。
2. 用户正常登录的本地测量约 0.28 秒，能够在安全成本和交互体验之间取得平衡。
3. 密码记录版本化后，可以逐个用户升级参数或迁移到未来的原生 Argon2id，而不需要保存明文密码。
4. D1 泄露不会直接得到可用会话令牌；会话可以逐个或批量撤销。
5. 禁用、待注销、改密和恢复流程对现有会话的影响明确。
6. 同源、CSRF、双维度限速和虚拟哈希形成分层防护，不依赖前端隐藏。

### 负面

1. PBKDF2 不具备 Argon2id 的内存困难属性，抵抗专用破解硬件的能力较弱。
2. 每次真实或虚拟登录都需要执行高成本哈希，恶意请求会消耗 Worker CPU，因此限速不能推迟到后续版本。
3. 会话验证需要读取权威状态；最近活动、会话列表和撤销会增加 D1 读写。
4. 7 天未活动后需要重新登录，部分低频用户会感受到额外操作。
5. 管理员重置后的强制改密增加一个受限登录状态和相应页面。
6. 不使用 pepper 意味着数据库副本泄露后，安全性主要依赖用户密码强度和 PBKDF2 成本。
7. 真实 Cloudflare 环境未完成前，不能承诺 Free 套餐可以稳定执行推荐参数。

## 验证方式

1. 对 PBKDF2 600,000、900,000 和 1,200,000 次分别完成预热和多轮测量。
2. 相同密码重复创建记录必须得到不同盐和结果；正确密码通过，错误、损坏和未知版本安全失败。
3. 不存在账号与错误密码执行相同成本，错误描述相同且耗时没有明显数量级差异。
4. 会话令牌具有 256 位随机性，D1 只保存摘要，列表接口不返回令牌或摘要。
5. 单个撤销、改密撤销其他设备、禁用、待注销、管理员重置、空闲过期和绝对过期均使旧令牌失效。
6. Cookie 属性完整；跨源、缺少 CSRF 令牌和错误令牌的修改请求全部拒绝。
7. 账号和来源限速、指数延迟及成功登录清理均通过自动验证。
8. 使用真实 Cloudflare Worker 重复性能、并发、限速原子性和 D1 读写验证后，才能进入生产实现。
