# 0013 采用权威数据逻辑备份并重建搜索索引

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10

## 背景

需求 `11.10` 和 `11.11` 要求管理员能够建立包含 D1 与 KV/R2 对象的本地完整备份，并执行经过验证的完整恢复。ADR `0007` 已经确定 FTS5 搜索索引属于可重建派生数据，不进入权威恢复链。

本地验证发现，Wrangler D1 物理导出会明确拒绝包含 FTS5 虚拟表的数据库。官方文档提供的临时方案是先删除虚拟表、导出后重新建立，但这会让生产搜索暂时不可用，也把破坏性结构操作引入常规备份流程。

原型改为导出所有权威普通表，排除 `search_chunks` 和 `message_search`。在新的本地 D1 应用相同迁移、恢复普通表并重建搜索索引后，3 名用户、206 封邮件和 207 个邮箱条目数量一致，206 个搜索分块成功重建并可搜索。证据见[D1 数据库工具与迁移验证结果](../验证/D1数据库工具与迁移验证结果.md)。

## 决定

采用以下方案：

1. “完整 D1 备份”定义为完整保存全部权威普通表、迁移版本、表数量、对象引用和校验信息，不保存可重建 FTS5 虚拟表及其影子表。
2. 常规本地备份不临时删除生产 FTS5 表，也不依赖 `wrangler d1 export` 对含虚拟表数据库的支持。
3. 建立版本化逻辑备份格式：一个简体中文清单文件加每张权威表的流式 NDJSON 或等价记录文件。
4. 清单记录应用版本、数据库迁移编号、备份格式版本、存储模式、表名、行数、文件哈希、对象数量、对象哈希清单和被排除的派生数据。
5. 数据按稳定主键分页读取并流式写入本地文件，不把整库载入单个 Worker 请求或内存。
6. 恢复到空数据库时先应用与备份兼容的 SQL 迁移，再按外键顺序导入权威表；恢复到现有数据库必须走单独、显式确认的覆盖流程。
7. 导入后检查表数量、外键、地址唯一性、邮件与对象引用、对象哈希和关键状态，再从正文对象重建搜索词元与 FTS5。
8. 搜索索引重建完成前，邮件和其他权威功能可以只读运行，但搜索明确显示“正在重建”，不能返回不完整结果冒充完整搜索。
9. D1 Time Travel 用于保留窗口内的快速同库恢复；本地逻辑备份用于长期、跨数据库和灾难恢复，两者都必须演练。
10. 备份工具、恢复工具和正常 Worker 请求路径分离；备份文件按敏感数据保护，不能写入仓库或公开日志。
11. KV/R2 对象备份与 D1 逻辑备份使用同一备份编号和清单，恢复完成前必须完成跨资源数量与哈希对账。

## 备选方案

1. 备份前删除 FTS5，使用 Wrangler 物理导出，再重新建表：依赖破坏性生产操作并造成搜索中断，不采用为常规方案。
2. 不备份 D1，只依赖 Time Travel：保留时间有限，无法满足长期本地备份和跨数据库恢复，不采用。
3. 把 FTS5 影子表作为权威数据自行导出：绑定 SQLite 内部实现，恢复脆弱，也违背搜索索引可重建边界，不采用。
4. 一次读取全部表并生成单个 JSON：小数据可行，但 100,000 封邮件时内存、请求时长和失败重试风险过高，不采用为生产格式。
5. 只保存各表 SQL INSERT：可读性高，但大数据转义、分块恢复和格式演进更难控制；保留为调试或小规模导出，不作为正式完整备份格式。

## 后果

### 正面

1. 常规备份不需要删除搜索表，也不会让生产搜索临时失效。
2. 备份只包含权威数据，避免把可重建索引当成恢复成功的必要条件。
3. 版本清单、行数、文件哈希和对象哈希使 D1 与 KV/R2 可以统一对账。
4. 流式分表格式可以在目标规模下分页、重试和定位失败。
5. 本地备份不依赖 D1 Time Travel 的保留窗口，可以恢复到新的 Cloudflare 资源。

### 负面

1. 项目需要自行实现和长期维护逻辑备份格式、分页导出与导入工具。
2. 恢复后搜索不可立即使用，需要额外时间从正文对象重建。
3. 逻辑备份与物理数据库不逐字节相同，验证必须依赖数据契约、数量、引用和哈希，而不是文件相等。
4. 备份格式和数据库迁移版本需要建立兼容矩阵。
5. 真实目标规模下的备份耗时、文件大小、断点续传和恢复时间仍需验证。

## 验证方式

1. 含 FTS5 的本地 D1 物理导出必须明确失败，并记录平台错误。
2. 逻辑备份必须列出全部权威表、迁移版本和被排除派生表。
3. 在新的空 D1 应用迁移后导入备份，权威表行数与原库一致。
4. 执行 `foreign_key_check`、唯一约束检查、邮件对象引用和对象哈希对账。
5. 从恢复后的正文对象重建搜索索引，完成后搜索结果通过样例与数量检查。
6. 中断导出、导入和索引重建后可以从稳定检查点继续，不产生重复权威记录。
7. 在 100,000 封邮件与两种对象存储模式下完成一次完整演练。
8. 在真实 D1 分别演练 Time Travel 同库恢复和本地备份跨库恢复。
