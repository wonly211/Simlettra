# 0016 分离物理邮件、投递、邮箱条目与用户状态

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10

## 背景

需求要求同一封邮件重复投递时只保存一次，同时允许它送达多个个人地址或组织地址。用户需要集中查看主地址和个人别名，组织成员需要共享邮件内容但保留独立的已读、星标、归档和垃圾箱状态。个人或组织删除自己的副本时，其他仍有权限的邮箱不能丢失邮件。

若把邮件正文、实际收件地址、邮箱归属和每名用户的整理状态全部放在同一行中，会出现以下问题：同一内容被重复保存；同一用户多个别名产生重复列表项；组织成员数量变化需要批量复制或删除邮件；一个人删除邮件可能误删其他人的内容。

本决定落实[第二批数据模型确认清单](../数据模型/第二批数据模型确认清单.md)中的数据-19 至数据-32，以及数据-37。

## 决定

1. 物理邮件、实际投递、邮箱条目和用户状态是四类不同对象。
2. 一封物理邮件只保存一份主题、邮件头事实和对象内容。重复投递通过独立防重键关联同一接收操作；`Message-ID`、原始邮件哈希和时间只作为辅助证据，不作为全局唯一键。
3. 邮件头地址与实际投递地址分开保存。邮件头地址保留当时的显示名称、地址文字、角色、顺序和规范地址；实际投递引用当时有效的地址归属或未分配地址时期。
4. 密送地址记录标记为仅发件人可见。收件人只能看到原始邮件头允许显示的地址和投递到自己的地址，不能读取其他密送投递。
5. 同一物理邮件命中同一用户多个个人地址时，只建立一条个人邮箱条目，多条实际投递共同关联该条目。
6. 个人邮箱、不同组织邮箱是不同邮箱上下文。同一物理邮件同时进入个人和组织邮箱时分别建立条目，状态与删除互不影响。
7. 每个组织对一封物理邮件只保存一条共享邮箱条目，不按成员复制。查看权由当前有效的组织成员关系动态决定。
8. 用户状态按“邮箱条目加用户”保存。状态记录采用稀疏覆盖：缺少状态行或字段时按明确默认规则计算，不为所有组织历史和成员预写默认行。
9. 新成员可以查看组织仍保留的全部历史；加入前历史默认已读，加入后新邮件默认未读。退出立即失去访问权；重新加入后恢复仍存在邮件的旧个人状态，退出期间邮件按加入前历史处理。
10. 草稿使用独立草稿对象。邮箱条目保存收件或已发送方向及初始位置；用户状态保存已读、星标、归档、垃圾箱、永久隐藏和单封远程图片放行。
11. 组织邮件进入某名成员垃圾箱并到期后，只从该成员普通视图永久隐藏。组织创建者必须通过单独且二次确认的组织范围删除操作，才能撤销整个组织对该邮件的访问。
12. 永久删除只撤销对应个人或组织邮箱关系。只要其他邮箱、恢复记录或未完成任务仍合法引用物理邮件，内容就继续保留；最后一个合法引用消失并满足保留规则后才进入对象清理。
13. 可信发件人按“用户加完整规范发件地址”保存，不按域名自动扩张。组织成员的可信设置和单封远程图片放行互不影响。
14. 搜索范围、会话汇总和列表统计属于可重建派生数据。最终访问始终从个人邮箱所有权或当前组织成员资格重新判断。

## 备选方案

1. 每名用户保存一份完整邮件：查询直观，但组织成员和多地址投递会大量复制正文与附件，不采用。
2. 同一用户的个人和组织副本自动合并：列表较短，但删除、已读和组织退出后的权限语义不清，不采用。
3. 为每名组织成员预写全部状态：读取简单，但新增成员和大量历史邮件会产生大批无意义记录，不采用。
4. 使用 `Message-ID` 作为唯一键：实现简单，但外部系统可能缺失、重复或伪造该字段，会误合并真实邮件，不采用。
5. 组织创建者的垃圾箱到期自动删除组织原件：操作步骤少，但普通个人整理动作可能导致全组织数据丢失，不采用。
6. 按发件域名信任远程图片：设置方便，但一个可信联系人会扩大为同域名所有地址，风险范围过大，不采用。

## 后果

### 正面影响

1. 邮件内容只保存一次，同时支持任意数量的个人和组织邮箱上下文。
2. 同一用户多个别名不会制造重复列表项，实际投递地址仍完整可见。
3. 组织成员加入、退出和重新加入不需要复制邮件，权限撤销也能立即生效。
4. 个人整理、组织范围删除和物理对象清理具有不同边界，不会相互误伤。
5. 密送隐私、历史地址快照和远程图片信任范围能够在服务端明确检查。

### 成本与限制

1. 列表和详情查询需要联合物理邮件、邮箱条目、投递关系和用户状态。
2. 稀疏状态需要应用服务实现确定且经过测试的默认值计算。
3. 邮箱条目与实际投递、地址归属是否匹配无法只靠普通外键完全表达，需要事务服务和契约测试。
4. 物理邮件的最终清理必须等待后续生命周期模型对全部合法引用完成对账。
5. 组织历史默认已读是一项明确产品规则，不能由前端临时推断成其他行为。

## 验证方式

1. 同一物理邮件投递到同一用户多个地址时只有一条个人邮箱条目，但能够查出全部实际投递地址。
2. 同一物理邮件进入个人和组织邮箱时生成不同条目，删除其中一条不影响另一条。
3. 退出组织后服务端查询不到组织条目；重新加入后旧个人状态恢复，退出期间邮件按历史默认已读。
4. 两名成员对同一组织条目设置不同状态时互不覆盖。
5. 同一防重键重复执行不会生成第二封物理邮件；相同 `Message-ID` 使用不同防重键时可以形成不同邮件。
6. 密送收件人不能通过详情、搜索或投递接口取得其他密送地址。
7. 删除一个邮箱条目后，只要仍有其他条目引用，物理邮件和内容对象就不能进入最终清理。
