# 0017 以权威邮件关系重建邮箱范围会话

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10

## 背景

需求要求根据标准邮件关系把回复归入同一会话，同时保留每封原始邮件。外部邮件可能缺少父邮件、晚于回复到达、包含重复 `Message-ID`，或者仅仅具有相同主题。个人邮箱和组织邮箱还具有不同权限边界，不能因为系统在另一邮箱中找到了相关邮件，就向当前用户泄露其存在。

若把一次计算得到的会话编号当作不可修改事实，会使迁移补入、晚到邮件和关系修复变得困难。若只按主题归并，则大量无关邮件会被错误合并。

本决定落实[第二批数据模型确认清单](../数据模型/第二批数据模型确认清单.md)中的数据-33 和数据-34。

## 决定

1. 原始 `Message-ID`、`In-Reply-To`、`References` 的结构化关系，以及 Simlettra 内部明确的回复父邮件关系，属于权威事实。
2. 系统内明确回复关系优先，其次使用标准 `In-Reply-To` 和 `References`。仅主题相同不能自动建立关系。
3. 每条关系保存目标引用文字和可选的已解析物理邮件编号。父邮件尚不存在时保留未解析引用，父邮件以后出现或迁移补入时可以重新解析。
4. 会话编号和会话成员表属于可重建派生数据，可以在算法修复或邮件补入后重新生成。
5. 会话必须按个人邮箱或单个组织邮箱上下文建立。相同物理邮件在不同邮箱上下文中可以属于不同的会话记录。
6. 会话查询不能直接授予访问权。返回每封会话邮件前仍需检查个人邮箱所有权或当前组织成员资格。
7. 会话重建只能修改派生会话表，不能改写原始 MIME、邮件头地址或权威邮件关系。

## 备选方案

1. 只按规范化主题合并：可以覆盖缺少标准头的旧邮件，但误合并率高，不采用。
2. 把会话编号直接永久写入物理邮件：查询简单，但一封邮件进入多个邮箱上下文时权限边界混乱，不采用。
3. 父邮件不存在时丢弃关系：表结构较小，但晚到和迁移补入后无法恢复正确会话，不采用。
4. 会话成员直接作为权限来源：查询步骤少，但派生数据损坏会造成越权，不采用。

## 后果

### 正面影响

1. 相同主题的无关邮件不会被强行合并。
2. 晚到、迁移补入或重新解析的父邮件可以修复已有会话。
3. 会话算法可以升级和重建，不破坏原始邮件事实。
4. 个人和组织邮箱的会话边界明确，不会通过关联结果泄露其他邮箱。

### 成本与限制

1. 需要保存未解析关系，并通过后台任务增量重新匹配。
2. 同一物理邮件可能在多个邮箱范围生成派生会话成员记录。
3. 缺少标准关系头且不是系统内回复的邮件不会仅凭主题自动归入会话。
4. 会话重建后内部会话编号可能变化，公共接口不能把它当作永久外部身份。

## 验证方式

1. 系统内回复、标准头回复和多级 `References` 能归入正确会话。
2. 相同主题但没有关系头的两封邮件保持分离。
3. 父邮件晚到后，未解析关系能够重新关联并重建会话。
4. 同一物理邮件进入个人和组织邮箱时，会话记录属于不同邮箱范围。
5. 用户退出组织后，即使派生会话成员仍存在，也不能读取组织邮件。
6. 删除并重建会话表后，分组结果可以从权威关系和邮箱条目恢复。
