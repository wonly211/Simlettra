# 0018 以未分配地址时期隔离认领历史

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10

## 背景

启用全域收信后，系统需要保存发往未创建地址的邮件，并允许获授权用户认领该地址成为个人别名，同时取得历史未分配来信。邮箱地址可以在删除和保留期结束后重新释放；相同地址文字将来可能由另一名用户重新创建。

如果只按地址文字保存一份永久未分配收件箱，后来的认领者可能取得该地址上一次使用时期的邮件。若在认领时逐封移动而没有稳定时期和事务边界，并发认领或中途失败还可能形成地址已经占用但历史邮件只迁移一部分的状态。

本决定落实[第二批数据模型确认清单](../数据模型/第二批数据模型确认清单.md)中的数据-35 和数据-36。

## 决定

1. 每个规范未分配地址按连续时间建立“未分配地址时期”，同时最多存在一个开放时期。
2. 发往未创建地址的实际投递引用当时开放的时期。同一物理邮件发往多个未分配地址时，每个地址具有独立投递和时期关系，但物理内容仍只保存一份。
3. 未分配来信只出现在独立视图，不自动进入任何个人或组织邮箱。
4. 查看权按“域名加用户”的显式授权保存。系统管理员设置授权，服务端每次查询都检查用户状态、域名状态和授权关系。
5. 认领前只提供查看、搜索和认领，不提供星标、归档、垃圾箱或永久删除等个人邮箱整理操作。
6. 认领在一个 D1 事务中完成：检查用户和域名状态、检查用户自建别名权限与配额、占用地址文字、创建地址身份和个人别名归属、关闭当前未分配时期，并为该时期的全部投递建立个人邮箱条目关系。
7. 并发认领依靠当前地址占用和开放时期唯一约束决定胜者。失败者的整个事务回滚，不能获得部分邮件。
8. 认领只包含当前未分配时期。地址以后释放并再次收到邮件时建立新时期，过去已经关闭或认领的时期不能自动重新开放。
9. 关闭但未认领的时期及其清理规则由后续数据生命周期模型决定，本决定不允许静默把它们交给未来地址使用者。

## 备选方案

1. 每个地址文字永久只有一个未分配收件箱：结构简单，但地址重用后会串联不同使用者的历史，不采用。
2. 认领时只接收认领后的新邮件：隐私边界清楚，但不满足取得历史未分配来信的需求，不采用。
3. 认领时异步逐封迁移：单次事务较小，但用户可能看到部分历史，并发失败难以回滚，不采用。
4. 未分配邮件直接显示在获授权用户的个人收件箱：入口少，但所有权和个人删除语义混乱，不采用。
5. 允许查看者在认领前整理或删除：功能丰富，但多人操作会改变共享待认领数据，不采用。

## 后果

### 正面影响

1. 相同地址文字的不同时期不会共享历史邮件。
2. 认领要么完整成功，要么不改变地址和邮件归属。
3. 一封邮件发往多个未知地址时，每个地址可以独立认领而不复制正文。
4. 未分配查看权、地址所有权和个人邮箱整理权具有清晰边界。

### 成本与限制

1. 每个出现过的未分配地址时期都会增加权威记录。
2. 大量历史投递认领时需要遵守 D1 参数和事务语句限制，应用服务必须分块构造批次并在提交前完成数量检查。
3. 未认领时期的保留与永久清理仍需第六批数据生命周期设计补充。
4. 授权用户能查看完整未分配邮件，属于高权限能力，需要审计和频率限制。

## 验证方式

1. 同一规范地址同时只能有一个开放时期，大小写不能绕过唯一约束。
2. 认领成功后地址占用、别名归属、时期关闭和历史邮箱条目同时存在。
3. 配额、地址冲突或任一邮箱条目写入失败时，认领事务全部回滚。
4. 两名用户并发认领时只有一名成功，失败者没有地址和历史邮件。
5. 地址释放后建立新时期，新的认领者不能访问先前关闭时期的邮件。
6. 用户失去域名授权或进入禁用、注销状态后，立即不能查看未分配来信。
