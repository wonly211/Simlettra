# 0023 以有界防重和冻结路由完成可恢复收信

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10
- 局部取代：决定 2 中“实际投递地址进入物理邮件有界指纹”的结论已由 [ADR 0047](0047-以内容窗口归并多地址收信并异步补交付.md)取代；本记录其余结论继续有效

## 背景

邮件路由或 Worker 可能重复投递同一请求，Worker 也可能在原始对象已写入、解析完成或最终 D1 提交前中断。同时，完全相同的邮件可能在较晚时间被合法再次发送，不能把原始内容哈希永久视为唯一邮件。

收信期间域名、地址或全域收信设置还可能变化。如果后台任务每次都重新路由，同一封已经接受的邮件可能因为配置变化被改投到另一个所有者或静默消失。

本决定承接[第四批数据模型确认清单](../数据模型/第四批数据模型确认清单.md)中的数据-67 至数据-71，并细化 ADR `0008` 和 `0009` 的收信状态机。

## 决定

1. 每次收信使用一个稳定收信操作编号，并预留唯一物理邮件引用。所有重试推进同一操作，不重新生成邮件身份。
2. 防重优先使用可信来源事件编号。来源没有稳定编号时，使用原始字节摘要、信封发件人、实际投递地址和明确时间窗口生成有界指纹；纯内容哈希不建立永久唯一约束。
3. 防重记录区分“来源事件”和“有界指纹”。有界指纹保存窗口起止时间，窗口外相同内容可以建立新操作。
4. 接受时冻结信封发件人、实际投递地址、命中的域名、地址身份、地址归属或未分配地址时期。后续配置变化不重写这次已经接受的路由事实。
5. 每个实际投递地址建立一条收信路由快照，状态区分已接受、已拒绝和已提交。已接受路由只能在最终事务中关联同一邮件的实际投递记录。
6. 收信操作状态区分接收意图、原始对象存在、解析中、衍生对象存在、等待一致性、提交中、可见、解析失败、损坏、拒收和需处理。
7. 临时对象读取、平台故障和 KV 传播等待推进同一操作重试。确定性 MIME 格式错误、资源边界超限和哈希不符不会无限重试。
8. 解析错误只保存有限错误代码、解析器版本、部件数量和安全摘要；原始 MIME 保留，完整正文和附件内容不进入错误字段或日志。
9. 最终可见提交使用一个 D1 批次建立物理邮件、完整性状态、邮件头、实际投递、个人或组织邮箱条目、附件元数据、最终防重关系和搜索任务，并把路由和收信操作改为完成。
10. 搜索索引任务必须随最终批次登记，但索引构建不阻塞邮件首次可见。索引未完成时不得返回不完整结果冒充完整搜索。
11. 最终批次任一语句失败时全部回滚；已经写入但尚未附着的对象由后续对账识别，不提前向用户显示。

## 备选方案

1. 永久按原始 MIME 哈希去重：能强力消除重复，但会吞掉合法的相同内容再次发送，不采用。
2. 只依赖 `Message-ID`：字段可能缺失、伪造或在合法重发中复用，不能作为唯一防重依据，不采用。
3. 后台解析时重新查询当前路由：可以自动跟随配置，但会改写已接受投递事实，不采用。
4. 原始对象写完即创建邮箱条目：延迟低，但解析或附件写入失败会产生半封可见邮件，不采用。
5. 解析失败时删除原始 MIME：节省空间，但失去重新解析、导出、排错和恢复依据，不采用。
6. 搜索索引完成后才显示邮件：搜索立即完整，但会无必要延迟读信并扩大索引故障影响，不采用。

## 后果

### 正面影响

1. 平台重试不会重复创建邮件，合法的较晚重发仍能进入系统。
2. 已接受路由不会因管理员随后修改地址或域名设置而漂移。
3. 任一中断点都能从收信操作状态判断下一步。
4. 解析失败和对象异常不会产生半封可见邮件。
5. 搜索任务可以独立恢复，不阻塞已完整保存的邮件被阅读。

### 成本与限制

1. 无稳定来源事件编号时，有界防重窗口不能数学上区分窗口内的完全相同合法重发与平台重试。
2. 每个实际投递地址增加一条路由快照和最终投递匹配。
3. 最终 D1 批次涉及多个模块表，需要严格固定写入顺序和回归测试。
4. 解析失败邮件默认不出现在普通邮箱中，管理员必须能够看到不含正文的异常告警。
5. 防重窗口的具体时长仍需结合 Cloudflare 实际重试行为验证后配置。

## 验证方式

1. 相同来源事件编号重复执行只得到同一收信操作和物理邮件。
2. 相同有界指纹在同一窗口内防重，使用下一窗口生成的新指纹可以建立新操作。
3. 路由快照建立后不能改指其他地址归属或未分配时期。
4. 已接受路由只能关联同一收信操作最终邮件的匹配实际投递。
5. 收信状态不能倒退或跳过必要对象阶段；确定性失败不会自动回到无限重试。
6. 最终批次失败时邮件、投递、邮箱条目、路由完成状态和收信完成状态全部回滚。
7. 收信操作进入可见前，必要对象、完整性状态、路由投递和最终防重关系必须同时存在。
8. 搜索任务重复执行不创建第二个权威邮件或邮箱条目。
