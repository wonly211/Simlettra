# 0024 以 D1 任务租约和分批对账协调后台工作

## 状态

已接受

- 提议日期：2026-08-10
- 接受日期：2026-08-10

## 背景

收信解析、对象一致性等待、站外发信、通知、转发、搜索、修复和永久清理都可能被 Queue 重复唤醒，也可能因 Worker 超时、消息过期或 Queue 暂时不可用而没有及时执行。若 Queue 消息本身承担任务真相，消息丢失后系统无法恢复；若两个 Worker 同时处理同一任务，迟到的旧执行者可能覆盖新结果或重复产生外部副作用。

免费额度规模还要求定时修复和对象对账分批进行，不能频繁全表扫描或一次列举全部对象。

本决定承接[第四批数据模型确认清单](../数据模型/第四批数据模型确认清单.md)中的数据-72 至数据-77，并细化 ADR `0003` 与 `0009` 的后台任务边界。

## 决定

1. 使用一张 D1 后台任务表保存所有任务的稳定编号、类型、目标引用、输入版本、唯一任务摘要、状态、优先级、下一次执行时间、尝试次数和有限错误。
2. Queue 消息只包含任务编号、任务版本和唤醒原因。消费者收到消息后必须重新读取 D1，不能把消息负载当作当前状态。
3. 任务状态至少区分等待、运行、等待重试、需要处理、成功和取消。Queue 死信不是权威终态，D1 的“需要处理”才是管理员入口。
4. 领取任务使用 D1 条件更新，同时增加尝试次数和递增领取令牌，并设置租约所有者与到期时间。
5. 运行中的任务只能使用当前领取令牌续租或提交结果。租约过期后重新领取会生成更高令牌，迟到的旧 Worker 不能覆盖新状态。
6. 每次领取建立任务尝试记录。尝试保存开始、结束、结果、可重试性和安全错误摘要；终态尝试不可重新分类。
7. 临时错误按任务类型使用指数退避和有限随机扰动。最大尝试次数或最大等待期限由任务策略决定；确定性错误直接进入需要处理或业务终态。
8. 管理员可以对支持的任务执行重新排队或取消，操作必须通过应用服务检查当前状态并写审计；不得直接修改业务表伪造完成。
9. 定时任务按 `next_attempt_at`、租约到期时间和稳定游标增量扫描 D1，重新唤醒到期、遗漏和租约过期任务。
10. 对象库存对账使用独立批次，保存存储模式、游标、批次号、扫描计数和结果。孤立、缺失与哈希不符分别记录，不在一次请求中全量处理。
11. 孤立对象只有在保护期结束且两个不同对账批次持续确认后才能安排删除。登记对象缺失或损坏则进入修复或告警，不套用孤立删除规则。
12. 任务和对账记录不得保存正文、附件内容、密码、令牌、密钥或完整外部回调。

## 备选方案

1. 只使用 Queue 重试和死信：平台配置少，但无法恢复丢失唤醒或统一查看任务状态，不采用。
2. 只用 D1 定时扫描，不使用 Queue：可以恢复，但日常延迟和读取成本更高，且 Cloudflare 发信事件仍需要 Queue，不采用。
3. 每个模块各建任务表：局部简单，但租约、重试、监控和人工处理规则重复且容易不一致，不采用。
4. 只用布尔“处理中”锁：Worker 崩溃后无法判断何时接管，也不能阻止迟到执行者写回，不采用。
5. 所有错误无限自动重试：可能最终成功，但会持续消耗配额并掩盖确定性错误，不采用。
6. 每次定时任务全量扫描任务和对象：实现直接，但数据增长后会浪费 D1 与对象列举额度并容易超时，不采用。

## 后果

### 正面影响

1. Queue 重复、丢失或过期不会改变任务的权威状态。
2. 租约和递增令牌阻止迟到 Worker 覆盖新结果。
3. 收信、发信、通知、清理和对账可以共用一致的运维视图。
4. 临时故障自动恢复，确定性失败明确停下并等待处理。
5. 分批游标与结果摘要使维护工作适合免费额度规模并可从中断处继续。

### 成本与限制

1. 每次执行增加任务和尝试行，需要定期按生命周期清理历史。
2. 应用服务必须使用条件更新和领取令牌，不能无条件覆盖任务行。
3. 不同任务仍需各自定义可重试错误、最大期限和业务补偿。
4. D1 条件更新能减少并发冲突，但真实多地区 Queue 消费仍需远程压力验证。
5. 对账只发现和安排修复，不能替代经过验证的完整备份。

## 验证方式

1. 同一任务摘要只能建立一条活动任务，重复 Queue 消息不增加业务结果。
2. 两个执行者竞争时只有一个条件更新成功领取任务。
3. 租约过期后新执行者以更高令牌接管，旧令牌完成更新失败。
4. 临时失败进入等待重试并具有未来执行时间；确定性失败或尝试耗尽进入需要处理。
5. 成功、取消和需要处理状态不能被普通 Queue 重放改回等待。
6. Queue 消息缺失时，定时扫描能按 D1 状态重新唤醒任务。
7. 对账批次可以使用游标多次继续，重复处理同一批不会重复创建开放发现。
8. 孤立对象未满 24 小时或只在一个批次出现时不能安排删除。
