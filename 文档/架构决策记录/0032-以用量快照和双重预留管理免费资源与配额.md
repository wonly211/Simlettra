# 0032 以用量快照和双重预留管理免费资源与配额

## 状态

已接受

- 提议与接受日期：2026-08-11
- 需求依据：需求 `2.10`、`7.12`、`7.16`、`11.13` 与需求变更 `0003`
- 数据依据：[第六批数据模型确认清单](../数据模型/第六批数据模型确认清单.md)中的数据-108 至数据-113、数据-129 至数据-132
- 官方依据：[Cloudflare 资源用量接口核验](../验证/Cloudflare资源用量接口核验.md)

## 背景

Simlettra 同时存在用户或组织能够理解的逻辑配额，以及 D1、KV/R2 免费额度形成的平台硬上限。两者统计口径不同：一封邮件在用户邮箱中只计一次，但物理上可能包含多个对象；共享 Cloudflare 账号中的其他项目也会占用平台免费额度。

域名月度发件配额还需要在并发发送、逐收件人状态、Provider 重试和结果未知情况下避免超发或重复计数。

## 决定

1. 用户和组织存储配额使用逻辑用量账本；平台免费额度使用不可变资源快照，两者分开显示和对账。
2. 任何增加存储的操作必须同时通过逻辑邮箱配额与平台免费额度检查，并分别建立短期预留。
3. 成功后预留转为正式用量，明确失败或超时后释放；结果未知或对象尚未对账时继续占用。
4. 平台快照记录账号用量、Simlettra 用量、免费上限、剩余额度、统计范围、数据来源、获取时间和结果，不把旧快照冒充实时值。
5. 优先使用 Cloudflare 账号级只读指标；只能使用本地估算时明确标记，并采用保守停止值。
6. 管理员可以设置更低的预警或停止比例，不能通过产品设置把平台上限提高到免费额度之外。
7. 域名月度配额使用系统默认与逐域名覆盖；默认不额外限制，并与 Provider 自身套餐额度分开显示。
8. 域名用量按系统时区的自然月和去重后的最终收件人数统计。发送前逐收件人预留；站内送达或域外 Provider 明确接受后提交，明确未接受时释放，结果未知时继续占用。
9. 重试和备用 Provider 切换复用同一收件人用量记录；通知、外部邮箱验证和自动转发不计入普通域名月度配额。

## 备选方案

1. 只使用 Cloudflare 指标作为用户配额：无法表达用户和组织的逻辑邮箱容量，不采用。
2. 只使用 Simlettra 本地账本：看不到共享账号中其他项目的占用，不能保证免费上限，不采用。
3. 发送完成后再计数：并发发送可能共同越过配额，不采用。
4. 按邮件封数计量：大量收件人可绕过防滥用限制，不采用。

## 后果

### 正面

1. 用户容量、系统物理容量和 Cloudflare 免费额度不会混成一个数字。
2. 并发收信、上传和发信能够在增加用量前阻止超限。
3. Provider 重试不会重复扣减域名配额。

### 负面

1. 每次容量增加需要维护两类预留。
2. Cloudflare 指标可能延迟，必须保留安全余量和本地对账。
3. 自然月切换与时区变更需要明确版本边界。

## 验证方式

1. 并发预留不能使逻辑配额或平台停止值被越过。
2. Cloudflare 指标缺失、过期、权限不足和共享账号占用时进入明确的估算或保守停止状态。
3. 一封邮件发给多名收件人逐人占用额度，重试和备用切换不重复计数。
4. 明确未接受释放预留，结果未知继续占用，后续事件只能进行允许的状态迁移。
5. 达到上限后阅读、导出、备份和永久删除仍可执行。
