# 0040 以加密本地容器和空白资源分阶段完成完整恢复

## 状态

已接受

- 提议与接受日期：2026-08-13
- 依据：需求 `11.10`、`11.11`，第六批数据模型中的备份与恢复决定
- 关联决定：[0013 采用权威数据逻辑备份并重建搜索索引](0013-采用权威数据逻辑备份并重建搜索索引.md)、[0033 以不可变记录和可验证清单完成审计、备份与迁移](0033-以不可变记录和可验证清单完成审计备份与迁移.md)

## 背景

Simlettra 需要让非程序员管理员把 D1 与当前 KV 或 R2 的完整备份保存到本地，并能够在故障后恢复。在线 Worker 适合生成可校验清单和分卷，但不适合持有管理员的本地备份密码，也不能把整个系统数据一次性装入内存。

D1 通过 Wrangler 导入外部 SQL 时不允许显式 `BEGIN`、`COMMIT`，导入文件中的 `PRAGMA foreign_keys = OFF` 也不能为乱序外键导入提供可靠保护。因此，完整恢复不能宣称为一个跨 D1 与对象存储的原子事务。

## 决定

1. 在线 Worker 生成的是带清单、大小和 SHA-256 的原始备份分卷。原始 HTTP 分卷本身不宣称已经加密。
2. 本地工具默认使用管理员提供的密码，把清单和分卷封装为 AES-256-GCM 加密容器；PBKDF2-HMAC-SHA-256 使用 900,000 次迭代，每个分卷使用独立随机值和认证标签，元数据另做 HMAC 认证。
3. 密码只从 `SIMLETTRA_BACKUP_PASSWORD` 或密码文件读取，不接受明文密码命令行参数。
4. 首发恢复只允许写入已经应用清单指定正式迁移、且没有业务数据和既有恢复账本的空白 D1；不提供覆盖现有系统的恢复模式。
5. 恢复工具通过正式迁移在内存 SQLite 中重建目标结构，按真实外键依赖生成父表优先的导入顺序。可空自引用外键先写入 `NULL`，全部行建立后再回填；不可空循环外键会使恢复计划失败。
6. 为避免业务触发器把按依赖导入误判为在线操作，导入开始时暂时删除正式触发器，数据和延迟外键写入完成后按正式迁移定义原样恢复触发器。外键约束始终保持开启。
7. D1 导入完成后逐个上传 KV 或 R2 对象，并立即回读核对大小和 SHA-256。任何对象缺失、损坏或不一致都使恢复失败。
8. 恢复使用 `restore_runs`、`restore_checkpoints` 和 `restore_checks` 记录阶段证据。六项检查为清单哈希、表行数、对象哈希、外键、对象引用和搜索重建。
9. 搜索索引不进入权威备份。恢复先为完整邮件建立待重建状态和后台任务；搜索全部变为 `ready` 且六项检查通过后，恢复运行才能标记为成功。
10. D1、KV/R2 与搜索任务无法组成一个跨资源事务。任一步失败后不得继续使用部分恢复目标，应废弃本次目标资源并从空白资源重新执行。

## 备选方案

1. 把本地备份密码交给 Worker 并在线生成加密大文件：会扩大密码暴露面，也不利于按分卷下载和失败重试，不采用。
2. 使用 `PRAGMA foreign_keys = OFF` 和字母顺序导入：D1 外部 SQL 不能可靠应用该方式，且会隐藏错误，不采用。
3. 使用 `INSERT OR IGNORE` 跳过冲突：可能静默遗漏数据，破坏完整恢复证据，不采用。
4. 覆盖现有 D1 和对象存储：需要维护模式、恢复前备份、冲突处理和更复杂的回退承诺，首发不采用。

## 后果

### 正面

1. 本地备份默认加密，密码错误、密文或元数据篡改都会被拒绝。
2. 导入顺序来自正式迁移结构，不依赖人工维护表名列表。
3. 每个对象都经过实际目标回读校验，恢复成功有可复核的 D1 证据。
4. 搜索作为派生数据重建，不扩大权威备份，也不会在重建完成前误报成功。

### 负面

1. 管理员需要准备空白 D1 和空白 KV/R2 目标，失败时需要删除并重建目标资源。
2. 大备份的对象逐项上传和回读会消耗时间及 Cloudflare 操作额度。
3. 真实 Cloudflare 远程 D1、KV 和 R2 的大规模恢复时间、限速和失败行为仍需演练。

## 验证方式

1. 校验多页表合并、二进制摘要、清单哈希、分卷大小和对象登记引用。
2. 验证父子表顺序、可空自引用回填、不可空循环拒绝及导入后的 `PRAGMA foreign_key_check`。
3. 使用临时本地 D1 与 R2 执行完整恢复，确认对象上传后回读摘要一致。
4. 搜索未完成时确认恢复保持运行状态；搜索完成后确认六项检查和恢复账本全部成功。
5. 使用错误密码、篡改密文、错误清单哈希、非空目标和迁移版本不匹配验证拒绝路径。
6. 在真实 Cloudflare Free 的 D1、KV 与 R2 上分别演练完整恢复并记录耗时、操作量和失败重试结果。
