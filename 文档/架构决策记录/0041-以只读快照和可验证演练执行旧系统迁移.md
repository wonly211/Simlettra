# 0041 以只读快照和可验证演练执行旧系统迁移

## 状态

已接受

- 决策日期：2026-08-13
- 需求依据：`11.01` 至 `11.06`
- 数据依据：数据-123 至数据-128
- 关联决定：[0033 以不可变记录和可验证清单完成审计、备份与迁移](0033-以不可变记录和可验证清单完成审计备份与迁移.md)

## 背景

旧系统把元数据保存在 D1，把正文和附件保存在 KV 或 R2，并且运行中的数据可能继续变化。新系统的数据结构、密码保护、邮件完整性和对象所有权模型均已重建，不能直接复制旧表或在正式迁移时边读取变化中的旧资源边写入新系统。

正式迁移还必须证明同一来源数据已经在副本上成功演练。演练目标与正式目标相互独立，因此演练证据需要能够被验证并带入正式目标，而不能要求在生产数据中先执行一次迁移。

## 决定

1. 旧系统迁移由独立本地工具执行，不进入 Worker 的普通请求、Queue 或定时任务路径。
2. 工具先以只读方式生成包含 D1 分卷、被引用对象、数量和 SHA-256 的本地快照；迁移只消费固定快照，不在写入目标时继续读取旧系统。
3. 来源快照摘要只由固定来源元数据和排序后的内容摘要计算，不包含本地路径或生成时间。
4. 演练在独立临时目标执行并生成可校验报告。正式执行要求报告的来源摘要、旧版本、参考提交、规则版本和目标迁移版本全部一致，并在正式 D1 登记外部演练证据。
5. 目标编号与对象键由来源身份和内容摘要确定；重复运行通过不可变来源映射和相同对象键继续，不生成重复用户、地址、邮件或对象。
6. 跨 D1 与对象存储按“对象写入回读、D1 可见提交、最终对账”分阶段执行。结果未知时停止并保留检查点，不猜测成功或自动创建第二份数据。
7. 旧弱密码不迁移。普通迁移用户使用不可登录的随机占位凭据，必须由管理员显式重置后才能登录；匹配当前管理员主地址时保留当前管理员凭据。
8. 没有原始 MIME 的旧邮件标记为结构化重建。没有可靠删除时间的旧逻辑删除邮件跳过，不把已删除邮件重新显示。

## 备选方案

1. **直接连接旧系统并边读边写**：来源在迁移期间可能变化，演练与正式结果无法证明一致，不采用。
2. **复制旧 D1 和整个 KV/R2**：会带入运行时缓存、无引用对象、旧权限和旧配置，也无法满足当前结构，不采用。
3. **让正式目标先执行一次演练再重复导入**：会在生产系统提前写入用户和邮件，不符合演练隔离目的，不采用。
4. **继续接受旧 SHA-256 密码**：会把已知不符合当前基线的密码保护带入新系统，不采用。

## 后果

### 正面

1. 演练和正式迁移使用完全相同的不可变输入，结果可复核。
2. 旧系统和数据副本保持只读，失败不会破坏来源。
3. 中断后可以从检查点继续，重复执行不会创建重复数据。
4. 旧密码和不完整邮件不会被描述成符合当前安全与完整性标准的数据。

### 负面

1. 迁移前需要额外本地空间保存 D1 分卷和被引用对象。
2. 管理员需要准备独立演练目标，并在迁移后为普通用户逐步重置密码。
3. D1 与 KV/R2 仍不具备跨资源原子事务，工具必须维护对象回读、检查点和最终对账。

## 验证方式

1. 对同一旧数据重复生成快照，来源摘要保持一致；任一行或对象变化都会改变摘要。
2. 快照过程只执行查询和对象读取命令，不包含旧资源更新、删除或格式化命令。
3. 同一快照重复迁移复用来源映射；内容冲突停止并进入失败报告。
4. 缺少匹配成功演练报告时，正式迁移被拒绝。
5. 迁移用户的旧密码不能登录，管理员重置后才能使用一次性临时密码登录。
6. 结构化邮件、正文、附件、星标和实际投递地址完成分类对账，缺失对象不会形成可见邮件。
