# 0042 以受限恢复会话和分步任务处理账号注销

## 状态

已接受

- 决策日期：2026-08-13
- 需求依据：`3.11`、`8.13` 至 `8.15`、`9.07` 至 `9.09`、`11.09`、`11.14`、`11.15`
- 数据依据：数据-99 至数据-107
- 关联决定：[0011 采用平台原生密码哈希和可撤销不透明会话](0011-采用平台原生密码哈希和可撤销不透明会话.md)、[0015 以显式主体关系维护唯一管理员和组织权限](0015-以显式主体关系维护唯一管理员和组织权限.md)、[0033 以不可变记录和可验证清单完成审计备份与迁移](0033-以不可变记录和可验证清单完成审计备份与迁移.md)

## 背景

用户申请注销后必须立即退出正常会话并停止收发，但七天内仍要能够通过密码进入只用于取消注销的页面。普通登录会话拥有邮箱和设置权限，不能在待注销状态继续复用。期满清理还会跨越 D1、KV/R2、搜索、草稿、邮件和地址占用，无法在一个 HTTP 请求或一个 D1 事务内可靠完成。

唯一系统管理员和组织创建者还承担不可为空的身份关系。进入注销前必须先转让管理员身份，并处理仍由本人创建的组织，不能把这些依赖留到期满任务中临时猜测。

## 决定

1. 普通会话只服务于状态为 `active` 的用户。用户进入注销冷静期时撤销全部普通会话。
2. 冷静期登录使用独立的受限恢复会话。它拥有独立随机令牌、CSRF 摘要和短有效期，只能读取注销状态并取消注销，不能访问邮箱、组织、设置或普通认证接口。
3. 恢复会话只允许在密码验证成功、用户仍为 `deletion_pending` 且恢复截止时间未到时建立；取消注销后立即消费该会话并撤销同一用户的其他恢复会话。
4. 当前唯一系统管理员必须先把身份原子转让给另一名已启用用户，才能申请注销。管理员身份始终由 `system_instances.current_admin_user_id` 唯一表示。
5. 用户申请注销前必须不再创建任何活动或待删除组织。仍有其他成员的组织先转让；只有创建者一人的组织先进入七天删除期并在永久删除后解除阻塞。
6. 用户和组织的期满清理均使用现有删除操作、步骤、后台任务和租约账本。每次任务只处理有界数据，并以检查点继续，不能把整个邮箱一次读入 Worker 内存。
7. 先撤销访问，再清理个人或组织邮箱条目、草稿对象、通知、转发、地址占用、设置、配额和缓存；仍被其他邮箱引用的物理邮件继续保留。
8. 用户永久删除后保留稳定用户编号和“已删除用户”占位，不保留原显示名称、密码、会话、地址占用或个人设置。组织永久删除后保留最小 `deleting` 历史占位，以承接已有邮件和发信事实，但不再拥有可用地址、成员或设置。
9. 升级前已经处于组织删除冷静期、但没有正式删除操作和后台任务的记录，仍允许创建者在原截止时间前恢复；Cron 按原始申请时间与截止时间补建统一账本，不能重新开始七天冷静期。

## 备选方案

1. **允许待注销用户继续使用普通会话**：权限过宽，容易误开放读信或设置接口，不采用。
2. **密码验证后直接取消注销**：缺少明确恢复页面与二次动作，用户无法先查看影响和截止时间，不采用。
3. **在注销请求中同步删除全部数据**：跨资源不能原子提交，且大邮箱会超过 Worker 的 CPU、内存和请求时限，不采用。
4. **期满后直接删除用户或组织主行**：历史邮件、审计和发信记录存在外键与署名需求，不采用。

## 后果

### 正面

1. 待注销用户没有邮箱权限，但仍能安全取消注销。
2. 管理员和组织身份依赖在进入冷静期前解决，期满任务不需要替用户选择继任者。
3. 大邮箱清理可以分批、重试、对账，不因一次故障重新开放访问。
4. 必要历史引用保留稳定编号，同时个人凭据和当前地址能力被清除。

### 负面

1. 认证边界增加一种只用于注销恢复的会话和 Cookie。
2. 用户与组织永久清理需要多阶段后台任务和额外检查点。
3. 本地备份仍可能包含删除前的数据，系统无法替管理员删除已经保存到本地的备份。

## 验证方式

1. 普通登录不能为待注销、正在清理或已删除用户建立会话。
2. 受限恢复会话不能访问任一普通认证接口，过期、撤销、消费或 CSRF 不匹配时不能取消注销。
3. 当前管理员未转让身份时注销请求被数据库和应用服务同时拒绝；转让后始终只有一名管理员。
4. 仍创建组织或仍存在组织依赖时注销请求返回具体阻塞项。
5. 用户和组织期满任务可以从检查点重放，不重复删除对象或生成第二份邮件清理操作。
6. 永久删除后密码、普通会话、恢复会话、个人设置和地址占用不存在，用户占位不含原显示名称与邮箱地址。
7. 外键检查、对象引用、搜索清理和逻辑存储用量对账全部通过后，删除操作才能标记完成。
8. 模拟缺少删除账本的历史待删除组织，验证冷静期恢复、Cron 幂等补建、原始截止时间保留、到期任务投递和永久清理。
