# 0045 区分代码回退与空白资源恢复

## 状态

已接受

- 决定日期：2026-08-13

## 背景

需求 `2.07` 要求每次升级提供版本说明、升级步骤、数据检查和回退说明，需求 `12.12` 要求发布前至少演练一次版本回退。ADR `0012` 已确定 `migrations/` 是只增不改的 Wrangler 唯一迁移账本，已经成功应用的迁移不能通过修改历史文件或在生产库执行随意的逆向 SQL 撤销。

“回退”实际包含两种不同情况：一是新 Worker 代码有问题但数据库仍与旧代码兼容；二是数据库、对象或跨资源状态已经发生不兼容变化，需要恢复升级前数据。如果把两者都处理成“执行一份降级 SQL”，容易在 D1、KV/R2、搜索和后台任务之间制造更难恢复的不一致。

## 决定

1. 正式迁移只向前追加；已经应用的迁移文件不改写、不删除、不重排，也不为生产回退提供通用逆向 SQL。
2. 每份发布说明必须明确行为变化、配置变化、数据变化、迁移顺序、升级前检查、升级后检查、已知限制和本版本允许的回退方式。
3. 远程迁移前必须取得并验证升级前完整备份，记录备份清单摘要、迁移版本、存储模式和所需配置加密密钥版本；只生成备份但没有下载、加密和校验，不算具备回退条件。
4. 若迁移尚未执行，或者已执行迁移经过本版本演练证明旧 Worker 可以忽略新增结构，则允许只回退 Worker 代码，已经应用的向前迁移保留。
5. 若迁移改写或删除旧代码依赖的数据、改变公共约束，或者升级后数据检查失败，不允许在原生产资源上尝试逆向修复。使用升级前完整备份恢复到迁移版本一致的全新空白 D1 与空白 KV/R2，六项恢复检查通过后再切换 Worker 绑定。
6. 回退目标不得覆盖原生产资源。切换成功前保留失败升级资源，停止继续写入，并记录资源标识、时间和影响；确认新目标正常后再由系统所有者单独决定何时删除旧资源。
7. 部署配置中的 `init_key`、配置加密主密钥、Provider 和通知相关外部凭据不属于 D1/KV/R2 完整备份，升级和恢复前必须在受保护位置单独确认能够重新配置。
8. 本地 `test:upgrade-rollback` 至少验证迁移顺序、升级前后外键、既有结构、既有表行数、代表性数据、新迁移约束和独立回退目标。它是发布前门槛，但不代替真实 Cloudflare Free 远程演练。
9. 当前 `0022` 是纯新增表、索引和触发器的兼容迁移。升级后若 Worker 代码需要回退，可以保留 `0022`；如数据检查失败，则仍执行完整空白资源恢复。

## 备选方案

1. 为每个迁移编写 `down` SQL：表面上回退快速，但 D1 与 KV/R2、搜索和 Queue 状态无法组成一个原子事务，容易产生部分降级，不采用。
2. 永远只回退 Worker 代码：对兼容的新增结构有效，但遇到破坏性数据变化无法恢复用户数据，不采用为通用策略。
3. 直接把备份覆盖回当前生产资源：资源更少，但恢复过程中用户可能看到半套数据，失败后也缺少干净重试边界，不采用。
4. 只依赖 Cloudflare 平台恢复能力：可以作为额外保护，但不能替代 D1 与 KV/R2 的统一清单、对象引用检查和可移植本地备份，不采用为唯一方案。

## 后果

### 正面影响

1. 系统所有者能够根据故障类型选择较小的代码回退或完整数据恢复，不会把两者混为一谈。
2. 正式迁移历史保持不可变，失败升级不会诱发临时逆向 SQL 继续扩大损坏。
3. 完整恢复继续沿用已验证的空白资源边界和六项收口检查，任何失败都可以废弃目标后重新执行。
4. 每次发布都必须留下可执行说明和验证证据，非程序员不需要从提交记录猜测升级影响。

### 成本与限制

1. 完整数据回退需要额外的空白 Cloudflare 资源、对象回读时间和 Worker 绑定切换，不能承诺瞬时完成。
2. 备份发生后到停止旧资源写入之间的新数据可能不在升级前备份中，正式演练需要明确维护窗口和可接受的数据恢复点。
3. 当前本地工具使用隔离 SQLite/D1 兼容演练验证迁移与快照逻辑；真实远程 D1、KV/R2、Queue 和绑定切换仍需发布前执行。
4. 单 Worker 部署没有自动蓝绿切换控制面，远程资源切换需要系统所有者依据手册明确执行。

## 验证方式

1. 从前一正式迁移重建带代表性数据的数据库，应用当前最新迁移并检查外键为零。
2. 比较升级前后的既有结构摘要、全部既有表行数和代表性业务数据摘要。
3. 验证新迁移的约束和状态转换。
4. 从升级前快照建立独立回退目标，确认迁移版本、代表性数据和外键恢复，且不包含升级后结构。
5. 在真实 Cloudflare Free 隔离资源重复完成备份、迁移、检查、代码回退和空白资源恢复，再允许首发发布。
