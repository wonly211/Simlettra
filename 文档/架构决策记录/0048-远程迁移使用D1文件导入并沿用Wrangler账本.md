# 0048 远程迁移使用 D1 文件导入并沿用 Wrangler 账本

## 状态

已接受

- 决定日期：2026-08-13

## 背景

正式迁移包含表、索引、数据回填和 SQLite 触发器。2026-08-13 首次真实 Cloudflare Free 部署时，`wrangler d1 migrations apply` 已成功应用 `0001` 至 `0003`，但在通过远程查询接口提交 `0004` 时返回 `incomplete input`。同一个未经修改的 `0004` 文件通过 `wrangler d1 execute --file` 导入到临时远程 D1 后完整成功，证明 SQL 内容和远程 D1 运行时兼容，问题位于 Wrangler 当前版本的远程命令字符串执行通道。

项目仍需要保持正式 SQL 文件只增不改、唯一迁移账本、逐个迁移失败回滚和重复执行跳过已应用版本，不能通过手工执行 SQL 后单独修改账本来绕过失败。

## 决定

1. `migrations/` 中按编号排列、只增不改的 SQL 文件继续作为数据库变更历史的权威记录。
2. `d1_migrations` 继续作为唯一生产迁移账本，表结构与 Wrangler 默认账本一致。
3. 本地迁移继续使用 `wrangler d1 migrations apply --local`。
4. 远程迁移使用项目工具 `tools/远程正式迁移.mjs`，逐个调用 `wrangler d1 execute --remote --file` 的 D1 文件导入通道。
5. 每个临时导入文件由原始迁移 SQL 和末尾一条账本插入组成；Cloudflare 文件导入失败时，业务结构与账本记录一起回滚。
6. 工具执行前要求远程账本必须是当前正式迁移目录的连续前缀；出现未知、缺失、重排或跳号时立即停止。
7. 工具执行后重新读取完整账本并与正式迁移目录逐项比较，不一致时视为失败。
8. 禁止手工跳过正式迁移、单独补写账本、使用 `drizzle-kit push` 或建立第二套迁移账本。

本决定取代 [ADR 0012](0012-采用Drizzle查询层和Wrangler迁移账本.md) 中“生产只使用 `wrangler d1 migrations apply` 应用”的具体执行通道；ADR 0012 关于正式 SQL、唯一 Wrangler 账本、只增不改、失败回滚和禁止并行迁移体系的其他结论继续有效。

## 备选方案

1. 改写已经进入正式序列的历史触发器：没有必要，真实文件导入已经证明原始 SQL 可执行，而且会破坏只增不改原则。
2. 手工逐条执行并最后补写账本：无法保证迁移内容和账本原子一致，不采用。
3. 等待未来 Wrangler 版本修复后再发布：会阻塞已完成产品上线，且不能保证修复时间，不采用。
4. 使用新的自定义迁移表：会形成第二套账本并增加升级分歧，不采用。

## 后果

### 正面

1. 复杂触发器通过真实 D1 已验证的文件导入通道执行。
2. 正式 SQL 文件、编号、账本结构和重复执行行为保持不变。
3. 每个迁移的业务变化和账本插入位于同一次文件导入，失败不会留下半个已记录迁移。
4. 后续 Wrangler 修复后仍可根据真实远程验证决定是否恢复默认命令，而不需要迁移账本。

### 负面

1. 项目需要维护一段很小的远程迁移编排工具。
2. Wrangler 或 D1 文件导入行为升级时需要重新进行真实远程演练。
3. 文件导入期间目标 D1 暂时不可用，仍必须选择维护窗口并先完成备份。

## 验证方式

1. 在空白远程 D1 从 `0001` 顺序应用到当前最新迁移，账本逐项一致。
2. 对同一目标重复运行时不再次执行任何迁移。
3. 故意使某个迁移失败，确认该迁移的结构和账本记录都未留下。
4. 迁移后执行 `PRAGMA foreign_key_check` 并要求返回零行。
5. 继续运行本地升级回退、备份恢复、旧系统迁移和完整测试门槛。
