## 背景

Simlettra 是由系统所有者自行部署的单管理员应用。唯一管理员既能控制 Cloudflare 账号和 Worker，也负责 Provider、通知、备份和恢复配置。把 `INIT_KEY` 与配置主密钥设置为管理员保存后无法回看的 Secret，并用本机 DPAPI 再包一层，只增加部署和恢复步骤，并不能形成独立可信边界。

Cloudflare Workers Builds 支持从“创建 Worker”页面连接 GitHub 仓库，并在推送后执行构建与部署。项目正式发布后应让非程序员主要通过这一入口完成安装和更新，同时避免把真实资源编号、运行密钥或第三方凭据提交到公共或私有仓库。

## 决定

1. 配置加密主密钥的唯一运行时绑定名改为 `CONFIG_KEY`，不保留旧名兼容分支，避免配置长期存在两套名称。
2. `INIT_KEY` 与 `CONFIG_KEY` 由唯一管理员在 Cloudflare Worker 的运行时变量页面以可查看文本变量保存。项目不再把“管理员不能回看”作为安全目标。
3. 两把运行密钥不进入仓库的 `wrangler*.jsonc`、GitHub 构建变量、源码快照或日志。Wrangler 配置使用 `keep_vars: true`，保留管理员在 Cloudflare 控制台设置的运行时变量。
4. `CONFIG_KEY` 仍是 32 字节随机值的 Base64 编码，并继续使用 AES-GCM 保护 D1 中的动态凭据。D1 静态加密防范数据库副本、普通导出或误读直接暴露可用凭据，不防范拥有 Cloudflare 和系统管理员权限的人。
5. 正式全新部署的首选路径为 Cloudflare 控制台连接 GitHub。此项最初要求 Workers Builds 的部署命令使用 `pnpm run deploy:github`，后由 ADR 0051 取代为兼容 Cloudflare 默认构建和部署命令。
6. 本记录最初要求 GitHub 部署使用 Worker、D1、Queue 和对象存储资源变量生成临时 Wrangler 配置；这些资源已由 ADR 0052 取代为按实际 Worker 项目名称自动创建或复用，运行密钥边界继续有效。
7. 自动部署在空白 D1 上使用 ADR 0048 的文件导入通道应用全部正式迁移。目标已有业务表时只允许迁移账本与当前代码完全一致；否则停止部署，防止代码在未备份、未检查的情况下先于数据库升级。
8. 本地 `pnpm deploy:r2`、`pnpm deploy:kv` 和远程迁移工具继续保留，服务于开发、真实验收、受控升级和排错。

## 备选方案

1. 继续使用 Cloudflare Secret：保存后不能回看，与可信管理员和易维护目标不符，不采用。
2. 把两把密钥提交到私有 GitHub 仓库：私有仓库仍会扩大复制、构建和日志边界，不采用。
3. 取消 D1 动态凭据加密：实现更少，但任何 D1 副本都会直接包含 Provider 和用户通知的可用凭据，不采用。
4. 自动升级所有已有 D1：会绕过项目已经接受的备份、数据检查和回退流程，不采用。
5. 完全删除 Wrangler 路径：迁移、恢复、远程验收和故障处理仍需要可审计的命令行工具，不采用。

## 后果

### 正面

1. 唯一管理员可以在 Cloudflare 控制台直接确认和修改两把运行密钥，不再依赖 DPAPI 文件或一次性复制脚本。
2. 非程序员的默认部署入口与 Cloudflare 控制台和 GitHub 更新流程一致。
3. 运行密钥、资源编号和源码各自处于清楚的配置层，Git 仓库不需要保存真实部署配置。
4. 全新部署可以自动建立空白 D1，已有系统升级仍保留人工安全门槛。

### 成本与限制

1. 能进入 Cloudflare Worker 配置页面的人可以看到 `INIT_KEY` 与 `CONFIG_KEY`；这是唯一管理员主动承担的信任边界。
2. Cloudflare 构建页面需要填写若干非敏感资源变量，填错时部署会停止。
3. GitHub 自动部署不能替代升级备份、远程恢复演练和真实邮件验收。

## 验证方式

1. 运行代码、配置模板和当前操作文档不再使用旧变量名 `CONFIG_ENCRYPTION_KEY_V1`；旧名只允许出现在明确的历史取代说明中。
2. R2 与 KV 构建均能读取 `CONFIG_KEY`，全部凭据加解密、邀请码和资源 Token 测试继续通过。
3. 生成的 GitHub 部署配置包含选定资源绑定和 `keep_vars: true`，但不包含 `INIT_KEY`、`CONFIG_KEY` 或第三方凭据。
4. 空白远程 D1 能自动应用全部正式迁移；迁移版本落后的已有 D1 必须拒绝自动部署。
5. Cloudflare 控制台连接 GitHub 后能够完成构建、部署和后续推送更新，且管理员设置的运行时变量仍存在。
