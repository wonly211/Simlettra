# 0050 公开仓库只包含部署必需文件

## 状态

已接受

- 决定日期：2026-08-14
- 依据：用户要求先建立公开部署测试仓库，并且只上传部署所需文件
- 关联：[0049 采用可信管理员可见变量和 Cloudflare 连接 GitHub 部署](0049-采用可信管理员可见变量和Cloudflare连接GitHub部署.md)

## 背景

完整开发仓库包含自动化测试、验证性原型、内部研发记录、验收证据、项目级 Skill 和本地运维配置。公开 GitHub 仓库当前的主要用途是让部署者在 Cloudflare“创建 Worker”页面连接并测试 Simlettra，而不是公开全部研发工作区。

直接推送完整开发目录会扩大公开信息范围，也会让 Cloudflare 构建下载和处理不参与部署的文件。只复制构建产物又无法让 Cloudflare 根据 GitHub 源码完成类型检查、D1 迁移和 Worker 部署。

## 决定

1. 公开 `Simlettra` 仓库作为部署分发仓库，只包含 Vue 与 Worker 源码、正式 D1 迁移、R2/KV Wrangler 模板、构建配置、部署工具、锁文件和简体中文部署说明。
2. 不上传内部测试、验证性原型、研发与验收文档、`AGENTS.md`、项目级 Skill、开发快照、本地资源配置、Cloudflare 登录配置、密钥、日志、依赖和构建产物。
3. 使用 `tools/生成公开部署仓库.mjs` 从完整开发仓库按白名单生成独立目录，禁止人工从工作区随意复制。
4. 公开目录必须在全新依赖安装后分别通过 R2 与 KV 类型检查、生产安全构建和部署配置自检，才能提交或推送。
5. GitHub 部署入口不运行内部完整测试集；它生成当前存储模式的 Cloudflare 类型，检查 Vue 与 Worker TypeScript，保护 D1 迁移版本，执行生产安全构建和部署配置检查。完整自动化仍是开发仓库发布前门槛。
6. 公开仓库当前标明为开发测试版，不创建正式 Release，也不声称已经完成首发验收。

## 备选方案

1. 推送完整开发仓库：最简单，但不符合只上传部署文件的要求，不采用。
2. 只上传 `dist`：文件更少，但失去可审查源码、D1 迁移和 Cloudflare Git 构建能力，不采用。
3. 手工维护两套代码：容易出现遗漏和版本漂移，不采用。

## 后果

### 正面

1. 公开仓库内容更小，部署者看到的文件都与安装或运行直接相关。
2. 本地密钥、真实资源编号和内部研发材料具有明确的自动排除边界。
3. Cloudflare 仍能从 GitHub 完成类型检查、空白 D1 迁移、构建和部署。

### 成本与限制

1. 完整开发仓库与公开部署仓库是两个边界，发布前必须重新生成并测试，不能直接复制差异。
2. 公开仓库不包含完整自动化证据，不能单独证明版本满足正式发布门槛。
3. 当前没有开源许可证，公开可见不代表授予复制、修改或再分发许可。

## 验证方式

1. 公开目录不存在禁止路径和旧变量名，且不包含 `.dev.vars` 中的已知本地密钥值。
2. 使用锁文件完成全新安装后，`pnpm check` 在 R2 与 KV 模式均通过。
3. 两种模式生成的 GitHub 部署配置不包含 `INIT_KEY`、`CONFIG_KEY` 或第三方凭据。
4. Git 提交清单与生成目录一致，不包含被忽略文件。
5. GitHub 仓库为公开可见，默认分支为 `main`，README 明确开发测试边界。
