# 0052 构建阶段幂等创建命名存储资源

## 状态

已接受

- 决定日期：2026-08-14
- 依据：[需求变更-0012](../需求/变更记录/0012-确定部署资源自动创建与命名规则.md)
- 取代关系：取代 [ADR 0049](0049-采用可信管理员可见变量和Cloudflare连接GitHub部署.md)第 6 项中手工提供 D1、KV/R2、Queue 真实编号或名称的部分，并细化 [ADR 0051](0051-让Cloudflare默认构建命令生成真实部署配置.md)的资源准备方式

## 背景

Cloudflare Wrangler 支持在资源绑定不完整时自动供应 D1、KV、R2 和 Queue，但 Cloudflare 官方明确说明该自动供应机制目前不受 Cloudflare Vite 插件直接支持。Simlettra 的生产构建必须先交给 Vite 插件生成单 Worker 与网页资产，因此不能简单删除 `database_id` 或 KV `id` 后等待最终部署自动补齐。

用户要求 Cloudflare Git 部署自动创建 D1、KV/R2 与 Queue。D1 与 KV/R2 使用 `simlettra-<Worker项目名称>-<meta|raw>`，Queue 使用 `simlettra-<Worker项目名称>-tasks`。实现需要在 Vite 构建前完成资源准备，再把真实编号和名称交给现有安全构建、迁移和部署检查。

## 决定

1. Cloudflare Workers Builds 优先读取平台自动提供的 `WRANGLER_CI_OVERRIDE_NAME` 作为实际 Worker 项目名称；本地或自定义流水线可以用 `SIMLETTRA_WORKER_NAME` 显式提供名称。
2. D1 名称为 `simlettra-<Worker项目名称>-meta`，KV 命名空间或 R2 存储桶名称为 `simlettra-<Worker项目名称>-raw`，Queue 名称为 `simlettra-<Worker项目名称>-tasks`。
3. 构建工具先列出账号中的目标类型资源并按完整名称精确匹配。存在时复用，不存在时调用对应 Wrangler 创建命令，随后重新列出并取得真实编号或确认名称。
4. 创建命令失败后必须重新查询一次；若目标已由并发构建创建则复用，否则保留原错误并停止。
5. R2 存储桶和 Queue 名称必须满足小写字母、数字和连字符规则及各自长度限制。项目不截断或散列 Worker 名称；无法生成合法名称时要求部署者改用合法且足够短的 Worker 项目名称。
6. 资源准备结果写入一次性临时 Wrangler 配置：D1 同时写入真实 `database_name` 与 `database_id`，KV 写入真实 `id`，R2 写入真实 `bucket_name`。
7. 临时配置生成后继续执行类型检查、空白 D1 正式迁移、已有 D1 版本保护、安全构建和最终部署配置自检。
8. 资源创建不是跨 D1、KV/R2、Queue 的原子事务。后续步骤失败时保留已创建资源，下一次构建按名称复用，不自动回滚删除。

## 备选方案

1. 直接在 Vite 使用的 Wrangler 配置中省略资源编号：官方当前不支持 Vite 插件自动供应，不采用。
2. 继续要求部署者手工创建并复制全部编号：步骤多且首次测试已经出现占位编号错误，不采用。
3. 使用 Cloudflare REST API 自行实现资源客户端：需要额外维护认证、分页、错误协议和 API 版本，Wrangler 已提供稳定命令，不采用。
4. 失败时自动删除刚创建的资源：无法确认资源是否已被并发流程复用或写入，存在误删风险，不采用。
5. 超长名称自动截断或追加散列：会破坏用户确认的可预测命名规则，不采用。

## 后果

### 正面

1. 普通部署者只需选择存储模式，不再复制 D1、KV、R2 或 Queue 编号和名称。
2. 同一 Worker 的资源名称固定、可识别，失败重试不会产生多份随机资源。
3. Vite 插件继续接收完整真实配置，现有构建与迁移保护无需降低。

### 成本与限制

1. Workers Builds 必须拥有列出和创建所选 Cloudflare 存储资源及 Queue 的权限。
2. 第一次构建会多出资源查询和创建请求；已有资源的后续构建只执行查询。
3. 某一资源创建成功后其余步骤仍可能失败，账号中会留下可安全复用或由管理员确认后删除的空资源。
4. Worker 项目名称加固定前后缀后必须满足 R2 的 63 字符限制。

## 验证方式

1. 模拟空账号时，R2 模式创建并返回 `<meta D1, raw R2, tasks Queue>`，KV 模式创建并返回 `<meta D1, raw KV, tasks Queue>`。
2. 模拟已存在资源时不执行创建命令，并返回现有真实编号。
3. 模拟并发创建冲突时，创建失败后重新查询能够复用目标资源。
4. 非法或过长 Worker 名称在任何创建命令前失败。
5. 最终 R2 与 KV 配置分别只包含当前模式的对象绑定，且不包含运行密钥。
6. 在真实 Cloudflare Free 账号中从空资源开始完成一次 R2 和一次 KV 自动创建、迁移、构建与部署。
