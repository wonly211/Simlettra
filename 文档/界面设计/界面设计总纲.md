## 设计目标

Simlettra 的界面定位为“澄明工作台”：现代、安静、清晰，保留少量书信气质，但不使用仿纸、古风或装饰性国风。

用户打开系统后首先感受到的是邮箱，而不是账号后台。个人地址、组织地址和待认领邮件是不同的邮箱范围；设置和系统管理按事情分类，不与日常收发邮件争夺首屏空间。

## 已确认的整体结构

### 桌面

桌面采用全高三栏邮件工作区：

```text
┌ 顶栏：品牌 │ 搜索 │ 同步状态 │ 账户菜单 ┐
├────────────┬────────────────┬────────────────────┤
│ 邮箱导航   │ 邮件列表       │ 阅读或写信         │
│ 约 224 px  │ 400 至 440 px  │ 使用剩余宽度       │
└────────────┴────────────────┴────────────────────┘
```

- 登录后直接进入收件箱，不展示账号大标题。
- 左栏承载写邮件、系统文件夹、邮箱范围和设置入口。
- 中栏承载当前范围的搜索、筛选、批量选择和邮件列表。
- 右栏承载邮件详情、会话、附件、回复或写信。
- 组织不是独立后台，而是用户可以切换的邮箱范围。

### 手机

手机采用单栏分层，不把桌面三栏压缩到窄屏：

```text
邮件列表 → 邮件详情 → 回复或写信
```

- 邮箱文件夹与邮箱范围放入导航抽屉。
- 邮件、写信和设置是三个主要入口。
- 邮件详情和写信使用独立全屏页面。
- 浏览器返回键和界面返回按钮遵循同一层级。

## 信息层级

### 日常邮件

- 一级入口：收件箱、星标、草稿箱、已发送、归档。
- 次级入口：垃圾邮件、垃圾箱、全部邮件，放入“更多”。
- 特殊入口：“未分配来信”在界面中使用更易理解的名称“待认领邮件”，只对有权限的用户显示。
- 邮箱范围：全部个人邮件、具体个人地址、组织邮箱，使用独立选择器表达，不与文件夹混排。

### 设置

- 个人：账户与安全、邮箱地址、自动转发、外部通知、邮件导出。
- 协作：组织与邀请。
- 系统管理：运行健康、用户与邀请码、域名与收信、域外发信、地址策略、存储与资源。
- 系统管理只对唯一系统管理员显示。

## 视觉方向

### 色彩

| 用途     | 建议色值  |
| -------- | --------- |
| 页面底色 | `#F5F7F6` |
| 主表面   | `#FFFFFF` |
| 次级表面 | `#EFF3F1` |
| 主文字   | `#18221F` |
| 次文字   | `#56645F` |
| 弱文字   | `#77837F` |
| 普通边界 | `#D8DFDC` |
| 强边界   | `#BBC7C2` |
| 品牌绿   | `#176B5B` |
| 品牌悬停 | `#125548` |
| 品牌浅色 | `#E5F0ED` |
| 信息蓝   | `#2F6F91` |
| 警告琥珀 | `#99620E` |
| 危险朱红 | `#B2423C` |

颜色只表达品牌、选择状态、信息、警告和危险，不为每个普通状态增加彩色徽章，也不使用大面积同色渐变。

### 字体与形状

- 正文和控件使用可靠的系统无衬线中文字体。
- 品牌“澄笺”可以使用高质量宋体字标；无法稳定提供字体时使用无衬线，不回退到 `SimSun`。
- 控件圆角为 6 px，弹窗和重复项目最多 8 px。
- 阴影只用于菜单、弹窗、抽屉和其他浮层。
- 普通页面分区优先使用留白和表面层级，减少密集边框。

## 核心交互原则

- 每个页面只有一个最明确的主要动作。
- 邮件详情优先显示回复和回复全部，低频动作进入“更多”。
- 写信时“发送”是唯一主按钮，自动保存状态保持可见但不抢夺注意力。
- 批量操作在进入选择模式后出现，不让复选框长期占据手机列表宽度。
- 危险操作必须说明具体影响并再次确认，默认焦点放在取消操作。
- 桌面和手机提供相同能力，只调整呈现层级，不因屏幕较小而删除功能。

## 可访问性基线

- 手机主要触控区域不小于 44 × 44 px。
- 手机表单文字不小于 16 px，避免 iPhone Safari 聚焦时自动缩放。
- 普通文字对比度至少为 4.5:1，控件与焦点边界至少为 3:1。
- 所有键盘操作具有清晰焦点框。
- 打开邮件、写信和确认界面后移动焦点；返回后恢复到原触发位置。
- 状态不能只依靠颜色表达。
- 放大至 200% 后仍能完成主要流程。
