# 第二批界面设计确认清单

## 确认信息

- 批次状态：已确认
- 确认日期：2026-08-14
- 确认方式：用户回复“第二批 UI 设计全部按推荐”
- 影响范围：邮件工作区、邮件列表、阅读区和相关状态

本批只确认邮件工作区的具体表现，不改变邮件权限、存储、搜索或收发规则。

## 确认清单

| 编号  | 要确定的事情           | 已确认方案                                                                                                                            | 用户会感受到的结果                                 | 状态   |
| ----- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------ |
| UI-09 | 顶栏放什么             | 左侧显示品牌，中间提供搜索入口，右侧显示同步状态与账户菜单；移除账号大标题和“邮件/设置”页签                                           | 打开后首屏立即是邮箱，账号信息不再抢占空间         | 已确认 |
| UI-10 | 左侧导航顺序           | 顶部为醒目的“写邮件”，随后依次显示收件箱、星标、草稿箱、已发送、归档；垃圾邮件、垃圾箱和全部邮件收入“更多”；设置固定在底部            | 最常用入口始终最容易找到，低频入口不制造拥挤       | 已确认 |
| UI-11 | 邮箱范围怎样切换       | 文件夹与邮箱范围分开；默认显示“全部个人邮件”，个人地址和组织邮箱通过独立选择器切换；有权限时显示“待认领邮件”                          | 用户能清楚知道自己正在查看个人邮箱还是某个组织邮箱 | 已确认 |
| UI-12 | 邮件列表每行显示什么   | 第一行显示发件人和时间，第二行显示主题，第三行显示正文摘要；只有别名或组织等有辨识价值时才显示简短标签，完整投递地址放在详情中        | 列表更安静，一屏可以更快比较多封邮件               | 已确认 |
| UI-13 | 未读和当前邮件怎样表现 | 未读使用粗体和小圆点；当前邮件使用浅品牌色背景和左侧 2 px 标识；不同时叠加多种高亮                                                    | 用户能迅速识别未读与正在阅读的邮件                 | 已确认 |
| UI-14 | 搜索与筛选怎样出现     | 列表顶部保留简洁搜索框，默认搜索当前邮箱范围；组合条件通过筛选面板打开，条件生效后显示数量与可清除摘要                                | 常用搜索简单，复杂搜索仍完整保留                   | 已确认 |
| UI-15 | 批量操作怎样进入       | 桌面可保留行选择框；手机通过“选择”进入批量模式后才显示选择框和批量工具栏                                                              | 桌面处理效率不降低，手机列表不长期被复选框挤占     | 已确认 |
| UI-16 | 阅读页保留哪些一级操作 | 顶部吸附工具栏只突出回复和回复全部；星标可直接操作；转发、标记未读、归档、垃圾邮件和删除进入“更多”                                    | 常用操作更清楚，危险操作不再与回复同等显眼         | 已确认 |
| UI-17 | 会话怎样阅读           | 会话按时间纵向排列；历史邮件默认折叠并显示发件人、时间和摘要，当前邮件展开；用户可以逐封展开                                          | 阅读顺序更接近正常邮件对话，不需要横向寻找         | 已确认 |
| UI-18 | 正文宽度怎样处理       | 阅读区使用剩余空间，普通纯文本与 Simlettra 编辑的内容保持舒适阅读宽度；外部 HTML 邮件在安全隔离区内按邮件自身布局显示，不强制压成窄栏 | 普通文字不横跨整屏，复杂外部邮件也不容易排版错乱   | 已确认 |
| UI-19 | 附件与远程图片怎样表现 | 远程图片提醒保留在正文前；附件使用稳定列表行，显示类型、名称、大小、预览和下载；图片附件可展开预览                                    | 安全提醒明确，附件更容易辨认和操作                 | 已确认 |
| UI-20 | 空白、加载和错误状态   | 首次加载使用不改变布局的骨架；空邮箱使用简短说明和相关动作；刷新失败保留已有邮件并在局部提示，不把整个页面替换成错误页                | 网络波动时页面更稳定，也不会让用户误以为邮件消失   | 已确认 |

## 本批不确认的内容

- 写信字段、工具栏、附件和自动保存的具体布局。
- 设置各分组的具体页面顺序。
- 手机底部导航、返回行为和详情底部操作栏的最终细节。
- 初始化与登录页面的品牌表现。

这些内容将在后续批次集中确认。
