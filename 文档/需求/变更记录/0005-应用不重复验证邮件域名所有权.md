# 需求变更-0005：应用不重复验证邮件域名所有权

## 状态

已接受，当前生效

- 提议与接受日期：2026-08-11
- 适用基线：[需求基线-0001](../需求基线.md)
- 影响需求：`2.05`、`4.01`
- 取代结论：需求基线中“已经验证所有权的邮件域名”由 Simlettra 自行验证的解释
- 架构决定：[0034 不在应用内重复验证邮件域名所有权](../../架构决策记录/0034-不在应用内重复验证邮件域名所有权.md)

## 背景

Simlettra 是由所有者自行部署和管理的单实例系统，系统只有一名可信的系统管理员。收信域名必须先在 Cloudflare Email Routing 中配置，站外发信域名及其凭据也已经由 Resend 或 SMTP2GO 的外部流程准备。用户明确指出，Simlettra 再要求 DNS TXT 所有权验证没有增加实际能力，只会重复外部平台职责并增加初始化步骤。

此前需求中的“已经验证所有权”只表达域名应当是部署者有权配置的域名，不再解释为产品必须自行建立域名所有权验证流程。

## 当前有效行为

1. Simlettra 不创建 DNS TXT 挑战，不查询 DNS 所有权记录，也不保存域名验证挑战或验证时间。
2. 唯一系统管理员可以在初始化或日常管理中直接添加邮件域名。
3. 添加域名时只校验输入是否合法、规范化后是否在当前系统中重复，以及是否满足地址与数据约束。
4. Cloudflare Email Routing 是否正确把来信交给 Worker，由部署配置和运行状态检查负责，不属于域名所有权验证。
5. Resend 或 SMTP2GO 的域名许可、服务密钥和发信能力由相应 Provider 负责；Simlettra 只保存管理员提供的配置并测试该配置是否能够正常使用。
6. 初始化可以直接创建首个域名、唯一管理员和管理员主邮箱，不以 DNS 验证为前置条件。
7. 域名进入系统后直接处于启用状态；以后可以暂停或进入删除流程，不设置“等待验证”状态。

## 数据与迁移影响

1. `mail_domains` 不保存 `verification_pending` 状态和 `verified_at` 字段。
2. 初始化事务不创建域名验证挑战表，也不执行外部 DNS 查询。
3. 旧系统迁移只迁移管理员选择并且格式合法的邮件域名，不要求补做 Simlettra 所有权验证。
4. 该变更发生在首份正式生产迁移建立之前，因此可以直接修正迁移草案，不需要生产数据回填。

## 影响与后续工作

1. 本变更不增减需求数量，当前仍为 161 项有效需求。
2. 初始化向导减少 DNS 记录步骤，只收集管理员、主邮箱、首个域名和存储模式等已确认信息。
3. 后续可以提供邮件路由和 Provider 配置的可用性检查，但检查结果只用于诊断，不改变域名所有权状态。
4. 当前需求、验收清单、目标架构、第一批数据模型和迁移草案需要同步移除域名验证表述。

## 不改变的结论

1. 只有系统管理员可以添加、停用和删除域名。
2. 一套系统仍可管理多个邮件域名，规范域名在系统内保持唯一且创建后不可修改。
3. 域名仍有关联地址或邮件时不能直接删除。
4. 邮箱地址、个人别名、组织地址、发信路线和月度配额规则保持不变。
5. 外部邮箱转发目标的验证码验证与 Provider 回调鉴权不属于域名所有权验证，本变更不修改这些能力。
