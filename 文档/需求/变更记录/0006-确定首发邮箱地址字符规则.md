# 需求变更-0006：确定首发邮箱地址字符规则

## 状态

已接受，当前生效

- 提议与接受日期：2026-08-11
- 适用基线：[需求基线-0001](../需求基线.md)
- 影响需求：`3.03`、`4.03`、`4.06`、`4.10`
- 架构决定：[0035 采用 ASCII 邮箱前缀与 IDNA 域名规范化](../../架构决策记录/0035-采用ASCII邮箱前缀与IDNA域名规范化.md)

## 背景

初始化必须创建管理员主邮箱，地址唯一性也依赖稳定的规范化规则。此前已经确认地址不区分大小写，但允许字符、国际化邮箱前缀和默认长度尚未收口，不能在实现中临时猜测。

用户于 2026-08-11 接受地址规则全部推荐方案。

## 当前有效行为

1. 首发邮箱前缀只允许小写英文字母 `a-z`、数字 `0-9`、点、下划线和连字符。
2. 邮箱前缀不能以点、下划线或连字符开头或结尾，不能包含连续两个点。
3. 首发不支持空格、引号、加号以及中文等非 ASCII 邮箱前缀。
4. 邮件域名可以使用国际化域名；系统把域名转换为小写 ASCII Punycode 作为规范值，并保留原始域名用于显示。
5. 邮箱前缀和规范地址统一转为小写保存及显示；仅大小写不同的地址视为同一地址。
6. 邮箱前缀允许 1 至 64 个字符；管理员以后可以提高新地址的最短长度，但不能超过 64。
7. 首发默认不预先阻止 `admin`、`postmaster`、`abuse` 等名称；管理员初始化后可以自行配置禁止文字和保留名称。

## 数据与迁移影响

1. `mail_domains.canonical_name` 保存小写 ASCII Punycode，`display_name` 保存经过清理的显示域名。
2. `email_addresses.display_address` 和 `canonical_address` 使用小写规范前缀及规范域名组合。
3. 当前首份正式迁移尚未发布，不需要对生产地址执行回填。
4. 以后改变允许字符、大小写规则或国际化邮箱前缀范围时，必须建立新需求变更、架构决策和显式迁移。

## 影响与后续工作

1. 本变更不增减需求数量，当前仍为 161 项有效需求。
2. 初始化、用户创建、别名、组织地址、全域认领和主地址迁移必须复用同一规范化函数。
3. 浏览器和 API 返回相同的简体中文校验错误，不能依靠数据库约束生成用户提示。
4. 测试必须覆盖大小写、连续点、首尾分隔符、中文前缀、国际化域名和规范值冲突。

## 不改变的结论

1. 主地址、个人别名和组织地址继续共用全局唯一命名空间。
2. 地址创建后不能修改，显示名称仍可修改。
3. 管理员仍可设置更高的最短长度、禁止文字和保留名称。
4. 域名所有权不由 Simlettra 重复验证。
