# 需求变更-0007：确定新用户个人别名默认额度

## 状态

已接受，当前生效

- 提议与接受日期：2026-08-12
- 适用基线：[需求基线-0001](../需求基线.md)
- 影响需求：`4.04`、`4.05`、`4.09`
- 架构决定：[0036 以独立用户策略管理个人别名权限与额度](../../架构决策记录/0036-以独立用户策略管理个人别名权限与额度.md)

## 背景

需求已经确认管理员可以为不同用户设置个人别名数量上限，并且用户默认可以在额度内自行创建别名，但此前没有确定新用户的默认额度。正式实现和数据迁移不能临时猜测这个数值。

用户于 2026-08-12 确认：新用户的个人别名上限默认设为 20。

## 当前有效行为

1. 初始化建立的唯一系统管理员和以后创建的普通用户，个人别名额度默认都是 20 个。
2. 用户默认允许在当前额度内自行创建个人别名。
3. 管理员可以分别调整每名用户的个人别名额度和是否允许自行创建。
4. 管理员创建并分配给用户的个人别名同样占用该用户额度，管理员不能绕过额度制造超额地址。
5. 管理员把额度调低到当前已用数量以下时，不自动删除或停用已有别名；用户和管理员都不能继续新增，直到已用数量低于新额度或管理员再次提高额度。

## 数据与迁移影响

1. 每名用户保存独立的个人别名策略，不把额度和自助创建权限混入账号登录状态。
2. 升级时为已有用户建立默认额度 20、允许自助创建的策略记录。
3. 新建用户和首次初始化必须在同一原子操作中建立策略记录，不能产生没有别名策略的活动用户。
4. 当前别名数量只计算仍属于该用户的个人别名，不包括主地址、组织共享地址或已经结束归属的历史地址。

## 影响与后续工作

1. 本变更只补充既有需求的默认值，不增减需求数量，当前仍为 161 项有效需求。
2. 别名创建、全域认领和主地址迁移中“旧地址保留为别名”的流程都必须使用同一额度规则。
3. 网页应同时显示已用数量、当前上限和是否允许自行创建。

## 不改变的结论

1. 主地址、个人别名和组织地址继续共用全局唯一命名空间。
2. 地址创建后不能修改。
3. 个人别名默认删除后立即释放；管理员以后仍可把保留期设置为 0 至 30 天。
4. 邮箱地址字符和域名规范化继续以需求变更 `0006` 为准。
