# 需求变更-0011：确定可信管理员密钥与 GitHub 部署规则

已接受，当前生效

- 提议与接受日期：2026-08-14
- 适用基线：[需求基线-0001](../需求基线.md)

## 背景

每套 Simlettra 只有一名系统管理员，该管理员也是部署者和系统安全的直接责任人。先前部署资料把 `INIT_KEY` 和配置加密主密钥设计为管理员保存后无法在 Cloudflare 控制台回看的 Secret，并为本机 `INIT_KEY` 增加 DPAPI 密文与复制脚本。用户明确认为这把可信管理员错误地当成了需要防范的对象，增加了记忆、备份和恢复负担。

正式发布后，绝大多数部署还会在 Cloudflare 的“创建 Worker”页面连接 GitHub 仓库，由 Workers Builds 在代码更新时构建和部署，而不是要求非程序员在本机长期维护 Wrangler CLI 部署环境。

## 当前有效行为

1. 唯一系统管理员对 `INIT_KEY`、`CONFIG_KEY`、Provider 凭据、通知凭据和 Cloudflare 只读 Token 的安全直接负责，产品不额外阻止管理员查看或管理这些值。
2. Cloudflare 控制台中的 `INIT_KEY` 与 `CONFIG_KEY` 使用管理员可查看、可编辑的运行时文本变量。它们不得提交到 GitHub、进入构建日志、普通日志或公开文档。
3. 配置主密钥的变量名固定为 `CONFIG_KEY`；旧名 `CONFIG_ENCRYPTION_KEY_V1` 不再受支持。
4. `CONFIG_KEY` 仍用于加密 D1 中动态保存的 Provider、通知、Cloudflare 只读 Token 和邀请码副本。这一层加密用于避免 D1 副本直接成为可用凭据集合，不是为了防止系统管理员查看。
5. 正式发布的默认全新部署入口是 Cloudflare 控制台“创建 Worker”并连接 GitHub 仓库。Cloudflare 从 GitHub 拉取代码，执行项目部署命令并部署到连接的 Worker。
6. 本记录最初要求 D1、KV/R2、Queue 名称和资源编号作为非敏感 Cloudflare 构建变量提供；这些资源已由需求变更-0012取代为按 Worker 项目名称自动创建或复用。`INIT_KEY`、`CONFIG_KEY` 不作为构建变量传给 GitHub 构建。
7. GitHub 自动部署只为完全空白 D1 自动应用全部正式迁移。已有系统的迁移版本不等于当前代码时自动停止，管理员必须先按升级手册完成备份、迁移、检查和回退准备。
8. 本地 Wrangler 命令继续作为开发、迁移、恢复、升级演练和高级排错工具，不再是普通部署者的默认安装路径。

## 取代的旧结论

1. “`INIT_KEY` 与配置主密钥只能作为保存后不可回看的 Cloudflare Secret”已被取代；当前由可信管理员选择可查看的 Cloudflare 运行时文本变量并承担安全责任。
2. “需要用 Windows DPAPI 为管理员额外封装本机 `INIT_KEY`”已被取代；项目不再维护这套本机复制机制。
3. “正式首次部署默认在本机安装 Node.js、pnpm、Wrangler 后手工部署”已被取代；当前默认使用 Cloudflare 控制台连接 GitHub，CLI 作为高级路径保留。

## 不改变的结论

1. 普通用户不能访问系统级密钥和外部服务凭据。
2. 密钥、密码、会话令牌、邮件正文和附件仍不得进入 GitHub、构建日志和普通运行日志。
3. `INIT_KEY` 仍只用于首次初始化和管理员恢复；`CONFIG_KEY` 仍只用于动态配置凭据加密，二者不能互相替代。
4. D1 动态凭据继续使用认证加密保存，唯一管理员在网页中可以查看、复制、替换、删除和测试明文。
