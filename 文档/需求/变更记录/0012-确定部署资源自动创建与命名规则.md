# 需求变更-0012：确定部署资源自动创建与命名规则

## 状态

已接受，当前生效

- 提议与接受日期：2026-08-14
- 适用基线：[需求基线-0001](../需求基线.md)
- 影响需求：`2.05`、`2.09`
- 取代结论：[需求变更-0011](0011-确定可信管理员密钥与GitHub部署规则.md)中要求部署者把 D1、KV、R2 或 Queue 的真实编号或名称作为 Cloudflare 构建变量提供的结论

## 背景

首次 Cloudflare Git 部署证明，要求非程序员预先创建 D1、KV/R2 并复制编号会增加步骤，也容易让占位编号进入构建。用户明确要求：部署时自动创建 D1 与当前选择的 KV 或 R2 存储实例，并使用统一、可预测的名称。

## 当前有效行为

1. Cloudflare Git 全新部署根据当前 Worker 项目名称自动查找或创建一份 D1、一份当前模式的 KV 或 R2，以及一个 Queue。
2. D1 保存权威元数据，名称固定为 `simlettra-<Worker项目名称>-meta`。
3. KV 或 R2 保存原始邮件、正文、附件和其他对象，名称固定为 `simlettra-<Worker项目名称>-raw`。
4. Queue 承载异步任务，名称固定为 `simlettra-<Worker项目名称>-tasks`。
5. 名称中的 `<Worker项目名称>` 使用 Cloudflare 当前实际部署目标名称；本地或自定义流水线可以显式提供相同名称。
6. 已存在完全同名资源时直接复用，不创建第二份；资源不存在时才创建。并发部署导致另一流程先创建成功时，重新查找并复用。
7. Worker 名称无法生成合法 R2 或 Queue 名称，或生成结果超过 Cloudflare 长度限制时，部署在创建资源前停止并明确提示，不截断、不改写名称。
8. 自动创建后取得真实 D1 或 KV 编号，再生成供 Vite 和 Wrangler 使用的最终配置；仓库模板继续不保存真实资源编号。
9. 失败部署已经创建的资源不自动删除，防止误删可能已被复用或写入的数据；管理员确认资源为空且不再需要后自行删除。

## 取代的旧结论

1. 普通 Cloudflare Git 部署不再要求填写 `SIMLETTRA_D1_DATABASE_ID`。
2. R2 模式不再要求填写 `SIMLETTRA_R2_BUCKET_NAME`。
3. KV 模式不再要求填写 `SIMLETTRA_KV_NAMESPACE_ID`。
4. `SIMLETTRA_WORKER_NAME` 不再是 Cloudflare Workers Builds 必填变量；优先使用 Cloudflare 自动提供的实际 Worker 项目名称，本地或自定义流水线仍可显式设置。
5. 普通 Cloudflare Git 部署不再要求填写 `SIMLETTRA_QUEUE_NAME`。

## 不改变的结论

1. 系统仍只提供 `D1 + KV` 与 `D1 + R2` 两种部署方式。
2. D1、KV 和 R2 的 Cloudflare 免费额度仍是 Simlettra 的产品资源上限，不自动进入付费用量。
3. 已有 D1 的迁移版本与当前代码不一致时自动部署仍停止，必须先执行备份、迁移、检查和回退准备。
4. `INIT_KEY` 与 `CONFIG_KEY` 仍是 Worker 运行时文本变量，不进入 GitHub 构建变量。
