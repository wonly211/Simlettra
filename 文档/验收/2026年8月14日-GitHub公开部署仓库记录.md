1. Vue 网页、Worker、业务模块与共享契约源码；
2. `0001` 至 `0025` 的正式 D1 迁移；
3. R2 与 KV Wrangler 模板；

6. 简体中文 README 和本地变量示例。

## 首次真实部署与修复

1. Cloudflare 于 2026-08-14 成功完成依赖安装和 `pnpm run build`，随后使用默认 `npx wrangler deploy`。
2. 旧构建入口没有读取 `SIMLETTRA_*` 变量，最终配置仍引用全零 D1 编号，部署以错误代码 `10181` 停止；Worker 版本没有成功发布。
3. 失败前自动创建了旧模板名称 `simlettra-mail` R2 存储桶和 `simlettra-tasks` Queue。新规则不会复用这两个旧名；项目也不会自动删除它们，管理员确认它们为空且不再需要后可以删除。
4. 修复新增 Workers Builds 专用构建入口，本地仍执行普通安全构建；`WORKERS_CI=1` 时由默认 `pnpm run build` 生成真实资源配置、检查 D1 并为默认 `npx wrangler deploy` 保留重定向配置。
5. 后续需求变更-0012与 ADR 0052 进一步取消手工资源编号和名称，改为按 Worker 项目名称自动准备 `meta` D1、`raw` KV/R2 和 `tasks` Queue；本地命名、创建、复用和并发冲突模拟已经通过。
6. 公开仓库 `main` 已推送到 `cf35123901cfaf764861cc6fb8e75d411660ca05`；当前版本只需 `SIMLETTRA_STORAGE_MODE` 构建变量，并会按实际 Worker 项目名称自动创建或复用 `meta` D1、`raw` KV/R2 与 `tasks` Queue。GitHub 没有返回 Cloudflare 检查记录，本机浏览器也没有 Cloudflare 登录会话，因此真实重试结果仍需从 Cloudflare 构建页确认。
7. 第二次真实构建已经成功创建 `simlettra-simlettra-meta` D1、`simlettra-simlettra-raw` R2 和 `simlettra-simlettra-tasks` Queue；随后查询到新 D1 自带的 `_cf_KV`，旧判断误认为数据库已有业务数据并停止首次迁移。
8. 提交 `a1b58d09c31ee049382284f5d4770636e089e376` 只从业务表集合排除 Cloudflare 精确保留表 `_cf_KV`，未知 `_cf_*`、普通业务表和正式迁移账本仍保留。真实日志形状回归、边界自检、R2/KV 完整 `pnpm check` 和公开内容扫描已经通过。
