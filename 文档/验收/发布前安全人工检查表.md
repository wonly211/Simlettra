## 使用规则

本表用于真实 Cloudflare Free 隔离环境的发布前人工检查，不在生产邮箱或真实个人邮件上执行。每种存储模式至少填写一份副本，文件名使用简体中文并包含日期和存储模式，例如 `2026年8月14日-R2发布前安全检查.md`。

所有项目默认未通过。只有实际执行、留下脱敏证据并由验收人签署后才能勾选。不得在本文档、截图、终端记录或问题报告中保存密码、密钥、Token、Cookie、邀请码、完整邮件正文、附件内容、真实邮箱地址或可复用的回调凭据。

## 一、开始前门槛

- [ ] `pnpm check` 完整通过，没有跳过测试、迁移、恢复、性能、可访问性或安全构建。
- [ ] `pnpm test:security` 的 8 个文件、52 项回归通过。
- [ ] D1 最新迁移为 `0025`，`PRAGMA foreign_key_check` 返回零行。
- [ ] 使用隔离测试域名、虚构用户、无敏感内容邮件和专用 Provider 及通知账号。
- [ ] 验收资源、账号和命令均已复核，不会操作正式生产资源。
- [ ] 已准备随时停止 Worker、Queue consumer、Cron 和外部发送的手段。
- [ ] 已建立可校验的升级前完整备份，并确认全新资源恢复路径可用。

## 二、权限与数据隔离

- [ ] 普通用户访问系统管理员接口返回拒绝，不能查看用户、域名、资源、健康、Provider 或邀请码管理数据。
- [ ] 系统管理员不能通过产品界面读取或永久删除另一名普通用户的个人邮件。
- [ ] 用户不能读取、整理、下载或删除其他用户的个人邮件和附件。
- [ ] 组织普通成员只能看到组织地址实际收到或发出的邮件，不能看到其他成员个人邮箱。
- [ ] 普通成员不能永久删除组织原始邮件；创建者删除后所有成员立即失去访问。
- [ ] 成员退出组织后立即失去组织邮件访问，恢复页面、旧链接和附件链接均不能绕过。
- [ ] 禁用用户后登录、收信和发信停止，既有会话被撤销，但数据没有被误删。
- [ ] 直接修改请求中的用户、组织、邮箱条目、附件或导出编号不能越权访问。

## 三、不可信邮件内容

- [ ] 在 Chrome、Edge、Firefox 和 Safari 中分别打开包含脚本、事件属性、表单、内嵌框架和危险协议的 HTML 邮件，没有脚本执行或同源访问。
- [ ] 远程图片默认不请求；单封放行和可信发件人放行只影响获授权用户和预期范围。
- [ ] `javascript:`、伪造显示文字、跨域跳转和可疑链接不会获得额外信任，页面不会替邮件内容执行导航。
- [ ] 包含路径分隔符、控制字符、引号、换行和脚本字符的附件名不能改变下载目录或注入响应头。
- [ ] 常见图片预览保持隔离；未知类型按下载处理，不以内联脚本或 HTML 执行。
- [ ] 回复、转发和外部通知使用安全可见文本，不重新激活原邮件脚本内容。

## 四、凭据、令牌与日志

- [ ] 密码、`INIT_KEY`、`CONFIG_KEY`、Cloudflare Token、Provider 密钥和回调凭据没有进入 GitHub、构建变量或普通日志；唯一管理员可以在 Cloudflare 控制台查看两把运行密钥，并在网页中管理动态凭据。
- [ ] 会话和 CSRF 令牌不出现在 URL、`Location`、响应正文、会话列表、浏览器历史或普通日志。
- [ ] 账号邀请码不出现在 URL、错误响应、审计字段、Worker 日志或代理访问日志；管理员页面按已确认规则仍可查看。
- [ ] Worker、Email Routing、Queue、Cron、D1、KV/R2、Resend、SMTP2GO 和通知通道日志抽查不含完整正文、附件内容、地址簿数据或对象字节。
- [ ] 故意触发登录失败、注册失败、解析失败、Provider 超时、回调拒绝和后台任务失败，错误日志仍只包含安全错误代码及必要上下文。
- [ ] 截图、录屏、问题报告和验收记录已经人工复核，不包含可重放凭据或真实用户数据。
- [ ] 生产构建产物不包含 `.dev.vars`、已知密钥、测试凭据、本机绝对路径或无关环境的资源编号。

## 五、重复、重试与外部边界

- [ ] 同一 Email Routing 事件重复投递只形成一封物理邮件，失败重试不会出现半封可见邮件。
- [ ] 同一草稿、同一发送请求键和并发提交不会让同一收件人收到重复邮件。
- [ ] Resend 只使用相同幂等键重试；SMTP2GO 结果未知时停止自动重发。
- [ ] 默认 Provider 明确未接受时才切换兼容备用 Provider；结果未知时不切换。
- [ ] Resend Svix 和 SMTP2GO HTTPS Basic Auth 的伪造、过期、重复及乱序回调不能改坏发送状态。
- [ ] 通知和外部转发失败不影响原始来信，重复任务不产生重复通知或转发，转发环路被阻止。
- [ ] 登录、邀请码、发信、邀请和高成本操作的限速在真实 Worker 中生效，不会因伪造普通请求头轻易绕过。

## 七、停止条件

出现以下任一情况立即停止后续验收，并把当前判断记为“失败”或“阻塞”：

1. 发现越权访问、脚本执行、路径穿越、响应头注入、令牌或密钥泄露。
2. 已送达 Worker 的邮件静默丢失、出现半封可见邮件、附件缺失或重复发信。
3. 无效回调被接受，结果未知后发生自动切换或重发。
4. 日志、截图或报告出现完整正文、附件内容、密码、密钥、Token、Cookie 或邀请码。
5. 目标账号、资源或套餐无法确认，或控制台提示操作可能产生计划外费用。
6. 为让检查通过而需要关闭安全边界、降低需求、删测试或修改验收数据。

停止后先撤销暴露凭据、隔离受影响资源并保留脱敏证据。修复必须关联问题编号、修复版本和复验结果，不能只写“已处理”。
