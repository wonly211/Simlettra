## 运行路径判断

1. 该路径只属于开发依赖 `drizzle-kit`，不属于 Worker 或网页生产依赖。
2. `pnpm dev` 运行 Wrangler 迁移和 Vite，不启动 Drizzle Studio；Vite 当前使用已修复范围内的 `esbuild 0.28.1`。
3. `drizzle-kit` 只由 `pnpm db:generate` 调用；正式 D1 迁移仍由 Wrangler 的只增不改迁移账本管理。
4. R2 与 KV 生产产物均未发现 `0.18.20`、`@esbuild-kit`、`serve_other` 或相关开发服务器标识。
5. npm 官方仓库在审查日返回的最新稳定版仍为 `drizzle-kit 0.31.10`，并继续依赖 `@esbuild-kit/esm-loader`；当前没有可通过稳定版升级消除该链的上游版本。

## 当前处理决定

不对 `@esbuild-kit/core-utils` 的固定依赖强行覆盖到不符合其声明范围的新 `esbuild`，避免用未经上游支持的组合换取表面上的零告警。当前采取以下限制：

1. 不运行或对网络开放 `drizzle-kit studio`、esbuild `serve` 或来自该旧依赖链的任何开发服务器。
2. `pnpm db:generate` 只在可信本机、项目根目录和无需对外监听的环境执行。
3. 正式部署不携带开发依赖，生产安全构建继续扫描产物。
4. 上游发布移除旧链的稳定版后，单独评估升级并重跑迁移生成、类型、测试和生产构建。

这一决定只接受当前中等开发工具风险，不接受任何生产、高危或严重风险。若后续审计发现风险进入生产依赖、高危或严重级别，立即停止发布，不能仅靠本文继续接受。

## 发布前重查

每次正式发布、依赖变更或安全公告更新后重新执行：

```powershell
pnpm audit --prod
pnpm audit
```

第一条必须保持零已知风险。第二条若仍有中低风险，必须逐项更新本文的实际路径、可利用条件、上游状态和接受人；高危或严重风险必须先修复。网络或 npm 公告接口不可用时只能记录“阻塞”，不能写成“零风险”。
