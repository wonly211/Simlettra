# 澄笺 | Simlettra KV 与 R2 故障恢复验证计划

## 文档状态

- 状态：当前
- 建立日期：2026-08-10
- 对应总计划：`验证-03`
- 目的：验证 D1 与 KV/R2 之间发生部分失败时，邮件不会半成品可见，重试不会重复写入，永久删除和对象对账能够继续完成

## 已接受前提

1. D1 保存唯一权威状态，KV 或 R2 只保存不可变邮件对象。
2. 对象写入完成不代表邮件可见；全部必要对象存在后，才通过 D1 事务建立可见邮箱条目。
3. Queue 只负责唤醒，D1 任务表保存权威任务状态；定时任务可以重新投递遗漏任务。
4. R2 是默认模式，KV 是低写入兼容模式，两种模式必须使用同一业务状态机和对象存储契约。
5. 原始 MIME 必须先保存，解析失败或衍生对象损坏时允许重新解析。

## 当前平台事实

资料于 2026-08-10 核验：

1. D1 的 `batch()` 在一个事务中顺序执行语句，任一语句失败会中止或回滚整个批次。
2. R2 对对象写入、读取、删除和列举提供全局强一致性；写入完成后后续读取应能立即看到，删除完成后后续读取应看不到。
3. KV 的读取是最终一致；其他网络位置可能在 60 秒甚至更久后才看到创建、更新或删除，负查询也会被缓存。
4. KV 单值最大 25 MiB，同一个键每秒最多写一次；因此邮件对象不能依赖频繁覆盖同一键完成状态更新。

## 原型范围

原型使用本地 workerd 的真实 D1、KV 和 R2 绑定，通过同一套业务状态机运行两种存储模式。KV 的跨地区传播延迟由故障适配层模拟，因为本地单进程不能自然复现全球边缘缓存。

每封合成邮件包含：

1. 一份原始 MIME 对象。
2. 一份纯文本正文对象。
3. 一份 HTML 正文对象。
4. 一份附件对象。
5. D1 中的接收操作、邮件、对象登记、邮箱条目、任务和不含正文的审计事件。

所有对象键由存储模式、接收操作编号和对象角色组成，创建后不修改，不在不同物理邮件之间共享。

## 故障注入场景

| 编号 | 注入位置 | 预期结果 |
| --- | --- | --- |
| 故障-01 | D1 已建立接收意图，原始对象尚未写入 | 邮件不可见；重试使用同一操作编号继续写入 |
| 故障-02 | 原始对象已写入，D1 尚未确认 | 对象可以被重试发现并校验；不生成第二份对象 |
| 故障-03 | 第一个衍生对象已写入 | 邮件不可见；重试补齐剩余正文和附件 |
| 故障-04 | 最终可见 D1 批次中途失败 | 整个批次回滚，不出现邮箱条目或半完成的可见状态 |
| 故障-05 | 最终可见批次已提交，但调用方收到失败 | 重复执行仍只有一封邮件、一个邮箱条目和同一组对象 |
| 故障-06 | KV 新对象在模拟的其他地区暂不可见 | 邮件保持隐藏或等待一致性，不提前进入收件箱 |
| 故障-07 | 已可见邮件缺少或损坏一个衍生对象 | 对账发现异常，立即撤下可见条目，从原始 MIME 重建后恢复 |
| 故障-08 | 对象存储出现无 D1 引用的孤立对象 | 对账列出孤立对象，超过保护期后可以幂等清理 |
| 故障-09 | 永久删除在 D1 停止访问后中断 | 用户立即失去访问；后台继续清理对象和引用 |
| 故障-10 | 部分对象已删除或最终 D1 清理批次失败 | 重试跳过已删除对象并最终完成，不恢复邮件可见性 |

## 通过标准

### 正确性

1. 任一接收故障点之后，可见邮箱条目数量为 0，直到全部必要对象通过大小和 SHA-256 校验。
2. 最终可见 D1 批次失败时，邮件状态、邮箱条目和任务完成状态全部回滚。
3. 每个场景恢复后恰好有一封邮件、一个邮箱条目、四个对象登记和四个实际对象。
4. 同一接收或删除操作重复执行至少三次，数量和对象键保持不变。
5. 缺失、损坏和孤立对象能够被对账分类，不被静默忽略。
6. 永久删除开始后服务端立即拒绝访问；完成后 D1 引用和实际对象均为 0，只保留必要的不含正文审计记录。

### KV 特有要求

1. 不覆盖已经完成的不可变对象，不依赖同一键连续写入。
2. 模拟跨地区读不到新对象时不提交可见状态。
3. 对象删除后的旧缓存即使暂时存在，也不能绕过 D1 权限和删除状态访问。
4. 本地模拟结果必须明确说明不能替代真实 Cloudflare 多地区复核。

### 对账

1. D1 登记为存在但存储中缺失的对象列为“缺失”。
2. 实际存在但 D1 没有有效登记的对象列为“孤立”。
3. 大小或 SHA-256 不匹配列为“损坏”。
4. 正常状态下 D1 登记、实际对象、邮件和邮箱条目的数量完全一致。

## 不在本轮验证

1. 20 MB 解析性能和内存，已经由验证-02负责。
2. 完整本地备份文件格式、加密和恢复工具，后续另建验证。
3. 真实 Queue 投递延迟和多地区 KV 传播时间，需要 Cloudflare 远程环境。
4. 发信、通知和转发的供应商幂等行为。
