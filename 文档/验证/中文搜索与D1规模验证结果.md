# 澄笺 | Simlettra 中文搜索与 D1 规模验证结果

## 文档状态

- 状态：本地验证完成，结论有限通过，架构建议已接受
- 验证日期：2026-08-10
- 架构确认日期：2026-08-10

- 原型位置：`验证性原型/搜索与规模/`
- 原始结果：`验证结果-bigram.json`、`验证结果-unigram-bigram.json`

## 一句话结论

在本地 D1 模拟环境中，应用生成中文双字词元、使用内容空 FTS5 索引并加入邮箱范围词元，可以在 100,000 封合成邮件下正确搜索两个及以上连续汉字，并把常用查询保持在可接受范围；为支持单个汉字而同时建立单字词元会把 D1 占用推到约 443.78 MiB，不适合作为首发默认方案。

这是一项“有限通过”：本地结果支持继续采用 D1 FTS5，但真实 Cloudflare D1、更多样的邮件正文和生产网络延迟仍需复核。

## 容量对照

| 方案 | 本地 D1 持久化体积 | 相对双字方案增加 | 判定 |
| --- | ---: | ---: | --- |
| 只建立双字词元 | 266.50 MiB | 基准 | 理想区间内 |
| 同时建立单字和双字词元 | 443.78 MiB | 177.28 MiB | 超过 400 MiB 风险线 |

D1 免费计划单数据库上限为 500 MB。443.78 MiB 已几乎不给用户、权限、组织、任务、审计和迁移过程留下余量，因此不建议为了单个汉字正文搜索采用单字加双字索引。

## 查询结果

以下为双字词元方案的本地第 95 百分位耗时和单次最大读取行数：

| 场景 | 第 95 百分位 | 最大读取行数 | 结果数 |
| --- | ---: | ---: | ---: |
| 收件箱列表 | 3 毫秒 | 158 | 50 |
| 未读筛选 | 15 毫秒 | 2,615 | 50 |
| 有附件筛选 | 6 毫秒 | 152 | 50 |
| 常见中文词搜索，不使用范围词元 | 101 毫秒 | 307,946 | 50 |
| 常见中文词搜索，使用范围词元 | 48 毫秒 | 13,946 | 50 |
| 较少中文词与状态组合搜索，使用范围词元 | 36 毫秒 | 13,769 | 50 |
| 发件人和日期组合 | 3 毫秒 | 203 | 50 |

邮箱范围词元把常见词搜索的最大读取行数从 307,946 降到 13,946，减少约 95.5%。范围词元只缩小候选集合；查询仍然关联邮箱条目和成员状态执行服务端授权检查，不能把词元当作权限证明。

## 工具链观察

1. Wrangler 4.120.0 在本机 Windows 环境执行 `d1 migrations apply --local` 时返回 `bad port`。
2. 同一份迁移文件逐条执行和使用 `d1 execute --file` 执行均成功，证明迁移 SQL 本身有效。
3. 原型运行器暂时使用 `d1 execute --file`。正式工程仍必须使用版本化迁移，并在工程骨架阶段复核 Wrangler 后续版本或建立稳定的迁移执行封装。
4. Worker 内执行 `PRAGMA page_count` 被 D1 以 `SQLITE_AUTH` 拒绝，因此容量由外部验证脚本统计本地 D1 持久化文件，生产代码不得依赖数据库管理命令。

## 建议

1. 首发使用应用生成的相邻中文双字词元，并继续使用 D1 FTS5 `unicode61` 保存这些明确词元。
2. 中文正文全文搜索首发至少输入两个汉字；暂不为单汉字建立全量索引。
3. 搜索分块使用内容空 FTS5 表，只保存索引；正文原文仍位于 KV/R2，索引可以重建。
4. 每个搜索分块写入稳定的个人邮箱或组织邮箱范围编号。查询先用范围词元缩小候选，再执行正式权限检查。
5. 把 300 MiB 作为设计预警线、400 MiB 作为高风险线，但不把本次合成数据结果写成生产容量承诺。
6. 正式发布前使用受控 Cloudflare D1 和更多样的中文、英文及混合正文完成远程复核。

## 架构确认结果

用户于 2026-08-10 接受第二批推荐方案：采用中文双字词元、首发正文搜索至少输入两个汉字、使用邮箱范围词元缩小候选集合，并使用内容空 FTS5 索引。对应 ADR `0007` 已为“已接受”。

该确认不改变验证范围：真实 Cloudflare D1、更多样的正文数据和生产网络延迟仍需在发布前复核。
