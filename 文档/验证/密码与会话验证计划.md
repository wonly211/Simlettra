# 澄笺 | Simlettra 密码与会话验证计划

## 文档状态

- 状态：当前
- 建立日期：2026-08-10
- 最近更新：2026-08-10
- 验证编号：验证-05
- 依据：`需求基线-0001`、已接受的架构决策记录 `0001` 至 `0010`
- 目的：验证 Cloudflare Worker 环境中的密码哈希候选、会话令牌保存方式、撤销语义和登录防滥用边界，为认证架构决策提供证据

## 已确认约束

1. 用户使用主邮箱地址和密码登录，首发不提供其他登录方式和动态验证码二次验证。
2. 密码必须使用成熟的慢速密码哈希保护，绝不保存明文。
3. 用户可以查看并退出自己的登录会话；改密时可以选择是否退出其他设备。
4. 管理员重置普通用户密码，管理员使用部署配置中的 `init_key` 进入恢复流程。
5. 用户被禁用或进入待注销状态后，必须停止正常登录。
6. 会话令牌可以撤销并具有有效期，不得进入 URL、公开日志或不受保护的长期前端存储。
7. 登录需要频率限制和异常告警。

## 官方基线

核验日期均为 2026-08-10。

1. Cloudflare Workers Web Crypto 原生支持 PBKDF2 的 `deriveBits()` 和 `deriveKey()`，可使用 SHA-256、SHA-384 和 SHA-512。
2. Cloudflare Workers 每个隔离实例的内存上限为 128 MB；免费套餐每次请求 CPU 时间上限为 10 毫秒，付费套餐默认 30 秒且可以配置得更高。
3. OWASP 首选 Argon2id，最低推荐参数为 19 MiB 内存、2 次迭代、并行度 1；无法使用 Argon2id 时可采用 scrypt，符合 FIPS 要求时可采用 PBKDF2-HMAC-SHA-256 至少 600,000 次迭代。
4. NIST SP 800-63B-4 要求密码使用带盐且成本可调整的密码派生函数；单因素密码最短建议 15 个字符，最大长度至少允许 64 个字符，不建议字符种类组合规则和无理由定期强制改密，并要求拦截常见或已泄露密码。
5. NIST 要求会话令牌至少具有 64 位随机性；浏览器会话应使用受保护 Cookie，采用 `Secure`、`HttpOnly` 和适当的 `SameSite` 属性；AAL1 会话整体最长建议不超过 30 天。

## 候选方案

| 候选 | 验证参数 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| Workers Web Crypto PBKDF2-HMAC-SHA-256 | 总计 900,000 次，分为 9 轮、每轮 100,000 次 | 平台原生、没有额外运行时依赖、保留总计算强度并适配 Workers 单次调用上限 | 抵抗专用硬件攻击的能力弱于合适参数的 Argon2id；多轮调用可能增加 CPU 和墙钟开销 |
| `argon2-wasm-edge` Argon2id | 19 MiB、2 次迭代、并行度 1 | 使用预编译 Wasm，目标是边缘运行时，安全属性符合 OWASP 首选方向 | 包体、冷启动和内存成本较高；项目维护活跃度与社区规模有限 |
| `@noble/hashes` Argon2id | 19 MiB、2 次迭代、并行度 1 | 纯 TypeScript、持续维护、没有 Wasm 装载边界 | 官方明确说明纯 JavaScript Argon2 较优化实现慢，可能给攻击者带来性能优势 |

scrypt 不进入本轮主候选。OWASP 推荐参数约需 128 MiB，几乎占满 Worker 隔离实例的全部内存，无法给请求、运行时和其他模块留下可靠余量。

## 自动验证范围

### 密码记录

1. 每次创建密码记录都使用新的随机盐，相同密码不得产生相同记录。
2. 记录保存算法、版本和完整参数，验证时按记录参数执行，支持以后逐步升级。
3. 正确密码通过、错误密码失败、损坏或不支持的记录安全失败。
4. 登录不存在的账号时执行等价的虚拟哈希，避免明显的账号存在性时间差。
5. 比较派生结果使用恒定时间比较能力，不直接比较普通字符串。

### 会话令牌

1. 会话令牌使用 Web Crypto 生成 32 个随机字节，即 256 位随机性。
2. 浏览器只持有不透明原始令牌；D1 仅保存令牌的 SHA-256 摘要，不保存可直接登录的原始令牌。
3. 支持列出当前用户的会话、撤销单个会话和撤销其他会话。
4. 改密可选择保留当前会话或撤销所有其他会话。
5. 禁用用户、进入待注销状态和管理员重置密码时立即撤销全部会话。
6. 会话过期、被撤销或所属用户不可登录时均不能继续使用。

### 浏览器边界与登录防滥用

1. 会话 Cookie 至少具有 `Secure`、`HttpOnly`、`SameSite=Lax`、固定 `Path=/` 和明确的 `Max-Age`。
2. 修改状态的请求必须使用同源检查和单独的 CSRF 令牌；Cookie 本身不能作为唯一的跨站请求防护。
3. 登录限速同时约束账号维度和来源维度，成功登录后清理对应失败状态。
4. 登录失败响应不区分账号不存在、密码错误、账号禁用或待注销。
5. 记录异常事件时只保存必要元数据，不保存密码、原始会话令牌或完整请求体。

## 性能判定

1. 每种算法和参数在本地 Wrangler Worker 中执行预热后至少 10 次测量，记录最小值、中位数、第 95 百分位和最大值。
2. 以本地结果比较候选的数量级、稳定性和构建兼容性，不把本机耗时当作 Cloudflare 生产性能承诺。
3. 候选方案必须能在 Worker 128 MB 内存边界下留出明显余量；接近或占满上限视为不适用。
4. 密码验证属于交互式登录路径，目标是用户通常不会感到明显停顿，同时必须避免为了追求速度而低于安全基线。
5. 最终参数在发布前必须使用真实 Cloudflare Worker 远程复核；免费套餐 10 毫秒 CPU 限制是否可用必须以远程结果为准。

## 输出和通过条件

1. 三个候选均给出“可构建并运行”“不兼容”或“风险不可接受”的明确结果。
2. 密码记录、虚拟哈希、会话摘要、撤销、过期、账号状态、Cookie、CSRF 和限速场景均有自动验证证据。
3. 结果文档明确区分本地事实、工程推断、推荐方案和仍需用户确认的产品参数。
4. 建立状态为“提议中”的架构决策记录和第六批批量确认清单。
5. 用户接受前，不建立正式认证模块，不把推荐参数写成已接受架构。
