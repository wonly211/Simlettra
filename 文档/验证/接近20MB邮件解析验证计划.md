## 已知边界

1. Cloudflare Email Routing 当前最大接收邮件大小为 25 MiB，Simlettra 自身要求更小的 20 MB 上限。
2. Cloudflare Worker 当前内存限制为 128 MB。
3. 已接受架构要求收信入口先可靠保存原始邮件，再由 Queue consumer 解析，不在收信入口内完成全部重工作。
4. `ForwardableEmailMessage.raw` 是原始 RFC 822 邮件的 `ReadableStream`，`rawSize` 提供原始字节数。
5. 本地运行成功不能直接证明真实 Cloudflare CPU 计费和峰值内存，需要后续远程复核。

## 候选解析库

本原型使用 `postal-mime 2.7.6`：

- 用途：解析 MIME 正文、地址、邮件关系、内嵌资源和附件。
- 当前维护情况：npm 元数据显示版本 2.7.6 于 2026-08-07 更新。
- 许可证：MIT-0。
- 采用原因：面向浏览器与 Worker 类运行时，无需 Node.js 邮件服务器运行环境；旧系统已经使用过同一库家族，但新系统不会复用旧的字符串拼接读取方式。
- 备选方案：`mailparser` 功能丰富但更依赖 Node.js 运行环境；自行实现 MIME 解析风险过高，不考虑。

## 合成样本

| 样本 | 目的 | 目标大小 |
| --- | --- | ---: |
| 标准功能邮件 | 验证纯文本、HTML、中文地址名、内嵌资源、附件名和邮件关系 | 小于 1 MB |
| 接近 20,000,000 字节的单附件邮件 | 验证一个大型 Base64 附件 | 约 19.9 MB |
| 接近 20 MiB 的多附件邮件 | 验证多个附件、边界和 20 MB 单位差异 | 约 20.9 MB |
| 接近 20,000,000 字节的纯文本邮件 | 验证大正文形成 JavaScript 字符串时的内存压力 | 约 19.9 MB |
| 多部件压力邮件 | 验证大量小附件导致的部件数量开销 | 约 1 至 5 MB |
| 结构异常邮件 | 验证缺少结束边界或异常编码时不会卡死解析进程 | 小于 1 MB |
| 超大邮件头 | 验证超过 256 KiB 时被受控拒绝 | 小于 1 MB |
| 过深 MIME 嵌套 | 验证超过 64 层时被受控拒绝 | 小于 1 MB |
| 过深 RFC822 嵌套 | 验证超过 5 层后停止展开并保留为附件 | 小于 1 MB |

所有样本由脚本生成，不包含真实邮件或用户数据。

## 通过标准

### 正确性

1. 标准功能邮件的主题、地址、正文、邮件关系、附件名、内容编号、附件大小和哈希全部匹配预期。
2. 大附件和多附件的解码后总字节数与生成清单一致。
3. 同一样本重复解析得到一致结果。
4. 异常样本必须在限定时间内返回受控结果，不能让 Worker 进程失去响应。

### 性能

1. 每个大样本在本地 workerd 中至少重复解析 5 次。
2. 接近上限样本的本地第 95 百分位解析时间目标为 5 秒以内。
3. 解析完成后 Worker 健康检查仍成功。
4. 使用独立 Node.js 进程记录近似峰值常驻内存，只作为相对比较，不冒充 Worker 精确内存。

### 架构判定

1. 原始邮件必须以字节或流处理，不允许先转成字符串再交给解析器。
2. 若接近上限样本在本地 workerd 中失败，不得直接进入生产实现。
3. 若本地成功但无法证明 128 MB 内存余量，应保留远程故障注入和套餐验证要求。
4. 20 MB 的单位解释根据验证结果单独确认；最终已接受 20,000,000 个原始邮件字节。

## 完成情况

本地验证于 2026-08-10 完成，结论为“有限通过”：正确性、重复一致性、本地耗时和进程健康通过；真实 Cloudflare Worker 的内存、CPU 计费和并发仍需远程复核。第三批架构已经全部确认，对应 ADR `0008` 已接受。
