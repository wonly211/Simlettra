## 验证原则

1. 验证性原型统一放在 `验证性原型/`，不得被生产代码直接依赖。
2. 原型只使用合成数据、公开样本或经过脱敏的测试数据，不使用真实用户邮件。
3. 每项验证必须记录环境、数据规模、操作步骤、结果、限制和结论。
4. 本机结果只用于发现相对差异和明显风险；涉及 Cloudflare 套餐与真实运行时间的结论必须再在 Cloudflare 环境复核。
5. 原型失败不能被隐藏。若证据否定已接受架构，必须新建架构决策记录取代旧决定。
6. 原型目录可重复生成本地数据库和临时结果，正式结论写入 `文档/验证/`。

## 验证-01 判定标准

### 数据规模

1. 50 名用户。
2. 100,000 封物理邮件。
3. 至少 100,000 个个人邮箱条目，并加入一部分额外共享条目。
4. 每名用户具有独立的已读、星标、归档和垃圾箱状态。
5. 正文搜索按分块模型建立可重建索引。

### 正确性

1. 默认 `unicode61` 分词的中文局限能够被明确复现。
2. 候选方案能够正确匹配常用的两个及以上连续汉字关键词。
3. 搜索结果必须先经过邮箱所有权过滤，不能只依赖前端隐藏。
4. 普通列表、未读筛选、有附件筛选和正文搜索返回稳定结果。

### 性能与容量

1. 本地数据库内部查询的第 95 百分位耗时目标为 500 毫秒以内，为网络、Worker 和页面渲染预留时间。
2. 目标规模下 D1 数据库估算体积不超过 300 MB 为理想，300 MB 至 400 MB 为需要优化，超过 400 MB 视为不能直接采用。
3. 查询读取行数必须与单个用户的可见数据或搜索命中量相关，不能在普通邮箱列表中扫描全部邮件。
4. 结果必须同时说明：本地 Miniflare/D1 模拟环境不能替代真实 Cloudflare D1 的最终性能复核。

## 验证-05 判定结果

1. 原单次 Workers Web Crypto PBKDF2 600,000、900,000 和 1,200,000 次均能在本地 Worker 运行；真实 Workers 后续确认单次超过 100,000 次会失败，因此生产实现改为 9 轮 × 100,000 次的链式派生，总计算量保持 900,000 次。
2. `argon2-wasm-edge` 与 `@noble/hashes` 的 Argon2id 均能运行并产生相同结果，但分别存在维护停滞和具体实现未纳入既有独立审计的风险。
3. 九组自动验证全部通过，覆盖密码记录、虚拟哈希、会话摘要、撤销、Cookie、CSRF、账号状态、过期和登录限速。
4. 方案记录于[密码与会话验证结果](密码与会话验证结果.md)，第六批架构已经确认；单次派生的结论由 ADR `0053` 取代 ADR `0011`。
5. 真实 Cloudflare Worker 的 CPU、冷启动、并发登录和限速原子性仍需远程复核。

## 验证-06 判定结果

1. Drizzle 生成迁移、手写 FTS5 SQL 和 Wrangler 迁移账本能够共存；Drizzle 与原生 D1 的代表性列表查询返回一致结果。
2. Prisma D1 adapter 可以运行，但仍为 Preview；代表性 Worker gzip 包体约为 Drizzle 的 32.25 倍。
3. 11 组自动验证全部通过，覆盖权限范围、键集分页、参数化 FTS5、原子批处理、参数分块、失败迁移和逻辑恢复。
4. D1 物理导出明确拒绝包含 FTS5 虚拟表的数据库；权威普通表逻辑备份恢复后能够重建搜索索引。
5. 详细证据见[D1 数据库工具与迁移验证结果](D1数据库工具与迁移验证结果.md)；第七批架构已经确认，ADR `0012`、`0013` 均为“已接受”。
6. 真实 D1 Time Travel、远程迁移、Sessions 和 100,000 封邮件流式备份仍需复核。
