# 中文搜索与 D1 规模验证原型

## 目的

本原型验证两件事：

1. D1 FTS5 默认分词、`trigram` 分词和由应用生成中文双字词元三种方式的中文搜索差异。
2. 50 名用户、100,000 封邮件及正文分块索引下，常用列表和组合搜索的查询耗时、读取行数与数据库体积。

该目录是独立实验，不是澄笺生产工程骨架。

## 数据模型

原型刻意保留未来模型中与性能有关的部分：

- `messages`：物理邮件。
- `mailbox_entries`：邮件进入哪个个人邮箱。
- `mailbox_states`：成员自己的已读、星标、归档和垃圾箱状态。
- `search_chunks`：正文分块与邮件的关系。
- `message_search`：可重建的 FTS5 内容空表索引。

正文原文在真实系统中应位于 KV/R2。本原型只把合成正文转换为搜索词元，不把原文放入 D1。

## 中文候选方案

候选方案先将连续中文转换为相邻双字词元。例如：

```text
预算调整 -> 预算 算调 调整
```

查询时使用同样转换并组成短语查询，因此可以搜索常见的两个及以上连续汉字。单个汉字是否需要支持仍需根据索引代价和用户体验另行决定。

规模查询还会比较两种权限过滤顺序：

1. 先搜索整套系统，再关联用户邮箱。
2. 把稳定的个人邮箱或组织邮箱编号作为 FTS 范围词元，先缩小候选邮件，再执行服务端权限复核。

范围词元只用于减少扫描，绝不代替服务端所有权和组织成员资格检查。组织成员变化时使用稳定组织编号，不需要为每名成员重建正文索引。

## 执行

此原型使用独立依赖。安装后执行：

```powershell
pnpm install
pnpm run check
pnpm run validate
pnpm run validate:compare
```

`validate` 验证只含中文双字词元的候选方案。`validate:compare` 还会建立第二个独立数据库，对比“单字＋双字词元”方案。命令会删除对应的 `.data-*`，重新建立本地 D1，生成合成数据，执行多轮查询并写出对应的 `验证结果-*.json`；不会访问仓库外的数据。

当前本机的 Wrangler 4.120.0 在 Windows 上使用 `d1 migrations apply --local` 时返回 `bad port`，但同一份带编号迁移文件可以通过 `d1 execute --file` 完整执行。原型运行器暂时使用后者；此现象会记录在验证结果中，不能据此取消正式系统的版本化迁移要求。

## 结果边界

- Miniflare 的本地 D1 适合验证 SQL、索引结构、结果正确性和数据库体积。
- Worker 运行时无权执行 `PRAGMA page_count` 等管理命令，因此容量由外部运行器统计本原型 `.data` 中的持久化文件。
- 本机耗时不能直接等同于 Cloudflare 生产环境延迟。
- 合成正文无法完全代表真实邮件语言分布，容量结论必须保留余量。
- 本原型通过后，仍需使用受控 Cloudflare 测试资源进行小规模远程复核。
